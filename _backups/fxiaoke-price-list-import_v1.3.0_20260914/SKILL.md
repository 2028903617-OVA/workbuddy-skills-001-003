# 纷享销客价目表明细导入文件生成器

把各品牌的新增产品价目表源表，转成符合纷享销客「价目表明细导入模板」的 xlsx。自动完成产品主数据匹配、已有明细查重，按「新建 / 更新 / 人工复核」三路分拆输出，用户拿文件去纷享销客「数据导入」即可。

## 何时使用

用户给出 1 份品牌价目表源表 xlsx，并说「加进价目表」「价目表明细导入」「处理价目表」「把这张表转成导入模板」等类似表达时使用。源表通常是某品牌的新增产品申请表（含产品型号与 4 个价格）。

## 运行前检查

1. 用 venv Python 运行 `scripts/check_environment.py`，得到 ready / partial / needs_setup。
2. **改动脚本后先跑测试**：`python scripts/test_build_import.py`（16 个用例，覆盖品牌推断、组织→价目表、西门子交叉填法、四舍五入、等级、(HE) 防错配、端到端）。全绿才可交付。
2. ready 或 partial：继续主流程；partial 时向用户说明受影响功能（见「降级与停止」）。
3. needs_setup：只展示缺失项和 `references/setup-guide.md` 对应步骤，等用户补齐后重检，不猜测继续。

## 主流程

1. **定位源表数据**：按 `references/field-mapping.md` 的规则定位数据 sheet 与表头行（申请表格式表头在 R3、数据 R4 起；导入模板格式表头 R1、数据 R2 起）。
2. **识别组织（org）**：优先用户明示（`--org`）；其次申请表 R2「申请部门：X」；识别失败必须问用户，不猜。
   ⚠️ **组织 ≠ 品牌**：组织决定「价目表」列；品牌是产品实际品牌，逐行从型号推断。二者互相独立，见下方「组织与品牌」章节。
3. **解析每行**：按 `references/field-mapping.md` 的列名变体表提取型号、建议售价、限价、结算价、成本价、备注；乾鑫源表另读产品大类、产品品项、品牌列。
4. **匹配产品**：在产品主数据快照按「产品名称 / 物料名称 / 型号规格 / 物料编号」四列匹配（精确 → 型号包含 → 子串，按序短路）。命中取系统「产品名称」；未命中标记「金蝶未同步」。
5. **查重**：用「系统产品名称 + 价目表名」在价目表明细快照中查已有明细。已存在 → 进更新文件（取该明细的唯一性ID 与价目表唯一性ID）；不存在 → 进新建文件。
6. **填分类**：按 `references/field-mapping.md` 品牌特例（西门子交叉填法、大金固定空调、乾鑫读源表、欣暖家留空、其他走通用关键词表）。关键词表匹配不上 → 两列留空并记入核对清单，交由 AI 按语义就近复核后填入或保持留空。
7. **运行脚本生成 3 份文件**：`scripts/build_import.py`，输出到用户指定目录（默认工作区）。
   - `{品牌}_新建价目表明细_{YYYYMMDD}.xlsx` — 12 列
   - `{品牌}_更新价目表明细_{YYYYMMDD}.xlsx` — 8 列（仅重复行；无重复行不生成）
   - `{品牌}_产品核对清单_{YYYYMMDD}.xlsx` — 待同步 / 重复 / 分类未匹配明细 + 快照日期与局限说明（无警示项不生成）
8. **交付**：展示生成的文件，并向用户报告：新建 X 行 / 更新 Y 行 / 待同步 Z 行 / 所用快照日期；提醒「金蝶未同步」的产品要先在金蝶建好并同步到纷享销客后再导入。

## 组织与品牌（2026-09-14 用户确认，务必分清）

这是最容易搞混的一组概念，两个维度互相独立：

| 概念 | 决定哪一列 | 怎么取值 | 例子 |
|---|---|---|---|
| **组织 org** | 「价目表（必填）」 | 用户明示 / 源表「申请部门」 | 欣暖家 → 美的价目表20250901；乾鑫 → 乾鑫价目表20260701；西门子 → 西门子价目表20260701 |
| **品牌** | 「品牌」列 | 产品的**实际**品牌，逐行从型号名推断（源表品牌列优先） | 产品 `TCL平板电视98C10L-A` → 品牌 `TCL`；产品 `美的3匹变频柜机…` → 品牌 `美的` |

**同一张价目表内可以有多个品牌**（这是常态，不是异常）：
- 乾鑫价目表20260701 里可以同时有「大金」「美的」「格力」产品 → 价目表列都填「乾鑫价目表20260701」，品牌列分别填各产品自己的品牌。
- 欣暖家组织用「美的价目表20250901」，但里面照样放 TCL 彩电、COLMO 冰箱、东芝空调 → 品牌列填 TCL / COLMO / 东芝。

命令行：`--org 欣暖家`（推荐）或 `--brand 欣暖家`（等价旧名，保留兼容）。

## 产品匹配：本地快照 + 连接器兜底（2026-09-14 实测）

`match_product()` 用本地快照做「精确 → 型号包含 → 子串」三级匹配，**已知两类失败**，必须按此流程兜底：

| 失败类型 | 真实例子 | 后果 |
|---|---|---|
| **错配**（子串/型号包含截短） | 源表 `美的电热水器F60-33Q7Pro(HE)` 命中快照里的 `F60-33Q7Pro`（**不带 (HE)，是另一个产品**，物料号 20.04.01.01.099 vs .079） | 导入到错误产品，价格挂错 |
| **漏配**（三种策略全落空） | 源表 `美的净饮机JR2288T-RO` vs 系统名 `美的台式净饮机JR2288T-RO冰川银`（规格 `JR2288T-RO冰川银`） | 被判「金蝶未同步」，白白漏掉 |
| **同型号不同产品** | `GMV-NHDR63PS/Fb1` 与 `…/Fb` 是两种机型 | 挂错型号 |

### 兜底流程（今天验证有效）

当出现「金蝶未同步」警示，或命中结果可疑（系统名与源表型号差异较大）时：

1. 用纷享销客连接器 `mcp__sharecrm__data_record_query-id-by-name` 对**源表型号**做语义搜索（`apiNames: ["ProductObj"]`），它会返回带相似度的候选列表。
2. 取相似度最高且**型号主体一致**的那条，必要时用 `data_record_get-by-id` 拉完整记录，确认 `name` / `mnemonic_code`（物料编号）/ `field_733tW__c`（型号规格）。
3. 以连接器返回的 **`name`（系统产品名称）** 为准填「产品（必填）」列——**不要填源表原名**。
4. 若连接器也确认产品不存在 → 才算真正的「金蝶未同步」，进核对清单。

> 注意：`PriceBookProductObj`（价目表明细）**禁止 Agent 写入**（返回 `DISABLED_OBJECT`），连接器只能读不能写，最终仍要靠数据导入或 CRM 页面录入。

### 当天新建的产品，快照里一定没有

产品常在建价目表的**同一天**由财务新建（如 2026-09-14 上午建、下午就要加明细），9/12 的快照必然查不到。
✅ 做法：用连接器实时确认后，把产品**补进快照副本**再跑脚本（不要改原快照）；或按上面流程直接用系统产品名生成。

## 固定规则（不可变）

- 价目表折扣（%）恒填 100；业务类型（必填）恒填「预设业务类型」。
- 价目表（必填）从 `references/brand-pricebooks.md` 的启用清单按品牌取；品牌不在清单 → 该列留空 + 记入核对清单。
- 「金蝶未同步」的产品不得进入新建/更新文件（导入必失败），只进核对清单。
- 启欣：4 个价格列与产品品项留空，其余照填。
- 产品等级：仅源表备注列出现 A–F 单字母时填「X类」，否则留空。
- 产品（必填）填系统产品名称（快照命中的值），不填源表原名。
- 不修改源表；不向纷享销客系统写入数据；不代用户执行导入；不擅自增删行、不改型号与价格数字、不改品牌名。

## 质量自查清单

- [ ] 新建文件 12 列、更新文件 8 列，列头与模板逐字一致
- [ ] 每个数据行的产品名称来自快照命中值，或该行已进核对清单（不混入）
- [ ] 折扣 100、业务类型「预设业务类型」全覆盖无遗漏
- [ ] 启欣行价格与品项为空
- [ ] 金额列为纯数字，无文本、无千分位逗号
- [ ] 核对清单含快照日期与「快照之后的新增未覆盖」说明

## 降级与停止

| 状况 | 处理 |
|---|---|
| openpyxl 缺失 | needs_setup，按 setup-guide 安装后重检 |
| 产品快照与明细快照均找不到 | partial：不做匹配与查重，全部行进新建文件且产品列填源表原名，文件名追加「未校验」，核对清单显著标注「未经产品匹配与查重，导入前需人工核对」 |
| 仅明细快照缺失 | partial：不做查重，全部走新建文件并在核对清单标注 |
| 源表品牌无法识别 | 停止，问用户 |
| 源表缺必填价格列 | 停止，列出缺失行问用户 |
