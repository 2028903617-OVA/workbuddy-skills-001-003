# 06 举一反三：从坑到方法论

> 这一章不是罗列坑，而是把坑**抽象成可迁移的判断规则**。遇到新问题时先匹配这里的模式。

## M1 内容含 shell 元字符 → 不走 shell

**原始坑**：反引号被命令替换吞掉，文件被截断（A02）。
**抽象**：任何"要写进文件的内容含 `` ` ``、`$`、`!`、`\` 等元字符"的场景，都不走 shell 内联通道。
**迁移**：写记忆、写配置、写含代码片段的文档 → 一律 Write/Edit 或 Python 脚本落盘。

## M2 生成类产出必须回读，且回读的是"新产出"不是"我记得写了什么"

**原始坑**：批量改 4 个只改了 3 个却报全改好（B12）；凭记忆交付（C02）；数组公式写盘不报错但内容是错的（B04）。
**抽象**：**写成功 ≠ 内容对**。凡"程序生成的产物"，都要用独立于生成过程的手段回读。
**迁移**：docx→文本 dump；xlsx→脚本读回；代码→Read；SQL 写入→再查一次。
⚠️ 注意"写盘不报错、读回也正常，但实际错了"这一类（如 B04），要靠**抽查底层 XML/原始结构**才能发现。

## M3 验证不能只和"上一版"比，要和"规则"比

**原始坑**：报"与旧版数值一致"但用户打开是错的（B11）。
**抽象**：**增量对比只能发现"变了"，不能发现"错了"**。上一版本身错，增量对比会错得一模一样。
**迁移**：三查 = 脱离旧版重算 + 逐个看引用取值 + 与权威模板 diff。

## M4 用户的"手调版"才是权威，不是你的"上一版"

**原始坑**：硬编码美化被否（B09）。
**抽象**：不要把"我上次做的"当成用户意志。用户改过的东西带有他没说出口的判断。
**迁移**：样式、排版、口径、命名——凡用户手动调过的，以用户版为模板继承，删掉自己的硬编码。
延伸为**F9 不做推测性决策**：样式/口径不明就问，不猜。

## M5 自检要看上下文，不能看词频

**原始坑**：脱敏扫描命中 5 处，全在"本件不含…"的免责句里（C05）。
**抽象**：**关键词命中的语义取决于上下文**，命中率高不代表有问题，命中率低不代表安全。
**迁移**：任何自动化检查（脱敏、术语残留、格式校验）都要**输出命中行原文**，由人或语义判断，不能只看计数。
同理：公式比对用 `str(cell)` 全是误报（B14）——**选对比较对象**比提高检查频率重要。

## M6 版本必须显式声明"哪一版是最终版"

**原始坑**：v1/v2/v3 同名系列，用户可能发错（C01）。
**抽象**：迭代过程中**必然**产生多版本，混乱是默认状态，需要显式消歧。
**迁移**：另存新名 + 每次交付明说"vN 取代之前所有版本" + 提醒别发混。

## M7 口径变更要"收回"，不能"静默改"

**原始坑**：R36 从"建议剔除 3 人天"改到"只做了一层"（C07）。
**抽象**：用户可能拿着**旧结论**去沟通。静默修正 = 让用户用错误依据做事。
**迁移**：文档里明写"上一版 X 的说法已作废，新结论是 Y"；重大口径推翻保留「原口径（已废止于 日期）→ 新口径」轨迹。

## M8 跨机/跨环境先确认"我在哪"

**原始坑**：猜机器身份，全盘做反（E09）。
**抽象**：**环境相关的假设必须用可验证的硬证据确认**，不能用"上次是…"推断。
**迁移**：机器身份用硬件锚点；连接可用性先探活再判断（D01 两条通道分开记）；对象是否存在先 describe 再猜。

## M9 分通道：不同性质的东西走不同通道

**原始坑**：记忆枢纽传整目录撑爆（E08）。
**抽象**：通道有适用类型，混用会崩。
**迁移**：文档型走枢纽、整目录镜像走 Git；只读操作走 A 通道、写入走 B 通道；别因为一条通道挂了就判定"整体不可用"（D01）。

## M10 备份要"改之前"且"完整"，否则不是备份

**原始坑**：备份是中途快照，回滚不了（E12）。
**抽象**：备份的价值在于**可回滚到改动前**，任何"改动进行中的快照"都不满足定义。
**迁移**：先备份→再改；install 后源目录会被清（E10）→ 提前反向拷贝；自动落档的快照是混合状态（不可信）→ 自建干净备份。
