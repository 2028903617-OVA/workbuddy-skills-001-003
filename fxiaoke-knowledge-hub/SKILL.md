# 欣锋集团 · 纷享销客知识库总入口

本知识库是纷享销客（CRM）相关**知识 + 技能路由**的总入口，覆盖：业务口径、对象字段、录单流程、避坑清单、技能索引。内容提炼自用户已确认的真实业务（2026.1–2026.9），自包含、可整体打包分享。

## 回答规矩（必须遵守）

1. **结论先行**：先给结论/口径，再给依据；表格分列「结论 / 证据 / 待定」。
2. **三态标注**：每条关键口径标注来源状态——`[已验证]`（实测或用户确认）、`[推断]`（依惯例推定）、`[未验证]`（存疑待确认）。禁止把推断当已验证输出。
3. **不编造**：字段 API 名、选项 code、金额字段等不确定时，明确说「需现场 data_describe_get 确认」，不要编。
4. **口径先问**：凡统计线索类指标，先问用户「按负责人(owner)还是按创建人统计」再拉数；凡涉及金额字段，以用户明确指定为准，勿硬编码。
5. **术语习惯**：后台自动化能力叫「审批流 / 工作流」，**不叫「触发器」**。
6. **查询前先确认范围**：fs-server 明细查询单页上限 20 条、超限静默截断——先说明过滤条件、预期数据量、翻页策略，等用户确认再查。
7. **严谨交付**：交付前自检术语统一（如只用「第一成交」不用「首次成交」）、各指标口径独立核对不互相套用。

## 维护约定

- **变更须经用户确认（最高优先级）**：当前正在做流程优化，后续流程调整会连带本知识库（及各关联 skill、对应记忆知识）发生变化。**任何新增/修改/删除口径、字段、流程规则、技能路由、记忆知识，都必须先向用户说明要改什么、为什么改、影响范围，等用户确认后再执行**——绝不擅自改动，也不静默更新。
- 新口径确认后：更新对应分册的对应品牌节，标注确认日期与状态。
- 字段 API / 选项 code 有实测变化的：同步更新 `object-fields.md`，旧值不删、注明「已废弃 → 新值」。
- 新技能沉淀后：在 `skill-routing.md` 追加一行。
- 已确认的旧口径被推翻时：不直接删除，改为「原口径（已废止于 日期）→ 新口径」，保留变更轨迹。
