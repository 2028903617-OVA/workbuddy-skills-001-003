# 纷享销客物料与价目表工具

**一个技能，三个能力**。先按下面的表判断走哪条，再打开对应文档；三份文档只读需要的那份。

| # | 能力 | 用户怎么说 | 打开 | 脚本 |
|---|---|---|---|---|
| **1** | 价目表明细导入 | 「加进价目表」「价目表明细导入」「处理价目表」「把这张表转成导入模板」 | `references/ability-1-pricebook-import.md` | `scripts/build_import.py` |
| **2** | 我方物料匹配外部物料 | 「这些对应我们哪个物料」「我们有没有」「销客产品编码是多少」「跟我们的物料对一下」 | `references/ability-2-material-match.md` | `scripts/match_material.py` |
| **3** | 外部物料 → 我方物料名 | 「帮我生成我们内部的物料名称」「这批是新机型，系统里没有」「按我们的格式命名」 | `references/ability-3-material-name.md` | `scripts/build_new_material.py` |

**组合用法**（实际跑批常见）：外部清单 → 先走**能力 2** 匹配已有物料 → 匹配不上的再走**能力 3** 生成新物料名 → 最后走**能力 1** 生成价目表导入文件。

共用参考：`references/field-mapping.md`（表头语义识别、列名变体、12/8 列填法、组织特例、分类关键词表）、`references/brand-pricebooks.md`（组织→价目表、品牌词表、选项表）、`references/setup-guide.md`（环境）。

## 共用硬规则（三个能力都适用）

- **组织 ≠ 品牌，永远不混**：组织只决定「价目表（必填）」列（映射见 `brand-pricebooks.md`）；「品牌」列填**产品的实际品牌**，逐行从型号/产品名推断，**永远不填组织名**。推断不出来 → 留空 + 记核对清单，不拿组织名顶。
- **按表头语义定位，不写死表名与列位**：源表每次都可能不同（表头在 R1 还是 R2、列名怎么叫、加列后整体右移都遇过）。一律扫前 8 行按语义认表头，见 `field-mapping.md`。
- **我方物料名的可信度排序**：物料名称类列（99–100% 完全一致）＞ 规格型号 ＞ 型号标题（与我方物料名 0 个完全一致，只能模糊）。能用物料名称就绝不用型号标题。
- **金额列输出纯数字**：去文本、去空格、去千分位逗号；4 个价字段四舍五入取整到 0 位小数（half-up），如 423.52 → 424。
- **不修改源表、不覆盖用户原件**：要写回的一律输出**副本**。
- **不向纷享销客写入数据、不代用户执行导入**；价目表明细对象禁止 Agent 写入（返回 `DISABLED_OBJECT`），连接器只能读。
- **不擅自增删行、不改型号与价格数字、不改品牌名**。

## 运行前检查

1. 用 venv Python 运行 `scripts/check_environment.py`，得到 ready / partial / needs_setup。
2. ready 或 partial：继续；partial 时向用户说明受影响功能（见「降级与停止」）。
3. needs_setup：只展示缺失项和 `references/setup-guide.md` 对应步骤，等用户补齐后重检，不猜测继续。
4. **改动任何脚本后必须跑测试**：`test_build_import.py`、`test_match_material.py`、`test_build_new_material.py` 全绿才可交付。

## 数据源优先级：本地快照 → 连接器兜底（三个能力共用）

**先用本地快照，快照没命中的才走连接器**（用户 2026-09-28 明确）。
本地快照是主数据源——快、全、离线、结果可复现；连接器只用来给「快照未命中」的行做二次复核，
避免把「快照滞后 1–3 天」误判成「金蝶未同步」。**不要反过来一上来就查连接器**。

### 第 1 步：本地快照匹配（主路径，必做）

- 用 `check_environment.py` 确认两类快照存在且非过期。
- 按 物料名称 → 规格型号 → 型号标题 的顺序匹配（可信度递减，见共用硬规则）。
- **快照命中的行直接出结果，不再查连接器**。

### 第 2 步：只对快照未命中的行走连接器兜底

本地快照滞后 1–3 天是常态（金蝶当天新建的物料快照查不到）。
**所以判定「我方没有这个物料」之前必须先过连接器**，否则会误报。

0. 先调 `get-current-user` 确认连接器可用；不可用就在核对清单标注「未经连接器复核」。
   ⚠️ **不要凭记忆判定连接器状态**——失效的是 **fs-server 那条渠道**
   （代理网关 / SSE 直连 / API 写三路都返回 HTTP 400），而另一条纷享销客连接器是**可用**的
   （2026-09-28 实测 `get-current-user` 返回 `ea / tenantId / employeeId`）。
   把「某条渠道不可用」记成「连接器不可用」，会让后续所有任务白白放弃这条兜底路径。
1. 用连接器对目标型号做语义搜索（`apiNames: ["ProductObj"]`），返回带相似度的候选列表。
2. **候选筛选：相似度最高（≥0.98）且型号主体一致优先；型号主体相同、只有前后缀差异的多个候选，取 id 最新的**（源表基本都是新增产品，最新添加的那条才对）。
3. 取选定候选，必要时拉完整记录，确认系统产品名称、物料编号、型号规格。
4. 以连接器返回的**系统产品名称**为准——不要填源表原名（源表常少品类词或大小写不同）。
5. 连接器也确认不存在 → 才算真正的「金蝶未同步」。

## 降级与停止

| 状况 | 处理 |
|---|---|
| openpyxl 缺失 | needs_setup，按 setup-guide 安装后重检 |
| 产品快照与明细快照均找不到 | partial：不做匹配与查重，全部行进新建文件且产品列填源表原名，文件名追加「未校验」，核对清单显著标注「未经产品匹配与查重，导入前需人工核对」 |
| 仅明细快照缺失 | partial：不做查重，全部走新建文件并在核对清单标注 |
| 金蝶物料表缺失（有产品快照） | 能力 2 降级：只按产品快照匹配，销客产品编码取自快照「唯一性ID」、物料编码取自快照「物料编号」，结果「降级说明」写明并要求人工复核 |
| 金蝶物料表与产品快照都没有 | 停止，说明「无底表不做无依据匹配」，让用户先导出底表 |
| 源表组织无法识别 | 停止，问用户 |
| 源表缺必填价格列 | 停止，列出缺失行问用户 |
| 表头语义识别失败（前 8 行找不到型号类或价格类列） | 停止，打印前 8 行原文问用户，不猜列 |
