# 能力 1：价目表明细导入文件生成

把某组织的新增产品价目表源表，转成符合纷享销客「价目表明细导入模板」的 xlsx。自动完成产品匹配、已有明细查重，按「新建 / 更新 / 人工复核」三路分拆输出，用户拿文件去纷享销客「数据导入」即可。

## 何时用

用户给出 1 份价目表源表 xlsx，并说「加进价目表」「价目表明细导入」「处理价目表」「把这张表转成导入模板」等。源表通常是某组织的新增产品申请表（含产品型号与 4 个价格）。

源表里若出现**我方系统里不存在的新型号**，先走能力 3 生成我方物料名，再回到本流程。若源表用的是**对方的物料名/型号标题**，先走能力 2 匹配。

## 主流程

1. **定位源表数据**：按 `field-mapping.md` 的「表头与数据行识别」定位表头行与数据起始行；多 sheet 累积表只取最新日期那个 sheet。
2. **识别组织（org）**：优先用户明示（`--org`）；其次源表里「申请部门：X」类字段；识别失败**必须问用户，不猜**。
   ⚠️ **组织 ≠ 品牌**：组织只决定「价目表」列；品牌是产品实际品牌，逐行从型号推断。二者互相独立，见 `brand-pricebooks.md`。
3. **解析每行**：按 `field-mapping.md` 的语义列名表提取型号、建议售价、限价、结算价、成本价、备注；源表若自带产品大类/产品品项/品牌列则一并读。
4. **匹配产品**：在产品主数据快照按「产品名称 / 物料名称 / 型号规格 / 物料编号」四列匹配（精确 → 型号包含 → 子串，按序短路；模糊路径内置**品牌一致性**与**型号码边界**两道闸）。命中取系统「产品名称」；未命中标记「金蝶未同步」。
5. **查重**：用「系统产品名称 + 价目表名」在价目表明细快照中查已有明细。已存在 → 进更新文件（取该明细的唯一性ID 与价目表唯一性ID）；不存在 → 进新建文件。
6. **填分类**：按 `field-mapping.md` 的组织特例（西门子交叉填法、大金固定空调、乾鑫读源表、启欣与部分组织留空、其他走通用关键词表）。关键词表匹配不上 → 两列留空并记入核对清单，由 AI 按语义就近复核后填入或保持留空。
7. **运行脚本生成 3 份文件**：`scripts/build_import.py`，输出到用户指定目录（默认工作区）。
   - `{组织}_新建价目表明细_{YYYYMMDD}.xlsx` — 12 列
   - `{组织}_更新价目表明细_{YYYYMMDD}.xlsx` — 8 列（仅重复行；无重复行不生成）
   - `{组织}_产品核对清单_{YYYYMMDD}.xlsx` — 待同步 / 重复 / 分类未匹配明细 + 快照日期与局限说明（无警示项不生成）
8. **交付**：展示生成的文件并报告：新建 X 行 / 更新 Y 行 / 待同步 Z 行 / 所用快照日期；提醒「金蝶未同步」的产品要先在金蝶建好并同步到纷享销客后再导入。

## 固定规则（不可变）

- 价目表折扣（%）恒填 100；业务类型（必填）恒填「预设业务类型」。
- 价目表（必填）从 `brand-pricebooks.md` 的启用清单按**组织**取；组织不在清单 → 该列留空 + 记入核对清单。
- 「金蝶未同步」的产品不得进入新建/更新文件（导入必失败），只进核对清单。
- 启欣：4 个价格列与产品品项留空，其余照填。
- 产品等级：仅源表备注列出现 A–F 单字母时填「X类」，否则留空。
- 产品（必填）填系统产品名称（快照命中的值），**不填源表原名**。
- 不修改源表；不向纷享销客系统写入数据；不代用户执行导入；不擅自增删行、不改型号与价格数字、不改品牌名。

## 产品匹配兜底：本地快照 → 连接器

> **顺序铁律（用户 2026-09-28 明确）：先用本地快照，快照没有的再走连接器。**
> 快照是主数据源，连接器只给「快照未命中」的行做二次复核，不要一上来就查连接器。

`match_product()` 用本地快照做三级匹配，**已知两类失败**：

| 失败类型 | 真实例子 | 后果 |
|---|---|---|
| **错配**（子串/型号包含截短） | 源表 `美的电热水器F60-33Q7Pro(HE)` 命中快照里的 `F60-33Q7Pro`（**不带 (HE)，是另一个产品**，物料号 .099 vs .079） | 导入到错误产品，价格挂错 |
| **漏配**（三种策略全落空） | 源表 `美的净饮机JR2288T-RO` vs 系统名 `美的台式净饮机JR2288T-RO冰川银`（规格 `JR2288T-RO冰川银`） | 被判「金蝶未同步」，白白漏掉 |
| **同型号不同产品** | `GMV-NHDR63PS/Fb1` 与 `…/Fb` 是两种机型 | 挂错型号 |

当出现「金蝶未同步」警示或命中结果可疑时：

0. **只对快照没命中的行走这一步**——先调 `get-current-user` 确认连接器可用，再判定「金蝶未同步」。
   产品快照滞后 1–3 天是常态（金蝶当天新建的物料快照查不到），直接判未同步会误报。实战：整批新物料在快照里全部查无。
   ⚠️ 别把「fs-server 渠道失效（HTTP 400）」记成「连接器不可用」——另一条纷享销客连接器是通的，先 ping 一次再下结论。
1. 用连接器对**源表型号**做语义搜索（`apiNames: ["ProductObj"]`），返回带相似度的候选列表。
2. **候选筛选：相似度最高（≥0.98）且型号主体一致优先；型号主体相同、只有前后缀差异的多个候选，取 id 最新的**（源表基本都是新增产品，最新添加的那条才对）。
3. 取选定候选，必要时拉完整记录，确认 `name` / `mnemonic_code`（物料编号）/ 型号规格字段。
4. 以连接器返回的**系统产品名称**为准填「产品（必填）」列——**不要填源表原名**（源表常少品类词或大小写不同，如 `美的热水器JSLQ27-S2-AK8 PRO` → `美的燃气热水器JSLQ27-S2-AK8 Pro`）。
5. 连接器也确认不存在 → 才算真正的「金蝶未同步」，进核对清单。

> 注意：价目表明细对象**禁止 Agent 写入**，连接器只能读不能写，最终仍要靠数据导入或 CRM 页面录入。

### 当天新建的产品，快照里一定没有

产品常在建价目表的**同一天**由财务新建，早几天的快照必然查不到。
做法：用连接器实时确认后，把产品**补进快照副本**再跑脚本（不要改原快照）；或按上面流程直接用系统产品名生成。

## 质量自查清单

- [ ] 新建文件 12 列、更新文件 8 列，列头与模板逐字一致
- [ ] 每个数据行的产品名称来自快照命中值，或该行已进核对清单（不混入）
- [ ] 折扣 100、业务类型「预设业务类型」全覆盖无遗漏
- [ ] 启欣行价格与品项为空
- [ ] 金额列为纯数字，无文本、无千分位逗号
- [ ] 核对清单含快照日期与「快照之后的新增未覆盖」说明
