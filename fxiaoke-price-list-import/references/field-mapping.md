# 字段映射与组织特例

## 表头与数据行识别（按语义，不按固定行号）

源表格式不固定，**同一个组织不同批次都可能变**。一律用语义识别，不写死格式名和行号：

1. **扫前 8 行**，对每一行统计「命中下方语义关键词的列数」。
2. 命中列数最多、且至少命中 1 个**必需语义**（型号类或价格类）的那一行 = **表头行**。
3. **数据起始行 = 表头行 + 1**，向下取到连续空行为止（表尾的「合计 / 备注」行按需跳过）。

| 语义 | 表头关键词（命中其一即认） | 必需 |
|---|---|---|
| 型号 / 物料名 | 产品官方名称及型号 / 产品（必填） / 产品 / 型号规格 / 型号标题 / 物料名称 / 商品名称 | ✅ 二选一 |
| 建议售价 | 零售建议价 / 零售价 / 价目表售价 / 销售指导价 | ✅ |
| 限价 | 零售限制价 / 销售限制价 / **销售限价** / 品牌负责人审核价 / 限价（前缀「（浮动下限价）」存在与否都算命中） | 否 |
| 结算价 | 销售结算价 / 结算价 / 底价 | 否 |
| 成本价 | 实际成本价 / 成本价 / 云仓底价 | 否 |
| 备注 | 备注 | 否 |
| 品牌 | 品牌 / 品牌系 | 否 |
| 产品大类 | 产品大类 / **品类** / 大类 | 否 |
| 产品品项 | 产品品项 / 品项 / **产品品相** | 否 |
| 唯一性ID | 唯一性ID | 否 |

**已实测过的三种形态**（仅供对照，不作为判断依据）：

| 形态 | 特征 | 表头行 | 数据起始 |
|---|---|---|---|
| 申请表 | R1 首格含「申请表」字样 | R3 | R4 |
| 导入模板 | R1 首格含「唯一性ID」 | R1 | R2 |
| 货品表 / 主推表 | R1 可能是标题行或全空，真表头在 R2 | R2 | R3 |

⚠️ **R1 全空不等于空表**：`find_data_sheet` 必须下探 R2 判断有没有表头，否则会跳过真数据表、误选到 `Sheet2` 这类空壳表。
⚠️ 表头行定位完成前，**不要读任何一列的价格**——对方加列后价格列整体右移是常态（实测出现过 O/P/Q/R → P/Q/R/S）。

**多 sheet 累积表（年度申请簿等）：只取最新日期的那一个 sheet 处理，绝不把全部 sheet 合并跑**——历史 sheet 的申请早已导入，全量跑只会产出大批无意义的「更新」行。这一条是用户明确的固定口径。

定位方法：倒序（最右优先）遍历 sheet 名，跳过 `hidden` 开头的表，取**前 8 行有表头语义**的表；日期名 sheet（如 0326、260910）取日期最大的那个，否则取最右。不解析日期名本身（4 位日期名无年份信息，跨年文件会排错）。

🔴 **`Sheet1` / `Sheet2` 这类名字不硬跳**：真数据也会装在唯一一个 `Sheet1` 里（实测一份 297 行的供货价表，整份文件只有一个 Sheet1，曾被旧逻辑整份拒掉）。现行规则：带表头语义的 SheetN **算候选**；多张候选并存时**优先用非 SheetN 名的**（避免 Sheet2 复制品抢走真数据表）；只有「SheetN 名 + 无表头语义」才按空壳诱饵排除（透视表孤岛、草稿表都属这种）。

## 产品匹配三道闸（模糊路径必过）

「精确 → 型号包含 → 子串」里的**型号包含、子串**两条模糊路径，每条候选都要过 `fuzzy_ok()` 才算命中，否则跳过该候选继续找：

1. **品牌一致性闸**：源表型号与候选产品名各自提取品牌词（内置 30 个品牌词表），两边都提取得到且交集为空 → 拒绝。
   实战案例：`东芝平板电视100Z600QFR-S`（东芝）曾被「型号包含」匹配到 `索尼平板电视100Z600QF`（索尼）。
2. **型号码边界闸**：候选产品名必须含型号码（无型号码的泛化名如「波轮洗衣机」不得作为命中）；候选的每个型号码 token 必须出现在源表型号中，且**紧邻字符不得是字母/数字/连字符/罗马数字/ `/` / `+`**（v1.7.5 补 `/`、`+`）。
   实战案例①：`美的电饭煲MB-AFB40C8`（新品）与 `美的电饭煲AFB40C8`（并存老产品）靠 `MB-` 前缀区分，`AFB40C8` 前面贴着 `-` 就说明边界不完整。
   实战案例②：`洗干套装TG10TMC3+TH10HC3` 的 `TG10TMC3` 后面贴着 `+` → **不许**命中套装内单机 `TG10TMC3`；`变频挂机KFR-35GW/MXY1` 的 `KFR-35GW` 后面贴着 `/` → **不许**命中定频基型 `KFR-35GW`。
3. **括号变体闸**：源表型号含 `(...)` 而候选名没有相同括号段（反之亦然）→ 拒绝（如 `F60-33Q7Pro(HE)` 与 `F60-33Q7Pro` 物料号不同，是两个产品）。

被闸拦下的候选不算命中，继续尝试下一个候选；全部落空 → 进核对清单，走 SKILL.md 的连接器兜底流程。

## 同产品去重闸（v1.7.5 新增）

三道闸管的是**单行匹配是否可信**；去重闸管的是**多行命中同一系统产品**：同一系统产品被多行命中会在导入文件里生成重复「产品（必填）」，导入报错或产生重复明细。

规则：精确同名行优先保留 → 其余行降级进核对清单（状态「模糊撞名·已降级」）；多条精确同名 → 同价去重留 1 行、异价该行记「同名多行异价·待确认」。

## 源表列名变体

命中语义表里的任一变体即认，**不要按列字母取数**。列名里带前缀括号（如 `（浮动下限价）品牌负责人审核价`）照样算命中。

> ⚠️ 「销售限价」与「销售限制价」是**两种不同写法，都要认**（2026-09-28 天猫库存物料价目表用的是「销售限价」）。
> 只认前者时整列会被静默漏掉——导入文件不报错，但限价列全空，很容易被当成"本来就没给限价"。
> 「限价」是 2 字短词，只在整格相等时命中，`销售限价` 不等于 `限价`，所以它兜不住这种情况。

**价格四列的列名变体**（金蝶供货价表这类源表写法不同，实测补进来的）：

| 语义 | 还认这些写法 |
|---|---|
| 价目表售价 | 零售建议价 / 销售指导价 / 指导价 / **面价**（挂牌价） |
| 销售结算价 | 结算价 / **核算价** / 底价 |
| 品牌负责人审核价 | 限价 / （浮动下限价）品牌负责人审核价 |
| 成本价 | 成本价 / 实际成本价 / **供 价(RMB)** / 供价 / 供货价 |

> 「供 价」中间有空格，`(RMB)` 会被 `norm_header` 的括号剥离规则去掉，归一化后正好等于「供 价」。

## 组织特例（决定分类怎么填）

> 下面各节标题里的名字指的是**组织**（决定价目表 + 决定分类怎么填），不是产品品牌。
> 分类特例按**组织**判断；「品牌」列**永远填产品的实际品牌**，逐行从型号/产品名推断，两者互不影响。
> 例：组织=乾鑫 → 分类读源表列，但品牌列仍逐行填 美的/大金/格力 等实际品牌。

> 🔴 **两条铁规则，违反即整批数据出错**：
> 1. **组织只决定「价目表（必填）」列**，映射表见 `brand-pricebooks.md`。
> 2. **「品牌」列填产品自己的品牌，永远不填组织名**——天猫组织里放容声冰箱，品牌列写「容声」，不是「天猫」也不是「芯猫」。
>    品牌推断不出来时**回退到留空 + 记核对清单**，宁可空着也不要拿组织名顶。

### 西门子（交叉填法）
字段名与内容反着填：
- 产品大类列 ← 填【西门子品项】组的值，如 `微蒸烤【西门子品项】`
- 产品品项列 ← 填【西门子大类】组的值，如 `微蒸烤箱【西门子大类】`
- 两组选项清单见 brand-pricebooks.md；用关键词表匹配，匹配不上留空进核对清单。

### 乾鑫
- 产品大类、产品品项直接读源表已有列值，脚本仅校验非空。
- 品牌按源表「品牌」列逐行取（格力 / 大金等），不用整表统一品牌。

### 大金
- 产品大类、产品品项固定填「空调」。

### 欣暖家
- 产品大类、产品品项留空（选项无对应则不硬凑）。

### 启欣
- 4 个价格列（成本价 / 销售结算价 / 品牌负责人审核价 / 价目表售价）留空。
- 产品品项留空。
- 其余列（品牌 / 产品大类 / 产品等级 / 折扣 / 产品 / 价目表 / 业务类型）照常填。

### 天猫 / 芯猫（同一个组织）

- **「芯猫」是「天猫」的口语说法，两者是同一个组织**，价目表统一取「天猫价目表20260901」。
- 产品大类、产品品项按**通用关键词表**填；未命中就留空并记核对清单。
  选项表里目前**没有**电视 / 洗衣机 / 干衣机 这类品项，遇到这些品类只能落 `生活电器 / 其他`——**把这类行单独列成「待新增选项」清单交用户拍板**，不要自作主张硬塞近义词。
- 品牌列逐行取**产品实际品牌**：品牌列常写成 `Ronshen/容声` 这种「英文/中文」形式，取 `/` 后的中文；`TCL` 没有中文名，直接用 `TCL`。**绝不填「天猫」或「芯猫」。**
- 表内混有多品牌是常态（同一张价目表里可能有西门子的产品）：**西门子交叉填法只在组织 = 西门子时启用，看组织不看品牌**——天猫组织里的西门子产品照通用规则填。
