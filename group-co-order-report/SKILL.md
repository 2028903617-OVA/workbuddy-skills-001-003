# 集团联单周报生成器

## Overview

将每周的"上周集团内部联单"原始 Excel 加工成符合固定规范的报表包：一个 9~10 工作表的主文件、若干按门店拆分的品牌子文件（带部门小计）、一份按部门带单费汇总表。所有规则（列顺序、归类依据、排序、标黄范围、付款公司兜底）已固化在 `scripts/generate_report.py`，一键即可复现。

## 触发条件

- 用户提供形如 `上周集团内部联单_YYYY-MM-DD HH_MM.xlsx` 的文件，并说"这是上周的数据 / 重新做一下 / 处理一下"。
- 每周固定一次（周初处理上周数据）。

## 工作流

### 1. 确认参数

从文件名/用户话术中提取三项，缺失则向用户确认：

| 参数 | 含义 | 示例 |
|------|------|------|
| `--src` | 源 Excel 绝对路径 | `D:/Backup/Downloads/上周集团内部联单_2026-07-15 14_12.xlsx` |
| `--out` | 输出目录（按 年/月/周 组织） | `F:/集团联单数据/2026/7月/2026.07.06-07.12` |
| `--week` | 周标签（文件名用） | `2026.07.06-07.12` |

可选：
- `--ref`：参考文件，默认 `F:/集团联单数据/2026/4月/2026.04.13-04.19/集团联单明细2026.04.13-04.19.xlsx`（含 370 人卡号 + 46 条付款公司映射）。换路径时传此参。
- `--remove-dajin`：临时去除"大金"公司数据（用户曾要求"大金暂时先去除"）。

### 2. 运行脚本

```bash
python <skill_dir>/scripts/generate_report.py \
  --src "源文件路径" \
  --out "输出目录" \
  --week "2026.07.06-07.12"
  # [--remove-dajin]  如需去除大金
```

脚本自动完成：读取源数据 → 补全银行卡号/开户行（来自参考表）→ 补全付款公司（参考表优先，缺失按公司兜底）→ 剔除不统计品牌 → 欣暖家 0 值带单费重算 → **待回款≠0 暂缓计提** → **拆单合并毛利封顶** → 排序 → 生成主文件/子文件/部门汇总。

> 带单费三步的顺序不可调换（见核心规则第 13 条），否则封顶基数会算错。

### 3. 验证输出

运行后脚本会打印每张子文件、部门汇总与"未匹配银行卡号"名单。务必检查：

- 主文件 Sheet 列表：`销售订单数据` / `集团互联销售明细` / 各品牌 Sheet（按公司归类）/ `集团公司人员卡号` / `内部带单费付款公司汇总表`，**如有调整则追加** `暂缓带单费清单`、`毛利封顶调整清单`。
- 品牌 Sheet **按"公司"列归类**（不是内部员工主属品牌）—— 这是早期易错点。
- 子文件"小计""合计"行的 L 列（现场管理/带单费）已标黄，其余列无底色。
- **本期调整过带单费的数据行，L 列应为橙色 `FFC000`** —— 逐条与运行输出的两份清单核对，橙色行数应等于清单行数。
- **暂缓行（待回款≠0）必须逐条向用户报出**：客户、待回款金额、被暂缓的带单费金额，并说明"款收齐后补算"。
- "未匹配银行卡号"名单—— 这些人需用户手动补填卡号。

### 4. 交付与提示

用 present_files 展示主文件，并口头汇总：本周条数、公司分布、部门带单费合计、未匹配卡号提醒。

## 核心规则（脚本已固化，勿在对话中临时改）

1. **23 列顺序**：前 16 列基础数据 → 姓名/银行卡号/开户行/内部带单费付款公司 → 销售结算毛利合计/毛利合计/待回款金额新（三列在最后，待回款金额新为第 23 列）。19 列版本去掉中间 4 列（姓名/银行卡号/开户行/付款公司）。详见 `references/data_schema.md`。
2. **品牌 Sheet 归类依据 = 公司列**（如公司=西门子，无论内部员工主属品牌是什么，都进西门子 Sheet）。
3. **排序**：先按公司、再按负责人主属部门。
4. **汇总列**：金额列求和；但"内部员工带单提成系数"列（第 13 列）汇总行留空，不参与 SUM。
5. **标黄范围**：小计/合计行**仅 L 列（现场管理/带单费，第 12 列）标黄**；其余列只加粗字体，不标底色。主文件各 Sheet 的合计行同样仅 L 列标黄。
6. **付款公司匹配（严格两级 → 兜底 → 暴露确认）**：
   - **第 1 优先**：精确匹配参考表"内部带单费付款公司汇总表"（权威依据）。
   - **第 2**：剥离 "N组/第N组" 后缀后再精确匹配（如"西门子新时代店1组"→"西门子新时代店"）。
   - **第 3**：仍未命中 → 按公司兜底：启欣→杭州启欣智家电器有限公司；乾鑫→杭州乾鑫暖通设备工程有限公司；方太/西门子→杭州欣锋控股集团有限公司；欣暖家→杭州欣暖家节能科技有限公司。
   - **禁止智能推断**：不得用"卖场关键词/子串相似度"等方式猜测付款公司（曾据此把"方太千年舟西门子店"误判为欣锋，正确应为智好——该条已补入参考表）。宁可走兜底并暴露，也不要静默猜。
   - 所有走兜底的部门会在运行输出末尾汇总为"待人工确认"清单，须向用户核实后补入参考表，再重跑。
7. **子文件拆分**：按 (公司, 负责人主属部门) 分组；命名规则见 `references/data_schema.md`。多部门则每部门加"小计"行 + 末尾"合计"行；单部门仅"合计"行。
8. **格式**：表头蓝底白字加粗（4472C4），薄框线，金额千分位，标题行不转置。
9. **剔除不统计的行**（整行删除，不参与任何统计与子文件）：
   - `内部员工主属品牌` 列命中 `BRAND_EXCLUDE`（当前为 `['泽锋']`）；
   - `实际金额新` 为 **0**（含空值）的行 —— 实际金额为 0 不统计。
10. **带单费为 0 的按一个点重算**：`公司` 列命中 `ZERO_FEE_RECALC_COMPANIES`（当前为 `['欣暖家']`）且 `现场管理/带单费` 为 0 的行，带单费改为 `销售订单金额(元) × ZERO_FEE_RECALC_RATE`（0.01，保留两位小数），`内部员工带单提成系数` 同步写为该系数。仅欣暖家适用，其他公司的 0 值保持原样。
11. **待回款未收齐 → 本期暂不计提带单费（全公司适用）**：`待回款金额新` ≠ 0 的行，把 `现场管理/带单费` 置 **0**，带单费状态记为 `待回款未收齐`；原值另存待补算，**等款收齐后再统计**。这些行必须在运行输出里逐条打印，并汇总进主文件《暂缓带单费清单》Sheet。判定前先做四舍五入到分，±0.00 视为已收齐。
12. **拆单合并看合计毛利（当前限 `SPLIT_MERGE_COMPANIES = ['西门子']`）**：同一公司 + 同一客户（`客户名称` + `客户电话`）+ 订单日期相差 **≤ `MERGE_WINDOW_DAYS`（默认 7）天** 的多张订单，视为"一次成交被拆成多单"，按**组合计**的 `毛利合计`（第 22 列）判定：
    - **合计毛利 ≤ 0** → 组内带单费全部置 0，状态 `毛利≤0不发带单费`；
    - **0 < 合计毛利 < 合计带单费** → 组内带单费按原比例分摊，总额**封顶为合计毛利**（末行兜差，保证分毫不差），状态 `毛利不足已裁剪`；
    - **合计毛利 ≥ 合计带单费** → 正常发放，不动。
    - 客户 + 电话相同但**订单日期相差超过 7 天**的，视为两次独立成交，各自单独判定。
    - 单张订单同样参与本判定（组内只有它自己）。
    - 该规则**只在 `SPLIT_MERGE_COMPANIES` 列出的公司生效**，其他公司即使毛利低于带单费也不裁剪。
13. **执行顺序**：剔除行(第 9 条) → 带单费重算(第 10 条) → 待回款暂缓(第 11 条) → 拆单毛利封顶(第 12 条) → 排序 → 汇总。即：**先算应得、再判暂缓、最后按毛利封顶**；被前一步剔除/暂缓的行不参与后续步骤的封顶基数。
14. **标记配色（不动主表列结构）**：本期被调整过带单费的数据行，其 L 列（现场管理/带单费）填 **橙色 `FFC000`**；小计/合计行的 L 列仍为 **黄色 `FFFF00`**。两种颜色语义不同，不要混用。调整明细另出两个 Sheet：`暂缓带单费清单`（待回款类）、`毛利封顶调整清单`（裁剪类），**无内容时不生成该 Sheet**。
15. **待回款跨周跟踪（自动登记 + 运行时提醒）**：所有被暂缓（规则 11）的订单自动登记进《带单费待回款跟踪清单》`F:/集团联单数据/带单费待回款跟踪清单.xlsx`。每次运行脚本时：
    - 已有跟踪项且本期待回款已归 **0** → 状态改 `已全款-待补算`，提醒"请补算带单费"；
    - 否则提醒"仍有待回款，继续暂缓"；
    - 本周新暂缓订单自动追加（状态 `待核查全款`）。
    运行输出会打印 `⏰ 待回款跟踪提醒` 清单，**必须原样转达给用户**（客户、待回款金额、是否已全款）。
16. **写入前须确认目标文件未被占用**：生成时若报 `PermissionError`（存在 `~$xxx.xlsx` 锁文件 = 该文件正被 Excel/WPS 打开），应提示用户关闭该文件后重跑；不要静默跳过或改用临时文件名交付。

## 与新部门的协作

出现参考表未收录的新部门（如"美的滨江店""乡镇"）时，脚本已按公司兜底自动填付款公司，无需每次打扰用户。若用户明确给出某部门的精确付款公司，应同步更新参考文件 `内部带单费付款公司汇总表` 并提示（参考历史：`格力办公室`、`乡镇-城西新时代集合店`、`格力特渠部` 的添加）。
