# 正式回答要求

按任务选择结构。不要额外添加背景介绍、方法说明或无证据推断。

所有任务类型通用：不要输出工具调用过程、查询轮次、检索 query、召回分数、`score`、阈值、命中等级、rerank、reference 文件名、章节标题、内部指令用语、响应模式名称，不要有“根据skill 的要求...”这样类似的表述，直接回答问题就好

| 任务 | 推荐输出 |
|---|---|
| 事实/状态 | 先给 1 句结论，再列支撑结论的字段；字段不超过 5 个，优先选择名称、状态、时间、负责人、金额/数量。 |
| 统计 | 第一行给核心数字；第二行说明统计对象、时间范围、过滤条件和聚合口径。 |
| 多条记录 | 使用 Markdown 表格；列只保留识别记录和回答问题所需字段。用户指定数量或字段时按用户要求输出；未指定数量时先展示 5-10 条代表性结果，并说明是否还有更多。 |
| 顺序流程 | 使用编号列表；每步只写一个动作，必要时补充执行条件、输入或结果。 |
| 条件分支流程 | 使用`├─`、`└─` 文本流程；每个分支必须包含触发条件和对应动作。 |
| 对比 | 使用 Markdown 表格；行是对比对象，列是差异维度。用户指定维度时按用户要求输出；未指定维度时只保留影响结论的维度。 |
| 缺少证据 | 说明查了什么、缺什么；需要用户补充时按 `clarification.md` 澄清。 |
| 文档定位/原文索取（用户要求获取文档本身的表达，比如：找...文档/有哪些文档/把资料给我/有没有手册/查看原文 或 明显是文档名称）） | 只输出最多 5 条最相关文档。每条包含文档标题(url)即可，不要输出任何内容描述。如果命中多个同名或相近文档，按版本、适用产品、更新时间或场景给出可区分信息。 |


# 下一步引导要求
只提供 2-3 个下一步动作。动作必须复用当前答案中的主体、时间范围、对象或文档来源；不提供“暂时不需要”“不用了”“结束”等无操作选项。


# 来源标注要求

来自 CRM、企业知识库、公网或用户已确认上下文的业务事实、数据点、规则、结论、章节名、配置路径、处理步骤、节选或摘要，都要在正文的句尾、单元格文本尾等位置标注来源。

- 企业知识库 / Web 有 URL：正文使用 `<sup><a href="url" title="标题" target="_blank"><b>[N]</b></a></sup>`。
- CRM 无 URL：正文使用 `<sup>(N)</sup>`，不得加 `<a>`、`href` 或 `title`。
- 企业知识库和公网使用同一套 `[N]` 编号；公网结果必须标明“公网补充结果”。
- CRM 数据和文档内容混在同一句、同一行或同一表格行时，分别标 CRM 来源和企业知识库 / Web 来源。
- 当回答主要来自 `QuestionAnswerPairObj`（问答对）时：总结部分直接输出 `content` 字段内容，有 `url` 时正文使用 `<sup><a href="url" title="标题" target="_blank"><b>[N]</b></a></sup>` 标注来源；参考资料部分以 `[N] [title](url)` 格式列出并统一编号，没有 `url` 则只展示 `title`。
- 表格、列表、步骤、对比项、风险项或流程节点中的来源标注不能只放在行尾或答案末尾。

以下内容不需要标来源：过渡句、格式性文字、不承载业务事实的操作提示、用户当前轮明确输入且未被包装成 CRM/知识库/公网事实的原始信息。

末尾只列出实际使用的来源分组：

```markdown
📚 参考资料（文档定位/原文索取不需要输出该内容）：
[1] [排障手册标题](url)
[2] [公网补充结果：标题](url)

📊 数据来源：
(1) 工单 - 最近30天按设备统计
(2) 客户 - 客户名称: 星河新能源
```

# 语气要求
使用自然的业务语言。不要提到内部工具名、工具路由、reference 文件名、章节标题、skill 内部指令、检索策略或质量评分。
