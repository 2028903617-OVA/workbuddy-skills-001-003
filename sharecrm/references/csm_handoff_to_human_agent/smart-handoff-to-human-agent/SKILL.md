# 智能转人工客服

## 1. 适用场景

### 1.1 适用场景

当出现以下情况时，使用本技能：

- 客户明确要求人工客服
- 当前流程已经明确判断需要人工处理
- 当前问题已经进入人工接手路径
- 判定客户诉求已超出机器人能力范围，无法解决用户问题，必须由人工进行处理

### 1.2 不适用场景

以下情况不要使用本技能：

- 只是高优先级问题，但还没有明确转人工结论
- 只是知识不足，但还没有明确进入人工处理
- 当前只是需要进一步澄清用户诉求

## 2. 执行路径

**第一步：确认前提条件**

参考1.1适用场景，只有在客户明确提出人工诉求，或上游技能/当前流程已经明确判定需要人工处理时，才允许进入本技能。


**第二步：收集已有上下文**

从当前会话中提取已有的上下文信息（客户问题描述、设备信息、服务请求编号、联系方式等），为人工交接做准备。

工具：无需额外调用，从会话记录中提取。

**第三步：调用人工转接**

调用转人工操作：

工具：`sharecrm service session transfer-to-human`

执行命令：
```bash
sharecrm service session transfer-to-human
```

**第四步：向客户确认转接结果**

- 成功：告知客户已转接人工，不再追问无关信息。
- 失败：告知客户当前无法立即完成转接，补充最少必要信息（如联系电话）。


**第五步：处理特殊情况**

- 如果当前会话中已经有足够上下文（客户问题描述、设备信息、服务请求编号、联系方式等），则不要要求客户重复说明，直接传递上下文。
- 如果系统暂时无法立即完成转人工，只补充最少必要信息（例如联系电话），不要重新进入长表单流程。
- 如果转接接口返回超时，应告知用户"转接请求已提交，请稍候"，由系统后台继续处理。

## 3. 禁止行为

你不得：

1. 在尚未明确需要人工时直接转人工
2. 因为问题紧急就默认直接执行转人工
3. 在客户明确要求人工后继续长时间追问
4. 在转人工场景中重新拉回知识问答或对象创建路径
5. 将内部动作名直接展示给客户
6. 在失败时编造转接成功的回复


## 4. 输出结果

### 4.1 成功输出

调用成功后，向客户明确说明已协助转人工。


表达参考：
- 好的，我已为您转接人工客服，请稍候。
- 好的，我已为您提交人工处理，请稍候。
- 我这边已为您转交人工客服继续协助处理。

### 4.2 失败输出

如果当前无法立即完成转人工，则礼貌说明并补充最少必要信息。

表达参考：
- 当前我先为您登记并转交人工处理。为了方便尽快联系您，请提供一下联系电话。


## 失败模式

| 失败场景 | 处理方式 |
|---------|---------|
| 前提条件不满足（客户未明确要求人工，上游也未判定） | 禁止调用转接，返回上游流程继续处理，并说明原因 |
| 转接接口返回超时 | 告知用户"转接请求已提交，请稍候"，由系统后台继续处理 |
| 转接接口返回错误（如 sessionId 无效） | 记录错误日志，告知用户"暂时无法完成转接，请稍后重试或联系管理员" |
| 重复转接请求（同一会话已转接） | 去重处理，告知用户"已在处理中，请稍候" |
| 缺少会话 ID 等上下文 | 提示"缺少必要信息，无法完成转接" |

### 测试用例

**测试用例 1：客户明确要求转人工**

用户输入："转人工"
预期行为：
1. 检查前提条件：客户明确提出人工诉求 → 满足
2. 提取当前会话已有上下文
3. 调用 `sharecrm service session transfer-to-human`
4. 执行成功，输出"好的，我已为您转接人工客服，请稍候。"
5. 不再追问其他问题

**测试用例 2：客户仅询问人工可行性**

用户输入："你们有人工客服吗？"
预期行为：
1. 检查前提条件：客户未明确要求人工，仅为询问 → 不满足
2. 不调用转接
3. 回复澄清："我们有人工客服，请问您需要转人工处理吗？"
4. 等待客户确认后再进入本技能
