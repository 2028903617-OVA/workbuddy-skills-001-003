# 话术推荐

## 1. 适用场景

### 1.1 适用场景

- 客服接手机器人处理后的会话，需要快速组织回复
- 客服已经了解客户问题，希望生成适合发送的话术
- 客服希望基于不同语气风格选择更合适的回复

### 1.2 不适用场景

- 当前缺少可用的会话上下文
- 当前客服并不需要生成回复话术
- 当前任务是直接查询案例、创建案例或查询服务进度

## 2. 执行路径

**第一步：获取当前会话上下文**

每次触发话术推荐，都必须重新调用 `sharecrm service session detail` 获取最新会话上下文，并提取 `webim_visitor_id`。不得复用上一次技能执行结果。

```bash
sharecrm service session detail
```

**第二步：获取聊天记录**

必须先调用 `sharecrm service session messages` 获取当前人工会话实时聊天记录。若当前人工会话已有客户消息或客服回复，它是话术生成的主要依据。

```bash
sharecrm service session messages
```

若 `webim_visitor_id` 可用，继续查询前序智能客服会话。前序智能客服会话用于补充背景；当客户刚转人工、当前人工会话尚无有效聊天记录时，可作为首次应答话术的主要依据。

```bash
sharecrm data record query-by-fields --object_api_name CustomerServiceSessionObj --select_fields _id,session_type,session_id,name,create_time,customer_service_session_id --webim_visitor_id-eq {webim_visitor_id} --sort create_time:desc --limit 5
```

选择最近一条会话类型为“智能客服”的记录，再获取完整记录并读取 `chat_record`：

```bash
sharecrm data record get-by-id --object_api_name CustomerServiceSessionObj --id {智能客服会话_id}
```

前序智能客服会话为空、查询失败或 `chat_record` 不可用时，不阻断话术生成；若当前人工会话实时聊天记录可用，则仅基于当前人工会话继续处理。若当前人工会话和前序智能客服会话均不可用，才输出失败提示。

**第三步：提取关键上下文**

优先基于当前人工会话实时聊天记录提取；若当前人工会话为空但前序智能客服会话可用，则基于前序智能客服会话提取首次应答上下文：

1. 客户当前问题摘要
2. 客户情绪状态
3. 客服已回复内容
4. 待回复的客户问题
5. 前序智能客服已提供的信息

**第四步：生成话术推荐**

生成 3 种风格话术：

| 风格 | 适用场景 | 特点 |
|------|---------|------|
| 专业简洁型 | 问题明确、客服需要直接回复 | 简洁明确 |
| 安抚说明型 | 客户急迫、不满或需要安抚 | 先共情再说明 |
| 推进处理型 | 需要推进处理流程 | 明确下一步动作 |

## 3. 禁止行为

- 不得复用上一次技能执行时的会话上下文、聊天记录或提取结果
- 当前人工会话已有有效客户消息或客服回复时，不得忽略当前人工会话而仅基于前序智能客服会话生成话术
- 不得使用列表查询中可能被截断的 `chat_record` 片段生成话术
- 不得编造前序会话内容、扩展无关历史会话或生成脱离当前会话的模板化回复
- 不得向客服输出内部字段名、命令、调试过程、CHECKPOINT、工具调用过程或执行步骤说明
- 不得只生成一种风格的话术推荐

## 4. 输出结果

### 4.1 成功输出

输出可由 Agent 根据当前会话内容自行组织，不限制固定标题、分隔线或版式。

必须输出 3 种可直接发送或稍作编辑后发送的话术建议，覆盖以下方向：

- 专业简洁型：适合问题明确、客服需要直接回复
- 安抚说明型：适合客户急迫、不满或需要情绪安抚
- 推进处理型：适合需要明确下一步动作或引导客户配合

每条话术都必须基于实际会话内容，不得空泛模板化；不得展示工具调用、字段名或执行步骤。若某一风格不适合当前场景，可保持该风格的语气方向，但内容仍必须围绕当前问题生成。

### 4.2 失败输出

- "当前缺少必要的会话上下文，暂时无法生成准确的话术推荐。"
- "当前会话聊天记录暂不可用，无法生成准确话术推荐。"
- "当前会话内容不足以生成多种风格的话术，请补充更多会话信息后重试。"

## 失败模式

| 失败场景 | 处理方式 |
|---------|---------|
| 当前会话上下文获取失败 | 不得向用户索要会话 ID，提示缺少会话上下文 |
| 当前人工会话实时聊天记录为空，但前序智能客服会话可用 | 基于前序智能客服会话生成首次应答话术 |
| 当前人工会话实时聊天记录获取失败，但前序智能客服会话可用 | 可基于前序智能客服会话生成首次应答话术，并避免声称已参考当前人工会话 |
| `webim_visitor_id` 缺失、最近 5 条无智能客服会话、前序查询失败或 `chat_record` 不可用 | 前序智能客服会话视为不可用；若当前人工会话可用则继续生成，否则输出失败提示 |
| 当前人工会话与前序智能客服会话均不可用 | 提示"当前会话聊天记录暂不可用，无法生成准确话术推荐" |
| 客户问题不明确 | 提示客服先确认客户需求，不生成空泛话术 |
| 权限不足 | 提示当前账号无权限访问会话 |

## 验证清单

### 测试用例

**测试用例 1：正常场景**

输入：客服点击“话术推荐”，当前会话中客户反馈“我的空调不制冷了，上次有人来修也没修好”。

预期行为：
1. 调用 `sharecrm service session detail` 获取最新会话上下文
2. 调用 `sharecrm service session messages` 获取当前人工会话实时聊天记录
3. 基于 `webim_visitor_id` 查询同一访客最近 5 条会话，选择最近一条“智能客服”会话
4. 使用 `get-by-id` 获取智能客服会话完整记录并读取 `chat_record`
5. 以当前人工会话实时聊天记录为核心，参考前序智能客服会话背景，生成 3 种风格话术

**测试用例 2：无前序智能客服会话**

输入：客服点击“话术推荐”，当前会话中客户咨询产品保修期，最近 5 条会话中无“智能客服”会话。

预期行为：
1. 已获取当前会话上下文和当前人工会话实时聊天记录
2. 前序智能客服会话视为不可用
3. 仅基于当前人工会话实时聊天记录生成 3 种风格话术

**测试用例 3：当前人工会话实时聊天记录不可用**

输入：客服点击“话术推荐”，但 `sharecrm service session messages` 获取失败或为空，且未获取到可用的前序智能客服会话。

预期行为：
1. 不编造当前会话或前序会话内容
2. 输出失败提示：“当前会话聊天记录暂不可用，无法生成准确话术推荐。”

**测试用例 4：客户刚转人工，当前人工会话为空**

输入：客户刚从智能客服转入人工，当前人工会话尚无新消息，客服点击“话术推荐”。

预期行为：
1. 调用 `sharecrm service session detail` 获取最新会话上下文
2. 调用 `sharecrm service session messages`，确认当前人工会话暂无有效聊天记录
3. 基于 `webim_visitor_id` 查询同一访客最近 5 条会话，选择最近一条“智能客服”会话
4. 使用 `get-by-id` 获取智能客服会话完整记录并读取 `chat_record`
5. 基于前序智能客服会话内容生成首次应答话术

### 验证检查清单

- [ ] 每次触发均重新调用 `sharecrm service session detail`
- [ ] 已调用 `sharecrm service session messages` 获取当前人工会话实时聊天记录
- [ ] 当前人工会话有有效内容时，已作为话术生成主要依据
- [ ] 当前人工会话为空但前序智能客服会话可用时，已基于前序智能客服会话生成首次应答话术
- [ ] 前序智能客服会话查询使用 `--webim_visitor_id-eq {webim_visitor_id}`、`--sort create_time:desc` 和 `--limit 5`
- [ ] 若存在前序智能客服会话，已通过 `get-by-id` 获取完整记录并读取 `chat_record`
- [ ] 未使用 `query-by-fields --data`、`sharecrm data describe get` 或列表查询中的截断 `chat_record`
- [ ] 未复用上一次技能执行结果
- [ ] 话术基于实际会话内容，覆盖 3 种不同风格
- [ ] 当前人工会话和前序智能客服会话均不可用时，未强行生成话术
- [ ] 输出不包含内部字段名、命令、调试过程、CHECKPOINT 或执行步骤说明
