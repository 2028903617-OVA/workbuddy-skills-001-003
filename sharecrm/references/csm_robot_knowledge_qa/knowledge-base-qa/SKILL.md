# 机器人知识库问答

## 1. 适用场景

### 1.1 适用场景

- 产品功能、使用方法、常见问题咨询
- 故障排查、报警代码说明
- 报修流程、服务流程、保修政策等说明

### 1.2 不适用场景

- 客户要创建服务请求
- 客户要查询服务处理进度
- 客户明确要求人工客服

## 2. 执行路径

**第一步：判断问题类型**

判断用户问题是否属于知识库问答场景。不属于时，转交对应技能或人工处理。

**第二步：判断是否具备检索条件**

对故障、报警、停机、无法启动类问题，先判断是否有有效定位信息。有效定位信息包括：设备/产品类型、设备型号、故障码/报警码、明确故障现象、通电状态、发生场景等。

若用户仅表达“机器无法启动”“设备坏了”“不能用了”等泛化问题，不执行检索，只追问一轮。用户补充任一有效定位信息后，即可进入检索，不得连续追问。

**第三步：知识检索**

检索词只能来自用户明确提供的信息，不得自行补充产品型号、故障码或设备类型。

```bash
sharecrm knowledge expertise rag-search-knowledge --data '{"content": "<检索词>"}'
```

**第四步：判断检索结果**

仅当检索结果与用户明确提供的产品、型号、故障码、现象或流程问题匹配时，才可生成答案。若检索结果命中具体产品、型号或故障码，但用户未明确提供这些信息，视为不匹配。

**第五步：输出结果**

- 匹配且足以回答：按成功格式输出，并标注来源引用
- 信息不足：只输出面向客户的一轮追问
- 检索不足或不匹配：说明暂未找到准确知识，并建议人工处理

## 3. 禁止行为

- 不得使用 `--query`、调用 `rag-search-knowledge --help` 或临时探索参数格式
- 不得在信息不足时强行检索或输出具体排查方案
- 不得连续追问；信息不足时最多追问一轮
- 不得引用用户未明确提供的具体产品、型号或故障码文档
- 不得编造知识答案、参考资料或来源引用
- 不得引用未出现在本次检索结果中的知识条目
- 不得向客户展示内部判断过程、技能规则、系统动作名或检索策略
- 禁止将意图识别、内部判定过程写入output中进行输出

## 4. 输出结果

### 4.1 成功输出

如果检索结果足以回答，先一句话回答用户核心疑问，再输出结构化内容：

```markdown
**{分组标题}**

- {事实1}<sup><a href="url" title="文档标题" target="_blank"><b>[1]</b></a></sup>
- {事实2}<sup><a href="url" title="文档标题" target="_blank"><b>[1]</b></a></sup>

---

📚 **参考资料：**

1. [文档标题](url)
2. [文档标题](url)

---

💡 **您可能想了解：**

1. 推荐问题1
2. 推荐问题2
```

要求：

- 每条事实都必须来自本次检索结果，并标注来源：`<sup><a href="url" title="文档标题" target="_blank"><b>[N]</b></a></sup>`
- 参考资料必须来自本次检索命中的知识条目，且使用可点击链接格式
- “您可能想了解”补充 2 到 3 个相关延伸问题
- 回答应清晰、简洁、面向客户，不直接整段复制检索内容

### 4.2 失败输出

如果未找到足够相关知识，礼貌说明并建议人工处理。

推荐表达：

- 抱歉，当前我没有检索到足够准确的相关知识，暂时无法直接回答您的问题。
- 如果您愿意，我可以继续为您转人工客服协助处理。

### 4.3 信息不足追问输出

如果用户问题缺少必要定位信息，只追问一轮，不要输出知识库答案，也不要解释内部判断依据。

推荐表达：

- 为了更准确地判断原因，请您补充一下设备类型/型号，或告诉我是否有故障代码、报警提示。
- 如果暂时不清楚型号，也可以先告诉我设备显示的故障代码或具体现象。

禁止表达：

- 根据知识库问答技能的要求，当前问题属于泛化故障描述。
- 因缺少必要定位信息，我不能直接检索。
- 我判断当前问题不满足检索条件。

## 失败模式

| 异常场景 | 处理方式 |
|----------|----------|
| 故障问题缺少定位信息 | 不执行检索，只追问一轮 |
| 已追问一轮后用户补充任一定位信息 | 直接检索，不继续追问其它条件 |
| 检索结果为空、冲突或不足 | 说明暂未找到准确知识，建议人工处理 |
| 检索结果命中具体产品/故障码但用户未提供 | 视为不匹配，不引用该知识；若已追问过则建议人工 |
| 知识检索 API 超时或返回错误 | 提示稍后重试或转人工 |
| 用户输入超出知识库范围 | 转交对应技能或人工处理 |

## 验证清单

### 测试用例

**测试用例 1：产品功能咨询**

输入：“XX型号的保修期是多久”

预期行为：
1. 使用 `--data` 执行知识检索
2. 基于检索结果回答保修期限和适用范围
3. 每条事实标注 `<sup>` 来源引用
4. 输出参考资料和“您可能想了解”

**测试用例 2：泛化故障描述**

输入：“机器无法启动”

预期行为：
1. 判断缺少定位信息
2. 不执行知识检索
3. 只追问一轮设备类型/型号、故障代码或具体现象
4. 不输出内部判断过程

**测试用例 3：追问后补充定位信息**

输入：用户先说“机器无法启动”，机器人已追问一轮；用户回复“故障代码 E01”

预期行为：
1. 识别用户已补充有效定位信息
2. 直接执行知识检索
3. 不继续追问设备类型、型号、通电情况等其它条件
4. 检索结果足以回答时输出带来源引用的答案；不足时建议人工

**测试用例 4：检索命中但不匹配**

输入：“设备无法启动”

检索结果：命中 E01 故障、某具体型号设备或明确产品文档

预期行为：
1. 判断检索结果中的 E01、具体型号或产品信息未由用户明确提供
2. 不基于该文档输出具体排查步骤
3. 若尚未追问过则追问一轮；若已追问过则建议人工

- [ ] 用户补充任一有效定位信息后已执行检索

- [ ] 回答事实来自本次检索结果，未编造
- [ ] 每条事实都有 `<sup>` 来源引用
- [ ] 参考资料来自本次检索结果
- [ ] 未展示内部判断过程、技能规则、系统动作名或检索策略
