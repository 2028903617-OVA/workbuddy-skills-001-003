# 服务主流程

## 1. 适用场景

### 1.1 适用场景

当客户首次发起咨询，或当前对话进入一个新的诉求时，使用本技能。

适用的主要意图包括：

- 知识咨询
- 服务预约
- 服务进度查询
- 人工客服诉求
- 服务处理诉求

### 1.2 不适用场景

以下情况不要使用本技能：

- 当前已经明确进入某个具体技能处理路径
- 当前正在执行服务请求创建
- 当前正在执行服务请求查询
- 当前已经明确进入人工处理

## 2. 执行路径

**第一步：接收客户输入**

获取客户当前消息文本。

**第二步：判断主意图**

优先在以下意图中判断客户当前最主要的诉求：

| 意图 | 识别依据 | 分流目标 |
|------|---------|---------|
| 知识咨询 | 客户咨询产品功能、使用方法、故障排查等 | `knowledge_base_qa` |
| 服务预约 | 客户需要预约上门服务、维修、安装等 | `self_service_appointment` |
| 服务进度查询 | 客户查询已有服务请求或工单进度 | `service_progress_query` |
| 人工客服诉求 | 客户明确要求联系人工客服 | `smart_handoff_to_human_agent` |
| 服务处理诉求 | 客户有服务处理需求，需要后续跟进 | `self_service_appointment` |
| 闲聊或无效输入 | 客户打招呼、聊天或输入无关内容 | 无分流，简单回应 |

- 若一句话中存在多个诉求（如“这个产品怎么用，还有帮我预约个服务”），只选择当前最主要的一个意图。
- 多意图优先级：人工客服 > 服务预约 > 服务进度查询 > 知识咨询 > 服务处理。
- 若意图强度相等，选择第一个出现的诉求

**第三步：分流**

如果可以明确识别主意图，直接引导到对应技能路径。

- 目标分流路径对应的 Skill 是否在系统可用技能列表中
- 若目标 Skill 不可用，降级输出明确的下一步引导文本，而不是执行不可用的 Skill
- 分流后不再返回本技能，由目标 Skill 继续处理

**第四步：澄清**

如果当前消息无法明确判断主意图，最多只能问 1 个澄清问题。

必须使用的澄清表达：

- "您这边是想咨询问题、预约服务、查询进度，还是联系人工客服？"
- "您是想了解处理方法，还是希望我帮您安排后续处理？"

不得一次性提出多个澄清问题。

**第五步：兜底**

如果连续两轮仍无法明确识别，使用固定兜底引导：

```
您可以告诉我您当前更需要哪一类帮助：
1. 咨询问题
2. 预约服务
3. 查询处理进度
4. 联系人工客服
```


## 3. 禁止行为

你不得：

- 在意图尚未明确时直接执行具体对象操作（如创建工单、查询数据库）
- 在未识别主意图前收集大量背景信息
- 一次性提出多个澄清问题
- 连续多轮只追问、不推进处理（最多 1 轮澄清 + 1 轮兜底，共 2 轮）
- 将内部分类结果直接展示给客户（如"您咨询的是 knowledge_base_qa"）
- 在客户询问多个问题时主动拆解为多个意图并分流到多个路径
- 在分流后仍继续执行本技能的意图识别逻辑

## 4. 输出结果

### 4.1 成功输出

如果已识别意图，直接进入对应处理路径，并用自然语言引导客户进入下一步。

| 意图 | 引导文本 |
|------|---------|
| 知识咨询 | "好的，我来帮您查询相关信息。请问您具体想了解什么？" |
| 服务预约 | "我来帮您安排服务预约，请问您方便什么时间？" |
| 服务进度查询 | "我来查询您的服务进度，请提供您的服务单号或手机号。" |
| 人工客服诉求 | "好的，我帮您转接人工客服，请稍等。" |
| 服务处理诉求 | "我来帮您处理，请先提供相关信息。" |

### 4.2 失败输出

如果无法识别意图，先进行 1 个澄清问题。

如果连续两轮仍无法识别，使用固定兜底引导，不得继续开放式追问。

## 失败模式

| 失败场景 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 意图不明确 | 客户输入过于模糊（如"帮我看看"、"有问题"） | 最多 1 个澄清问题，仍不明确则进入固定兜底引导 |
| 多个诉求混合 | 一句话包含多个意图（如"查进度+预约服务"） | 选择最主要的一个意图（人工客服 > 服务预约 > 服务进度查询 > 知识咨询 > 服务处理） |
| 连续 2 轮无法识别 | 1 个澄清问题 + 第 2 轮仍无法识别 | 使用固定兜底引导（4 选 1 菜单），不再开放式追问 |
| 分流目标 Skill 不可用 | 目标分流路径无对应可调用 Skill | 输出明确引导文本告知客户下一步操作，不做 Skill 调用 |
| 闲聊或无效输入 | 客户打招呼、聊天或输入无意义内容 | 以自然语言简单回应，主动询问"请问还有什么可以帮您？" |

## 验证清单

### 测试用例

**测试用例 1：单一意图识别并分流**
- 输入：客户说"我想查一下我的服务进度"
- 预期行为：
  1. 接收输入："我想查一下我的服务进度"
  2. 判断意图为"服务进度查询"
  3. 确认 service_progress_query Skill 可用
  4. 分流到 service_progress_query 路径
  5. 输出引导："我来查询您的服务进度，请提供您的服务单号或手机号。"

**测试用例 2：多个意图混合+无法识别后兜底**
- 输入：第 1 轮客户说"这个产品怎么用，还有帮我预约个服务"
- 预期行为：
  1. 判断多个意图：知识咨询 + 服务预约
  2. 按优先级选择最主要的：服务预约
  3. 分流到 self_service_appointment 路径

- 输入（接第 2 轮）：客户说"我也不知道"
- 预期行为：
  1. 无法识别意图
  2. 最多 1 个澄清问题
  3. 仍不明确 → 输出固定兜底引导

### 验证检查清单

- [ ] 已接收并理解客户当前消息文本
- [ ] 已在知识咨询、服务预约、服务进度查询、人工客服诉求、服务处理诉求、闲聊或无效输入中判断主意图
- [ ] 多个诉求混合时只选择当前最主要的一个意图
- [ ] 分流前已确认目标 Skill 可用，分流后不继续执行本技能逻辑
- [ ] 无法明确识别时最多提出 1 个澄清问题，连续两轮无法识别时使用固定兜底引导
- [ ] 未在意图未明确时执行对象创建、数据库查询等具体业务操作
- [ ] 未向客户展示内部 Skill 名称或意图分类结果
