# 服务进度查询

## 1. 适用场景

### 1.1 适用场景

当客户表达以下诉求时，使用本技能：

- 查询服务请求进度
- 查询预约是否已安排
- 查询售后处理状态
- 查询上门服务进展

### 1.2 不适用场景

以下情况不要使用本技能：

- 客户在咨询知识类问题
- 客户要新建服务请求
- 客户明确要求人工客服

## 2. 执行路径

**第一步：确认查询条件**

确认客户是否提供了服务请求编号或联系电话。不可自行探索其他查询方式。

**第二步：执行查询**

使用 `sharecrm data record query-by-fields` 查询 `ServiceRequestObj`。

- 有服务请求编号 → 直接使用编号查询
- 无编号但有联系电话 → 使用联系电话查询

联系电话查询命令：

```bash
sharecrm data record query-by-fields --object_api_name ServiceRequestObj --contact_tel-eq {联系电话} --select_fields name,subject,service_request_status,assign_status,priority,create_time,appointment_processing_time,problem_desc,deal_user,finish_time
```

**第三步：处理查询结果**

- 唯一记录：进入第四步，返回进度结果。
- 多条记录：不要直接展示全部结果，进入二次澄清，让客户提供服务请求编号、确认具体事项或预约时间。
- 无记录：礼貌提示客户核对服务请求编号或联系电话。

推荐表达：

- "当前未查询到对应的服务请求记录，您可以先核对一下服务请求编号或联系电话。"

**第四步：返回进度结果**

返回内容包括：

- 服务请求编号
- 当前状态
- 最近进展
- 下一步安排

如果查询到多条服务请求，不要直接把全部查询结果展示给客户。

查询结果字段仅用于内部判断、定位和生成回复，不等于直接面向客户展示。

多条结果时，必须先进入第三步的二次澄清流程，进一步收敛查询范围；只有客户确认唯一记录后，才返回最终进度。

## 3. 禁止行为

你不得：

1. 使用 `sharecrm data record query-by-name` 查询服务请求
2. 调用 `query-by-fields --help`
3. 调用 `sharecrm data describe get`
4. 在当前技能中自行探索字段结构
5. 在当前技能中重新规划查询路径
6. 因查询失败自行切换为其他未指定查询方式
7. 将 `query-by-fields` 改写为 `--data` 格式
8. 在执行前重新判断参数格式
9. 在执行前重新判断是否需要 `--select_fields`
10. 查询到多条记录时直接输出全部服务请求列表
11. 将内部查询结果原样表格化展示给客户
12. 在客户未明确确认唯一记录时返回进度结果
13. 在最终回复中输出内部对象名、字段名、查询命令或数据来源说明


## 4. 输出结果

### 4.1 成功输出

如果查询到唯一服务请求，向客户说明：

- 服务请求编号
- 当前状态
- 最近进展
- 下一步安排

回复时只输出对客户有用的最终结果，不要原样输出内部查询字段。


### 4.2 失败输出

如果未查询到对应记录，礼貌提示客户核对信息。

推荐表达：

- 当前未查询到对应的服务请求记录，您可以先核对一下服务请求编号或联系电话。

如果查询到多条记录，不要直接返回最终结果。

推荐表达：

- 我这边查询到多条相关服务请求，请您提供一下具体的服务请求编号，我再继续为您查看。
- 我这边查询到多条相关记录，请您确认一下具体事项或预约时间，我来帮您继续定位。


## 失败模式

| 异常场景 | 处理方式 |
|----------|----------|
| 接口调用超时 | 提示用户稍后重试 |
| 参数格式错误（如电话格式非法） | 提示用户核对输入格式后重新输入 |
| 查询结果为空 | 礼貌提示核对服务请求编号或联系电话 |
| 查询到多条结果 | 进入二次澄清流程，逐条确认筛选 |
| 用户未提供任何查询条件 | 引导用户提供服务请求编号或联系电话 |


## 验证清单

### 测试用例

**测试用例 1：通过联系电话查询到唯一记录**
- **输入**："查一下我的服务进度，电话是 13800138000"
- **预期行为**：
  1. 使用 `query-by-fields --object_api_name ServiceRequestObj --contact_tel-eq 13800138000` 查询
  2. 返回唯一记录
  3. 输出：服务请求编号、当前状态、最近进展、下一步安排

**测试用例 2：查询到多条记录**
- **输入**："我的售后处理怎么样了？电话是 13800138000"
- **预期行为**：
  1. 查询到多条记录
  2. 不直接展示全部记录
  3. 进入二次澄清："查询到多条相关服务请求，请提供具体的服务请求编号"
  4. 客户确认后返回最终结果

**测试用例 3：查询结果为空**
- **输入**："帮我查一下进度，编号 SR-99999"
- **预期行为**：
  1. 查询结果为空
  2. 礼貌提示："当前未查询到对应的服务请求记录，您可以先核对一下服务请求编号"


### 验证检查清单

输出前逐条检查：

1. [ ] 查询条件来源已验证（服务请求编号或联系电话）
2. [ ] 已使用 `query-by-fields` 查询 `ServiceRequestObj`，并显式传入 `--select_fields`
3. [ ] 未使用 `--data`、describe、help 或其它未指定查询方式
4. [ ] 查询结果为唯一记录时才展示最终进度
5. [ ] 查询到多条结果时已进入二次澄清流程
6. [ ] 输出内容不包含内部字段、ID、对象名、查询命令或系统状态码
