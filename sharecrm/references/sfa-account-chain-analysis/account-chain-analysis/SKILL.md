# account-chain-analysis

## Goal

作为客户情报 Agent 中的专题 Skill，围绕目标客户生成面向客户理解的产业链分析结果，重点回答：

1. 这个客户在产业链中处于什么位置。
2. 这个客户卖给谁、依赖谁、通过什么链路运作。
3. 这个客户有哪些上下游、渠道、生态、集团或资本关系。
4. 这些关系会给客户经营、需求、风险和相关情报信号带来什么影响。

本 Skill 的输出重点不是围绕产业链找新客户，而是把产业链关系解释成对“这个客户”的业务理解和判断依据。

## Trigger

适合：

- 用户要求分析某个客户的产业链位置、上下游、渠道或生态关系。
- 用户说“这个客户上游下游是谁”“客户在产业链什么位置”“客户依赖谁”“客户有哪些生态关系”“客户的渠道和上下游结构是什么”。
- 客户尽调报告需要补充产业链位置、上下游关系、渠道生态和关键依赖。
- 销售或销售管理者需要在会前理解客户链路结构。
- 售前需要理解客户业务链条、组织复杂度和系统相关信号。
- 客户成功需要理解客户业务链和合作复杂度是否影响续费、扩容或服务覆盖。
- 风控或签约角色需要理解集团关系、资本关系、关键供应依赖或下游集中度。

不适合：

- 只要求生成完整产业链研究报告或产业全景图谱。
- 只要求从上下游或集团关系中找新客户、拓客、扩线索。
- 只要求分析行业趋势、政策和竞争格局：应使用行业分析 Skill。
- 只要求分析公开合作、供应商占位、竞品占位、招投标和内部历史接触：应使用合作历史 Skill。
- 要求输出触达路径、销售话术、跟进节奏、作战计划或资源投入决策。

## Inputs

| 输入 | 作用 | 必填 |
|:---|:---|:---|
| 目标客户名称 | 确定产业链分析对象 | 是 |
| 用户角色 | 判断输出重点 | 否，默认销售 |
| 用户业务场景 | 判断输出偏向会前准备、客户经营、售前准备、续费、签约风控等 | 否 |
| 关注方向 | 上游、下游、渠道、生态、集团/资本、关键依赖中的某几类 | 否，默认全覆盖 |
| 发问方/卖方画像 | 判断哪些关系与发问方业务相关 | 运行时应尽量获取 |
| CRM 客户记录 | 锚定客户主体、内部覆盖状态、组织复杂度和内部样本 | 有权限时应获取 |
| 企业情报数据 | 工商、股权、分支、对外投资、融资、官网、年报、新闻、公告等 | 有可用工具时应获取 |
| 行业模板或行业背景 | 辅助判断客户链位、价值流向和上下游关系 | 需要时应获取 |

## Scope

本 Skill 负责：

- 锚定目标客户主体。
- 判断目标客户在产业链中的位置和价值角色。
- 识别上下游、渠道、生态、集团/资本和关键依赖关系。
- 解释这些关系对客户经营、需求、风险和相关情报信号的影响。
- 独立工作时输出完整产业链分析结果。
- 被主报告 Skill 编排调用时输出产业链摘要、判断和证据。

本 Skill 不负责：

- 输出产业链拓客方案、上下游新客清单或关系扩线方案。
- 输出二跳拓展、候选池、查重、线索创建、挂接客户或 CRM 写入。
- 输出 P0/P1/P2 机会定档、优先级排序或销售动作建议。
- 输出触达路径、销售话术、跟进节奏、作战计划。
- 自动写 CRM、建线索、建商机或修改字段。

## Output

本 Skill 有两种输出模式。

### 1. 独立调用模式

当用户直接要求做产业链分析时，默认交付方式为：先输出文字业务概要结论，同时交付一份 HTML 产业链分析结果作为正式完整结果。若用户未明确要求完整 Markdown/文字长文，不强制再生成整份 Markdown 报告。

独立输出前，必须先按 `references/schemas/standalone-report-data-model.md` 形成同构结构化数据，再按 `references/output-contract.md` 渲染文字结果；需要 HTML 时，再按 `references/html-report-template.md` 渲染。

生成 HTML 前必须已经读取 `references/html-report-template.md`。如果本轮没有读取该文件，不得生成正式 HTML 文件，不得宣称 HTML 自检通过；应先读取模板后再继续。

独立输出通常包含：

1. 产业链情报结论
2. 客户产业链位置
3. 上游、下游、渠道与生态关系
4. 集团/资本关系
5. 关键依赖与业务含义
6. 与发问方业务相关的产业链信号
7. 待核实事项
8. 证据来源

### 2. 编排调用模式

当被主报告 Skill 编排调用时，不输出完整产业链分析结果，只返回：

- 客户产业链位置
- 上游、下游、渠道和生态关系摘要
- 集团/资本关系摘要
- 关键依赖
- 对客户经营、需求、风险和相关信号的影响
- 关键证据和待核实事项

编排调用模式必须按 `references/schemas/insight-data-model.md` 返回结构化字段，供主报告写入 `topicInsights.chain` 和 `chainContext`。

编排调用模式不能只读取本 `SKILL.md` 后直接返回结论。至少必须读取并执行 `references/00-workflow.md`，读取 `references/output-contract.md`、`references/enterprise-cli-map.md` 和 `references/schemas/insight-data-model.md`，并按链位判断需要读取 `references/chain-structure.md`、`references/chain-position.md`、`references/relations.md` 和 `references/external-data-rules.md`。无法完成时必须在返回结构中说明降级原因，不能把“主报告已有数据”当作跳过 workflow 的理由。

独立输出和编排调用输出必须消费同一组事实和证据，不能出现口径不一致。

输出要求：

- 只输出与目标客户相关的产业链内容。
- 每段都要解释“这对这个客户意味着什么”。
- 没有获取到的信息不强行输出。
- 不在开头固定输出证据缺口或待核实事项。
- 不展示卖方画像原文。
- 不输出触达动作、销售话术、跟进计划或作战方案。
- 重要判断应有证据来源支撑。
- 模型推断必须与事实分开表达。
- HTML 结果不得新增文字版没有依据的事实。

## Core Rules

### 1. 先锚定客户主体，再判断产业链关系

优先确认目标客户主体，再统一使用工商全称、主体身份和公开业务信息做关系判断。主体未确认时，不输出完整产业链结论。

### 2. 先定产业链位置，再展开关系

先判断客户位于上游、中游、下游、平台、渠道、服务商或集成商中的什么位置，再分析上下游、渠道、生态和集团关系。不要在链位未确认时直接堆关系。

### 3. 产业链分析必须落到客户影响

只罗列关系对象而不解释业务含义，视为无效输出。每条关系都应说明其对客户经营、需求、风险或相关情报信号的影响。

### 4. 区分事实、推断、待核实

- `事实`：有明确来源、可回链。
- `推断`：基于经营范围、公开业务描述、行业结构或弱信号推理，必须标注。
- `待核实`：主体不清、关系证据不足、时间口径过旧或来源冲突。

没有证据不进结论，只进待核实。

### 5. 集团/资本关系只是辅助维度，不自动等于产业链主关系

集团/股权/资本关系可以解释控制、区域覆盖、采购归口和组织复杂度，但不能自动等同于上下游供应链关系。只有有明确证据时，才能作为产业链主关系表达。

### 6. 卖方画像只参与推理，不作为正文展示

发问方可能来自任意 B2B 行业。卖方画像只用于判断哪些链路关系与发问方业务相关；报告正文不能直接展示卖方公司介绍、产品清单、能力说明或销售卖点。

### 7. 不输出动作类方案

本 Skill 可以输出关系信号和业务解释，但不输出拓客、触达路径、找谁推进、销售话术、跟进节奏、作战计划或资源投入决策。

## Workflow

1. **识别用户意图和范围**
   - 判断用户关注的是客户产业链位置、上下游、渠道、生态、集团/资本还是关键依赖。
   - 如果无法判断，默认全覆盖。

2. **锚定客户主体**
   - 确认客户工商主体和公开业务身份。
   - 必要时结合 CRM 记录和企业基础信息统一主体口径。
   - 主体不清时，要求确认或明确降级。

3. **识别用户角色和场景**
   - 判断用户是销售、销售管理者、售前、客户成功、风控/签约，还是其他角色。
   - 如果无法判断，默认按销售视角输出。

4. **读取卖方画像**
   - 优先读取已验证的卖方画像或上下文。
   - 配置不足时，按 `business-context.md` 降级。
   - 用于判断哪些链路关系与发问方业务相关。

5. **判断产业链结构和客户位置**
   - 结合行业模板、公开业务描述、主营业务、目标客户和价值流向，判断产业链结构。
   - 判断客户在产业链中的位置、价值角色和核心链路。

6. **收集关系证据**
   - 收集上下游、渠道、生态、集团/资本、融资和关键依赖相关资料。
   - 收集 CRM 中与该客户链路结构、组织复杂度和内部覆盖相关的内部证据。
   - 证据不足时，明确标注缺口，不编造关系。

7. **形成关系判断和业务含义**
   - 区分事实、推断和待核实。
   - 对每类关系解释业务含义和对客户的影响。
   - 输出与发问方业务相关的客户侧产业链信号。

8. **生成结果**
   - 独立调用时按 `output-contract.md` 组织完整输出。
   - 编排调用时，只输出结构化摘要、判断和证据。
   - 根据实际获取到的信息动态裁剪内容。

9. **自检**
   - 按 `quality-checklist.md` 内部检查。
   - 自检结果不得作为正文输出。
