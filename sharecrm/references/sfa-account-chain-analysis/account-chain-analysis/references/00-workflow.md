# 客户产业链分析执行流程

本文是 `account-chain-analysis` 的主流程 reference。主 `SKILL.md` 负责入口，本文件负责执行顺序、独立/编排调用两种输出模式和降级规则。

## 阶段顺序

```text
用户输入客户 / 产业链问题
  ↓
A. 客户主体锚定
  ↓
B. 识别用户角色和场景
  ↓
C. 卖方画像读取
  ↓
D. 产业链结构判断
  ↓
E. 客户产业链位置判断
  ↓
F. 外部关系证据采集
  ↓
G. CRM 内部链路线索采集
  ↓
H. 关键依赖与业务含义映射
  ↓
I. 形成数据模型并生成结果
  ↓
J. 质量自检
```

## A. 客户主体锚定

执行要求：

1. 先确认客户主体，并抽取简称、品牌名、产品名、股票简称、城市、行业/业务关键词等主体辅助锚点。
2. 用户输入不是完整工商名称时，先按 `enterprise-cli-map.md` 调用 `sharecrm intelligence company search` 做一次结构化候选召回；候选可解释用户输入后，再进入企业批量取数，不先进入 web search。
3. 高置信候选可自动选中；多家候选都可能匹配、集团/子公司/分公司混杂或辅助锚点冲突时，返回前 3-5 个候选让用户确认。
4. 主体确认后统一使用工商全称，并用 `sharecrm intelligence company conc` 的批量结果锚定主体、业务、股东、投资、分支、融资、竞品和资质信息。
5. 主体未确认时，不输出完整产业链结论。

## B. 识别用户角色和场景

执行要求：

1. 判断用户是销售、销售管理者、售前、客户成功、风控/签约还是其他角色。
2. 默认按销售视角输出。
3. 角色只影响表达重点，不改变事实口径。

## C. 卖方画像读取

目标是让产业链分析具备发问方语境，但不把卖方画像展示在结果中。

执行要求：

1. 优先按 `business-context.md` 中的已验证配置 CLI 读取 `service_models`。
2. 配置不足时，按 `business-context.md` 使用用户明确上下文、CRM 产品/服务对象摘要、近 12-24 个月成交摘要降级。
3. 卖方画像缺失时仍可输出链路事实，但不做强相关性判断。

## D. 产业链结构判断

执行要求：

1. 结合行业模板、公开业务描述和主营业务判断产业链结构。
2. 先解释价值流向，再进入关系层。
3. 结构证据不足时，标注“结构信息有限”，只输出已确认部分。

## E. 客户产业链位置判断

执行要求：

1. 先判断客户是上游、中游、下游、平台、渠道、服务商、集成商中的哪类。
2. 再解释价值角色和业务位置。
3. 不把行业标签直接当作链位结论。

## F. 外部关系证据采集

关系证据包括：

- 上游关系
- 下游关系
- 渠道关系
- 生态关系
- 集团/资本关系
- 融资或同资方关系

执行要求：

1. 先读取 `enterprise-cli-map.md`，复用主报告已取得的 `company conc`、招投标、新闻、上市公告等结构化结果；字段不足时再按本专题 CLI map 补查。
2. 内部 `company / market / listed` CLI 已覆盖的数据域，不先 web search；CLI 不可用、返回空、字段不足、关系解释不够或需要权威公开原文补证时，才使用 web search / web fetch。
3. 每条关系都要记录来源。
4. 事实、推断、待核实必须分开。
5. 不能因为集团/资本关系存在就自动推导出供应链关系。
6. 上游无直接证据时，可以只输出上游环节类型，不强写具体企业名。
7. 企业情报和公开资料的优先级、时效和降级规则按 `external-data-rules.md` 执行。

## G. CRM 内部链路线索采集

执行要求：

1. 先识别对象，再读取对象描述，再决定查询内容。
2. 重点读取客户档案、联系人覆盖、商机、合同、订单、活动和必要的关联对象摘要。
3. 只提取对链位、渠道模式、集团化经营、区域覆盖、采购归口或交付复杂度有帮助的业务线索。
4. CRM 查询和写入规则按 `crm-context.md` 执行。

## H. 关键依赖与业务含义映射

执行要求：

1. 从关系中识别关键依赖。
2. 解释对客户经营、需求、风险和相关情报信号的影响。
3. 只输出客户侧信号，不输出拓客或销售执行动作。

## I. 形成数据模型并生成结果

### 独立调用模式

1. 先按 `references/schemas/standalone-report-data-model.md` 形成 `meta / crmContext / chainContext / sellerRelevantSignals / gaps / evidence`。
2. 再按 `output-contract.md` 输出完整产业链分析结果，包括：

- 产业链情报结论
- 客户产业链位置
- 上下游、渠道、生态关系
- 集团/资本关系
- 关键依赖与业务含义
- 与发问方业务相关的产业链信号
- 待核实事项
- 证据来源

### 编排调用模式

编排调用模式仍必须先完成本 workflow 的关键步骤；不得只读取 `SKILL.md` 后基于上游主报告数据直接生成结论。至少读取 `enterprise-cli-map.md`、`output-contract.md`、`schemas/insight-data-model.md`、`chain-structure.md`、`chain-position.md`、`relations.md` 和 `external-data-rules.md`。无法完整执行时，在结构化结果中写明降级原因。

按 `references/schemas/insight-data-model.md` 返回以下结构化结果：

- 客户产业链位置
- 上游、下游、渠道和生态关系摘要
- 集团/资本关系摘要
- 关键依赖
- 对客户经营、需求、风险和相关信号的影响
- 关键证据
- 待核实事项

独立调用和编排调用必须消费同一组事实与证据，不得出现口径漂移。

## J. 降级规则

| 情况 | 处理 |
|:---|:---|
| 客户主体多候选 | 中止，要求用户确认 |
| 客户主体未完全确认 | 允许输出部分链路判断，但必须标注主体待确认 |
| 产业链结构证据不足 | 输出已确认环节，并标注“结构信息有限” |
| 上游无直接证据 | 只输出上游环节或推断逻辑，不编造具体企业 |
| 集团/资本信息不足 | 对应维度进入待核实，不替代上下游判断 |
| 卖方画像缺失 | 输出客户事实，不做强相关性判断 |
| CRM 内部记录不足 | 不编造内部覆盖结论，只说明信息不足 |
