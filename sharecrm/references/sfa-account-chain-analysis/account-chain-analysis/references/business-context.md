# 卖方上下文规则

本文定义 `account-chain-analysis` 如何读取卖方画像，并把产业链关系与发问方业务相关性联系起来。

## 1. 卖方画像用途

卖方画像只用于内部推理，不用于正文展示。

用途包括：

- 判断哪些链路关系与发问方业务相关。
- 避免把与发问方无关的关系误写成重要信号。
- 帮助解释客户侧机会信号或风险信号。

## 2. 读取顺序

1. 优先读取已验证配置：`sharecrm sales get-config-by-key --data '{"key":"service_models"}'`。
2. 配置不足时，使用用户明确输入的卖方上下文。
3. 仍不足时，可用 CRM 产品/服务对象摘要、近 12-24 个月成交摘要做降级。
4. 三路都取不到时，标注卖方上下文缺失，但仍可输出客户产业链事实。

配置 CLI 返回结构通常为：

```json
{
  "value": "<配置值>"
}
```

`value` 只进入 `meta.sellerContext.summaryForInternalReasoning`，不得在正文展示原值。配置读取是顶层命令，不属于 `crm-cli-map.md`。

## 3. 禁止展示

正文中不得直接展示：

- 卖方公司介绍。
- 卖方产品清单。
- 卖方能力说明。
- 配置原值。
- 内部成交敏感明细。

## 4. 允许输出

只允许输出客户侧相关性判断，例如：

- 客户存在多区域、多渠道协同信号。
- 客户依赖某类上游资源，可能放大供应链协同或项目复杂度。
- 客户生态合作关系密集，可能影响系统集成或渠道协同判断。

## 5. 不假设卖方行业

不得默认发问方是 SaaS、CRM 或企业服务厂商。
