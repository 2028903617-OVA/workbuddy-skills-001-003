# CRM 内部上下文规则

本文定义 `account-chain-analysis` 如何使用 CRM 内部记录补充产业链分析。

## 1. 使用范围

CRM 内部记录主要用于：

- 锚定客户主体和内部客户身份。
- 理解客户是否存在集团化、区域化、渠道化或项目制经营线索。
- 补充联系人覆盖、商机、合同、订单、活动中的链路线索。
- 佐证内部已有的链位、交付复杂度、采购归口或合作模式理解。

CRM 不是产业链事实的唯一来源。没有 CRM 线索时，可以继续使用企业情报和公开资料，但不得伪装为“CRM 已确认”。

## 2. 查询原则

1. 先识别对象，再读取对象描述，再决定查询内容。
2. 默认从预设对象开始，不做自定义对象全量扫描。
3. 只有字段 label、类型、选项或关联关系能支撑链位、渠道、集团、区域、采购归口或交付模式判断时，才纳入查询。
4. CRM 内部记录只输出业务含义，不输出对象 API 名、字段 API 名、SQL 或内部记录 ID。

## 3. 默认读取顺序

### 3.1 客户对象

目标是确认 CRM 内是否已有该客户，以及哪些字段能支撑链路判断。

执行顺序：

1. 识别客户对象和候选记录。
2. 读取客户对象描述。
3. 用客户名称查询记录。
4. 在唯一命中后读取客户完整记录。

优先关注的业务含义包括：

- 客户分层、区域、集团归属、业务线或事业部字段。
- 渠道属性、客户类型、行业角色、服务模式、交付模式。
- 组织复杂度、区域经营、集团化经营、统一采购、项目制等可观察线索。

### 3.2 联系人和活动

联系人和活动主要用于理解：

- 是否覆盖总部、子公司、区域公司、渠道伙伴或项目团队。
- 是否存在采购、交付、实施、渠道、生态、集团或区域相关的内部沟通线索。

只有这些信息能支撑客户链路理解时才写入结果；普通跟进动作不作为正文重点。

### 3.3 商机、合同和订单

主要用于理解：

- 我方是否已按总部/区域/子公司/项目形态与其合作。
- 是直签、渠道合作、项目交付还是集团统采模式。
- 是否存在跨区域、多主体或复杂交付线索。

如果只能说明“内部有合作记录”，但不足以解释链路结构，则只写入内部覆盖摘要，不强下链位结论。

## 4. 可选关联对象

只有以下情况才探索关联对象或自定义对象：

- 用户明确提到某类内部关系对象。
- 预设对象不足以解释集团关系、区域结构、渠道模式或内部合作链路。
- 对象描述显示存在明显相关的关联对象，且字段含义清晰。

探索时仍必须先读对象描述，再决定是否查询。

## 5. 写入规则

- 客户业务摘要写入 `crmContext.account.businessSummary`。
- 链位、渠道模式、集团模式、采购归口等 CRM 线索写入 `crmContext.chainAnchor`。
- 联系人、商机、合同、订单、活动等内部样本只写业务摘要，写入 `crmContext.internalSamples`。
- 对独立报告正文有帮助的内部链路线索，可同步提炼到 `chainContext.businessImplications` 或 `chainContext.keyDependencies`。
- 与发问方业务相关的客户侧链路信号，可同步写入 `sellerRelevantSignals`。

## 6. 能力降级

| 情况 | 处理 |
|:---|:---|
| `describe` 不可用 | 标 `crmContext.objectDescribeDriven=false`，仅保留已确认记录摘要 |
| 客户名称无命中 | 标“客户未在 CRM 命中”，不伪装为 CRM 已确认 |
| 多候选 | 要求用户确认主体，不输出完整 CRM 锚定结论 |
| 只有弱线索字段 | 只写内部摘要，不提升为强链位判断 |
| 关联对象字段不清 | 不查询或仅记录为待核实 |
| 内部样本不足 | 不输出强内部覆盖结论，只说明信息不足 |

快速检索未命中不等于 CRM 未覆盖；必须完成对象识别、对象描述和记录查询后，才能说明当前 CRM 证据不足。

## 7. 边界

- 不输出对象 API 名。
- 不输出内部记录 ID。
- 不输出敏感字段原值。
- 不做 CRM 查重、去重和写入动作。
- 不把我方产品、报价或销售动作建议写进客户产业链结论。
