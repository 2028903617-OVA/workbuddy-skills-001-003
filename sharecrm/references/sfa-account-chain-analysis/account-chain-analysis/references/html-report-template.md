# HTML 客户产业链分析模板

本文定义 `account-chain-analysis` 的 HTML 输出形态。最终输出边界、数据消费顺序、章节裁剪和证据展示规则以 `output-contract.md` 为准；本模板只负责 HTML 展示结构。HTML 结果用于 CRM 页面展示、浏览器预览、打印或转 PDF，内容必须消费同一份 `schemas/standalone-report-data-model.md`，不得新增文字版结果没有依据的事实。

## 输出原则

- HTML 结果是正式展示形态，不是另一套分析逻辑。
- HTML 章节与 `output-contract.md` 的独立输出模板保持一致，并根据已有信息动态裁剪。
- 使用完整 HTML 文档结构和内联 CSS，避免外部依赖。
- 可使用少量内联 JavaScript 仅做目录锚点高亮和滚动跟随，不得异步加载、改写或补充报告内容。
- 样式应偏正式业务分析，适合 CRM iframe、富文本预览、浏览器打开和打印。
- 可打印、可转 PDF，避免依赖屏幕交互才能理解内容。
- 每个一级章节必须包含：开头概述结论、明细内容、末尾业务含义总结。

## 内容一致性

HTML 结果必须与文字版共享：

- 同一份目标客户主体。
- 同一份 `chainContext`、`sellerRelevantSignals`、`gaps` 和 `evidence`。
- 同一份 `meta.retrievalCoverage` 覆盖范围说明。
- 同一套事实 / 推断 / 待核实边界。
- 同一套脱敏和禁止展示规则。

HTML 可以用摘要块、表格和关系标签提升可读性，但不能额外编造客户链位、上下游关系、集团关系、关键依赖或卖方信息。

## 标签来源规则

- HTML 中的标签、徽章和 emoji 文案必须来自 `schemas/standalone-report-data-model.md` 中已有字段、`chainContext`、`sellerRelevantSignals`、`gaps` 或可回链 `evidence` 的事实/归纳。
- 链位、上游、下游、渠道、生态、集团/资本、关键依赖标签只能来自 `chainContext.chainPosition`、`chainContext.relations`、`chainContext.groupCapitalRelations`、`chainContext.keyDependencies` 等结构化字段；不得把行业标签直接当作链位结论。
- 荣誉/资质标签仅在主报告传入的资质字段、企业情报 CLI 结果或公开证据明确支持时展示；不得仅凭行业、规模或产业链位置生成“高新技术企业”“专精特新”“单项冠军”等标签。
- 风险、机会、壁垒和卖方相关信号标签可来自模型归纳，但必须能回链关系、依赖、CRM/公开证据或 `sellerRelevantSignals`，并在正文或图例保留归纳口径。

## 视觉表达自由度

不要把 HTML 结果限制成纯白卡片和普通表格。允许模型根据客户链位、关系复杂度和信息密度自由选择更有解释力的视觉表达：

- 封面可以使用品牌色、行业感配色、渐变背景、浅纹理或几何层次，并与正文 section 明显区分。可使用深色封面，但避免深色封面和深色全高目录同时占据过大面积。
- 封面可采用通栏背景 + 限宽内容，也可采用受控限宽封面；不固定标签数量、KPI 数量、摘要卡样式或副标题句式，只要求首屏有明确层次和视觉重点。
- 允许使用 emoji 或 Unicode 图标作为轻量视觉锚点，用于目录标题、链位结论、上下游卡片、关键依赖、风险/机会信号和图表标题。
- 当上游、客户能力、渠道、下游应用或生态伙伴之间存在方向性关系时，优先尝试 Sankey 或分层流向图表达“上游资源 -> 客户能力 -> 下游场景/客户类型”；关系不具备流向或证据不足时，再使用关系网络图、矩阵图、热力图、指标卡或关系卡片。
- 允许将强/中/弱、核心/一般/待核实、已证实/推断/待核实等模型归纳可视化，但必须标注归纳口径，不得伪装成原始统计值。

边界：不为视觉效果发明供应链关系、交易金额、合作强度、集团控制关系、CRM 记录或卖方信息。

## 图表尺寸与 Sankey 规则

- 不要让 Sankey、关系网络图和矩阵复用普通图表的 360-380px 高度。普通图表建议 `min-height: 360px`；Sankey、分层流向图和关系网络图桌面端建议 `min-height: 520px`，节点多于 12 个时提高到 `560-640px`；移动端不得低于 `400px`。
- 图表初始化前容器必须已有稳定宽高；窗口尺寸变化时调用 `chart.resize()`。
- Sankey 必须回答“上游资源/能力如何流向客户能力、渠道、下游场景或客户类型”。节点和边必须来自 `chainContext`、证据或明确标注的模型归纳；边的 `source`、`target` 必须能在节点中找到。
- 真实 `value` 只能来自金额、次数、数量、项目数等证据。只有定性关系时，可用统一布局值，但必须在图例或说明中标注“数值仅用于布局，不代表金额、份额或真实流量”。
- 方向关系不足、节点少于 3 层、边界不清或节点过多导致不可读时，不强行生成 Sankey，改用分层关系卡、链路表、矩阵或表格增强。
- 集团/股权/资本关系用于解释控制、区域覆盖、采购归口或组织复杂度时，默认优先用环形图/饼图展示股东分布；有持股比例按比例画，比例不完整时按“已披露股东/投资方构成”标注口径，股东较多或名称较长时合并小项并配明细表。不得把股权/资本关系自动等同于上下游供应链关系。

## 长文档目录规则

- HTML 结果应为实际渲染出的章节生成目录；没有渲染的章节不得出现在目录中。
- 桌面端默认优先使用封面下方的横向 sticky 目录，让桑基图、关系图和表格获得更宽展示空间；章节很多或标题很长时，可改用侧栏 sticky 目录。
- 横向目录宜使用浅色、半透明白或低饱和底色，当前章节用下划线、浅底或细色条高亮；避免默认使用深色全高侧栏。
- 移动端目录优先保持顶部 sticky 横向滚动；必要时可折叠成紧凑目录，不能遮挡正文。
- 目录项点击后跳转到对应 `section id`，正文应设置 `scroll-margin-top`。
- 目录高亮可使用少量内联 JavaScript 或 `IntersectionObserver`，脚本只允许控制目录状态。

## 样式规则

- 使用简洁正式但有视觉完成度的版式：清晰标题、紧凑段落、表格、摘要块、关系卡和高信息密度图表。
- 适合 CRM 工作台阅读，不做营销页、海报页或花哨动效。
- 使用 `max-width` 控制正文宽度，打印时移除多余阴影和背景。
- `上游、下游、渠道与生态关系` 优先尝试 Sankey、分层流向图或关系网络图；证据不足或类别过少时再使用表格/关系卡片。
- Sankey、关系网络图、分层流向图下方必须有对象明细表，至少覆盖关系对象、关系类型、业务含义和证据来源。
- 首屏应优先形成“封面 + 链位结论摘要 + 至少一个核心关系可视化 + 对应明细表”的组合，而不是只放关系长表。
- `集团 / 资本关系`、`关键依赖与业务含义` 和 `证据来源` 可用表格、矩阵或关系卡片展示，避免整页只有表格。
- `产业链情报结论` 和 `客户产业链位置` 优先用摘要块展示。
- 长报告使用悬浮目录 + 正文布局；默认横向 sticky 目录，侧栏目录作为长目录备选。
- 允许封面使用大面积背景色或渐变；正文避免无关装饰、复杂动画、外部字体和不可控外部图片。深色应作为重点视觉层，不应同时覆盖封面和整条目录栏。

## CRM 内嵌展示规则

- 默认宽度按 CRM 内容区适配，推荐正文容器 `min-width` 不超过 960px。
- 可使用侧边或顶部目录辅助长文档阅读，但正文必须在没有交互时仍可顺序阅读。
- 首屏优先展示 `产业链情报结论` 和 `客户产业链位置`，避免先看到大表格。
- `relations` 表格列数要受控；如果对象名或业务含义过长，优先换行而不是新增横向滚动。
- `集团 / 资本关系` 只展示与控制、采购归口、区域覆盖、组织复杂度相关的内容，不在 CRM 内嵌版扩写完整组织图。
- `meta.retrievalCoverage` 仅在覆盖度会影响结论理解时，以简短提示块展示。
- 每个一级章节开头应先给出概述结论，结尾补业务含义总结；不得只有图表和事实罗列。

## 章节渲染规则

- 章节只在对应数据存在时渲染。
- 无数据章节不输出占位文案，例如“暂无”“未获取到”“待核实”。
- `待核实事项` 只在确实存在、且会影响关键判断时渲染。
- `证据来源` 只展示业务可读来源名称、时间和支撑内容。
- 同一条证据可以被多个关系判断引用，但在证据区只出现一次。

## 脱敏和禁止展示

HTML 结果不得展示：

- 卖方画像原文、配置 CLI 原始返回值、卖方产品清单或能力说明。
- CLI 路径、SQL、对象 API 名、CRM 记录 ID 等技术追溯信息。
- 联系人手机号、邮箱、身份证等个人敏感信息。
- 内部备注、审批意见、成本、折扣、底价、合同条款、订单明细等敏感商业信息。
- 二跳拓展、候选池、查重、线索创建、挂接客户、P0/P1/P2 定档或销售动作建议。

## HTML 交付前自检

- 生成 HTML 结果后，交付前必须做一次展示完整性自检。
- 自检重点包括：目录项是否只对应实际渲染章节、锚点跳转是否有效、sticky 目录是否遮挡正文、表格/摘要块/关系卡是否完整。
- 如使用 ECharts、内联 SVG 或 JavaScript 图表，必须检查容器高度、数据字段引用、`series`、`legend`、节点/边关系和 fallback 内容是否一致。
- 不得保留空白图表容器、无效锚点、脚本报错后不可读的图表区域，或因目录层遮挡导致无法阅读的正文。
- 如图表无法稳定渲染，必须改为表格、列表、关系卡、矩阵或文字摘要表达同一数据。
- 每个一级章节是否都具备开头概述结论和末尾业务含义总结。
- 每个真实图表下方是否都有对应详细表格，而不是只有 fallback table。
- 自检只用于修复 HTML 呈现问题，不新增客户事实，不改变原有判断，不补写没有证据的关系。

## 打印和交付

- HTML 文档应可直接保存为 `.html` 文件。
- 文件名必须使用 `客户产业链分析-<企业简称或工商全称>-<YYYYMMDD>.html`。
- 打印样式应保证标题、表格和证据来源可读。
- 如果运行环境不能创建 HTML 文件/附件，默认仍返回完整 HTML 内容或说明生成失败原因；只有用户明确要求 Markdown/文字版时才改为 Markdown/文字交付。可以创建文件时，文件对象应作为内部产物或附件卡片返回，不在最终回复正文中打印原始文件对象 JSON、内部路径或 `{"type":"file","path":"..."}`。
