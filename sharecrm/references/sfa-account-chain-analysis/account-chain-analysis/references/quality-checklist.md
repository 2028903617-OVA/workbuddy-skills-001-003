# 客户产业链分析自检清单

本清单仅供内部验证，不得作为正文输出。

## 主体与位置

- [ ] 目标客户是否已唯一确认。
- [ ] 用户输入为简称、品牌名、产品名、股票简称或非完整工商名称时，是否先调用 `sharecrm intelligence company search` 做结构化候选召回，而不是先进入 web search。
- [ ] `company search` 返回多候选或主体冲突时，是否返回前 3-5 个候选让用户确认，没有直接套用名称相近主体。
- [ ] 是否先判断了产业链位置，再展开关系。
- [ ] 价值角色是否清晰，不空泛。

## 数据与证据

- [ ] 关键关系是否有证据来源。
- [ ] 企业情报 CLI 调用是否只使用 `enterprise-cli-map.md` 中允许的读命令。
- [ ] `sharecrm intelligence company conc` / `ip conc` 是否只传入本 skill 白名单内的 `actionTypes`，没有一次性传入全部支持类型。
- [ ] CRM CLI 调用是否只使用 `crm-cli-map.md` 中允许的读命令。
- [ ] 推断是否与事实区分。
- [ ] 独立调用模式是否先形成了 `standalone-report-data-model.md` 定义的数据模型。
- [ ] 企业情报和公开资料是否按 `external-data-rules.md` 的优先级、时效和降级规则使用。
- [ ] CRM 查询是否经过对象识别和对象描述，而不是直接假设字段。
- [ ] 集团 / 资本关系是否没有被误写成供应链关系。
- [ ] 上游证据不足时是否没有编造具体供应商。
- [ ] 上游、下游、渠道和生态关系有可靠证据时，是否优先输出具名代表企业或机构；无具名证据时是否标注推断/待核实。

## 内容与边界

- [ ] 是否解释了这对目标客户意味着什么。
- [ ] 是否没有写成拓客报告。
- [ ] 是否没有输出二跳拓展、查重、定档、线索创建。
- [ ] 是否没有输出触达路径、话术、跟进节奏、作战计划。
- [ ] 是否没有展示卖方画像原文。
- [ ] 是否没有为了模板完整输出“暂无”“未获取到”“待核实”。

## 输出模式

- [ ] 独立调用模式是否可完整输出。
- [ ] 编排调用模式是否只返回摘要、判断和证据。
- [ ] 编排调用模式是否读取并执行 `references/00-workflow.md`、`references/output-contract.md`、`references/schemas/insight-data-model.md` 和必要链位/关系判断文件，而不是只读 `SKILL.md` 后直接推断。

## HTML / CRM 展示

- [ ] 需要 HTML 时，本轮是否已经读取 `references/html-report-template.md`；如未读取，HTML 自检必须失败，不能生成正式 HTML 或宣称自检通过。
- [ ] `output-contract.md` 是否没有被误当作 HTML 模板替代品。
- [ ] 需要 HTML 时，是否按 `references/html-report-template.md` 生成，而不是临时拼接页面。
- [ ] CRM 内嵌版本是否优先展示产业链结论和客户链位，而不是先展开大表格。
- [ ] 独立调用交付是否默认采用“先输出文字业务概要结论 + HTML 完整报告”；如用户未明确要求完整 Markdown，是否没有重复输出整份 Markdown 长文。
- [ ] HTML 是否没有新增文字版结果没有依据的事实。
- [ ] HTML 是否没有展示卖方画像原文、CLI 路径、对象 API、SQL 或内部记录 ID。
- [ ] 长 HTML 是否包含实际渲染章节的目录、锚点和滚动高亮规则。
- [ ] 目录是否优先采用封面下方横向 sticky 样式；若使用深色侧栏，是否确有长目录或标题拥挤原因，且没有让大面积深色压过正文。
- [ ] HTML 是否没有被限制成纯白卡片和普通表格；封面、摘要区、关系卡和图表是否有正式报告的视觉完成度。
- [ ] 标签、徽章和 emoji 文案是否来自 `chainContext`、`sellerRelevantSignals`、`gaps`、结构化字段或证据；是否没有把行业标签直接当作链位结论。
- [ ] 荣誉/资质类标签是否只在主报告传入字段、企业情报 CLI 或公开证据明确支持时展示；是否没有凭行业、规模或产业链位置生成“高新技术企业”“专精特新”“单项冠军”等标签。
- [ ] 结构化信息充足时，是否允许使用 Sankey、关系网络图、分层链路图、矩阵图等更适合产业链判断的表达。
- [ ] 每个一级章节是否都具备开头概述结论和末尾业务含义总结。
- [ ] Sankey、分层流向图和关系网络图容器桌面端是否约 `520-640px`，没有复用普通 360-380px 高度；移动端是否仍有稳定可读高度。
- [ ] 每个真实图表下方是否都有对应详细表格，而不是只有 fallback table。
- [ ] 上游、客户能力、渠道、下游场景存在方向性关系时，是否优先尝试 Sankey 或分层流向图；不适合时是否说明并使用关系卡/表格降级。
- [ ] Sankey 节点和边是否来自 `chainContext`、证据或明确模型归纳；没有真实金额、次数、数量、项目数时，布局值是否标注不代表金额、份额或真实流量。
- [ ] 集团/股权/资本关系是否默认优先用环形图/饼图展示股东分布；比例不完整时是否明确“已披露股东/投资方构成”口径，股东较多或名称较长时是否合并小项并配明细表；是否没有把股权/资本关系误当作上下游供应链关系。
- [ ] 定性归纳型可视化是否标注了模型归纳口径，没有伪装成原始统计值。
- [ ] 如链位、关系强弱、关键依赖、Sankey 布局值或上下游场景分组来自模型归纳，是否在图例、表头、结论句或说明中明确保留归纳口径。
- [ ] 如项目关系、下游样本、公开合作或内部样本只消费首批结果，是否在表格、图例、章节结论或 coverage 说明中明确写明覆盖范围，没有把首批样本写成全量关系网络或整体产业链结构。
- [ ] CRM 快速检索未命中、仅返回模糊候选或主体未在 CRM 侧确认时，是否没有把内部覆盖、CRM 样本、渠道模式或组织复杂度写成已确认 CRM 事实。
- [ ] HTML 交付前是否完成展示完整性自检，并修复空白图表、无效锚点、目录遮挡、脚本配置错误或其他明显渲染异常；如图表无法稳定渲染，是否改为表格、列表、关系卡、矩阵或文字摘要表达同一数据。
- [ ] 最终用户正文是否没有打印原始文件对象 JSON、内部路径或 `{"type":"file","path":"..."}`。
- [ ] 关系表格是否控制列数，避免在 CRM 内嵌场景出现难以阅读的横向超宽表。
