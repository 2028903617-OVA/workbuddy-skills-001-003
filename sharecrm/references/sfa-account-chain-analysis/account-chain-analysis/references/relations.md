# 关系识别与证据规则

本文定义 `account-chain-analysis` 如何识别和表达关系。

## 1. 关系类型

本 Skill 默认处理以下关系：

- 上游关系
- 下游关系
- 渠道关系
- 生态关系
- 集团 / 资本关系
- 投资 / 融资关系

## 2. 每条关系必须回答的四件事

1. 关系对象是谁。
2. 关系性质是什么。
3. 证据来自哪里。
4. 对客户意味着什么。

## 3. 代表企业要求

产业链分析应优先输出具名代表企业，而不是只输出抽象环节。

- 上游、下游、渠道和生态关系只要有可靠证据，就应写出代表企业或机构名称。
- 关系对象必须带上角色，例如供应商、客户、渠道商、生态伙伴、项目合作方、终端行业客户。
- 如果只能判断上游或下游环节类型，但没有具名企业证据，应明确标注为推断或待核实，不算完整关系对象。
- 代表企业用于解释目标客户的链路结构，不生成拓客清单、候选池、CRM 查重或线索创建建议。

## 4. 事实、推断、待核实

- `事实`
  有明确来源，例如工商、公告、官网、年报、新闻原文。
- `推断`
  基于经营范围、行业结构、公开业务描述或弱信号推理。
- `待核实`
  证据不足、主体不清、时间过旧或来源冲突。

## 5. 集团 / 资本关系

集团、股权、分支、对外投资和融资关系可以用于解释：

- 谁控制客户。
- 区域覆盖和组织复杂度。
- 是否存在统一采购、区域经营或集团化经营。

但这些关系不能自动当作供应链关系表达。

## 6. 上游关系

上游关系优先用直接证据；没有直接证据时，可以：

- 只解释上游环节类型。
- 或标注为推断关系。

不能在证据不足时强写具体供应商企业名。

## 7. 下游、渠道和生态关系

下游、渠道和生态关系要区分：

- 客户卖给谁
- 通过谁卖
- 和谁协同

不要把合作伙伴、渠道商和终端客户混成一类关系。

## 8. 关系表达要求

关系表达至少包含：

- 关系类型
- 关系对象
- 对象角色
- 关系性质
- 业务含义
- 证据来源

## 9. 不允许的输出

- 基于关系直接生成拓客对象清单。
- 基于关系做 CRM 查重和机会定档。
- 把关系直接翻译成销售动作。
