# account-cooperation-history

## Goal

作为客户情报 Agent 中的专题 Skill，围绕目标客户生成面向客户理解的合作历史分析结果，重点回答：

1. 这个客户过去和哪些企业发生过合作。
2. 这些合作对象分别是什么角色，合作集中在哪些业务方向。
3. 客户是否存在长期供应商、竞品占位、强绑定生态或公开项目合作关系。
4. 招投标、采购、中标和参与项目等合作事件反映了客户什么样的业务偏好和合作模式。
5. CRM 内部是否已有历史接触、商机、合同、订单或失败记录。
6. 这些合作关系会给客户经营、需求、风险和相关情报信号带来什么影响。

本 Skill 的输出重点不是销售行动建议，而是把合作事实解释成对“这个客户”的业务理解和判断依据。

## Trigger

适合：

- 用户要求分析某个客户的合作历史、合作对象、供应商关系或公开合作动态。
- 用户说“这个客户以前和谁合作过”“这个客户近几年有什么合作动作”“有没有公开案例能看出它关注什么”“这个客户的供应商关系怎么样”“这个客户最近有没有招投标”“它的中标供应商有哪些”。
- 客户尽调报告需要补充合作历史、供应商关系、竞品占位、招投标和内部历史接触。
- 销售或销售管理者需要在会前理解客户合作网络和合作偏好。
- 售前需要理解客户是否已有相关项目、供应商体系和项目合作复杂度。
- 客户成功需要理解历史合作、成交、合同、订单和关系变化。
- 风控或签约角色需要理解公开合作、供应商集中度、履约背景和内部历史记录。

不适合：

- 只要求分析行业趋势、政策和竞争格局：应使用行业分析 Skill。
- 只要求分析产业链位置、上下游、渠道和生态关系：应使用产业链分析 Skill。
- 只要求做完整招投标策略、投标动作或采购窗口推进方案。
- 要求输出触达路径、销售话术、跟进节奏、作战计划或资源投入决策。

## Inputs

| 输入 | 作用 | 必填 |
|:---|:---|:---|
| 目标客户名称 | 确定合作历史分析对象 | 是 |
| 用户角色 | 判断输出重点 | 否，默认销售 |
| 用户业务场景 | 判断输出偏向会前准备、客户经营、售前准备、续费、签约风控等 | 否 |
| 时间范围 | 控制合作事件时间窗 | 否，默认近 3 年 |
| 关注方向 | 战略合作、项目合作、供应商合作、生态合作、客户案例、招投标、内部历史接触中的某几类 | 否，默认全覆盖 |
| 发问方/卖方画像 | 判断哪些合作关系与发问方业务相关 | 运行时应尽量获取 |
| CRM 客户记录 | 锚定客户主体、内部接触、商机、合同、订单、联系人和失败记录 | 有权限时应获取 |
| 企业情报数据 | 工商、新闻、公告、官网案例、上市公告、招投标、采购、中标等 | 有可用工具时应获取 |
| 行业模板或行业 route | 帮助识别合作事件重点、供应商类型和项目含义 | 需要时应获取 |

## Scope

本 Skill 负责：

- 锚定目标客户主体。
- 识别公开合作、供应商关系、竞品占位、招投标合作事件和公开案例。
- 识别 CRM 内部历史接触、商机、合同、订单和失败记录。
- 区分合作对象角色、合作类型、合作内容、业务领域和关系强度。
- 解释这些合作关系对客户经营、需求、风险和相关情报信号的影响。
- 独立工作时输出完整合作历史分析结果。
- 被主报告 Skill 编排调用时输出合作摘要、判断和证据。

本 Skill 不负责：

- 输出完整招投标策略、投标动作或投标推进方案。
- 输出触达路径、销售话术、跟进节奏、作战计划。
- 输出新建商机、线索、联系人或 CRM 动作建议。
- 输出最终机会推荐、资源投入决策或销售执行方案。
- 自动写 CRM、建线索、建商机或修改字段。

## Output

本 Skill 有两种输出模式。

### 1. 独立调用模式

当用户直接要求做合作历史分析时，默认交付方式为：先输出文字业务概要结论，同时交付一份 HTML 合作历史分析结果作为正式完整结果。若用户未明确要求完整 Markdown/文字长文，不强制再生成整份 Markdown 报告。

独立输出前，必须先按 `references/schemas/standalone-report-data-model.md` 形成同构结构化数据，再按 `references/output-contract.md` 渲染文字结果；需要 HTML 时，再按 `references/html-report-template.md` 渲染。

生成 HTML 前必须已经读取 `references/html-report-template.md`。如果本轮没有读取该文件，不得生成正式 HTML 文件，不得宣称 HTML 自检通过；应先读取模板后再继续。

独立输出通常包含：

1. 合作历史情报结论
2. 合作时间线
3. 合作对象分类分析
4. 合作业务领域分布
5. 供应商关系与合作偏好
6. CRM 内部历史接触摘要
7. 机会信号与壁垒信号
8. 待核实事项
9. 证据来源

### 2. 编排调用模式

当被主报告 Skill 编排调用时，不输出完整合作历史分析结果，只返回：

- 合作对象
- 合作类型
- 合作内容
- 业务领域
- 关系强度
- 供应商 / 竞品 / 项目合作摘要
- 内部历史接触摘要
- 对客户经营、需求、风险和相关信号的影响
- 关键证据和待核实事项

编排调用模式必须按 `references/schemas/insight-data-model.md` 返回结构化字段，供主报告写入 `topicInsights.cooperation`、`cooperationContext` 和 `cooperationHistory`。

编排调用模式不能只读取本 `SKILL.md` 后直接返回结论。至少必须读取并执行 `references/00-workflow.md`，读取 `references/output-contract.md`、`references/enterprise-cli-map.md` 和 `references/schemas/insight-data-model.md`，并按合作判断需要读取 `references/cooperation-types.md`、`references/bidding-merge-rules.md`、`references/external-sources.md` 和 `references/crm-context.md`。无法完成时必须在返回结构中说明降级原因，不能把“主报告已有数据”当作跳过 workflow 的理由。

独立输出和编排调用输出必须消费同一组事实和证据，不能出现口径不一致。

输出要求：

- 只输出与目标客户相关的合作历史内容。
- 每段都要解释“这对这个客户意味着什么”。
- 没有获取到的信息不强行输出。
- 不在开头固定输出证据缺口或待核实事项。
- 不展示卖方画像原文。
- 不输出触达动作、销售话术、跟进计划或作战方案。
- 重要判断应有证据来源支撑。
- 模型推断必须与事实分开表达。
- HTML 结果不得新增文字版没有依据的事实。

## Core Rules

### 1. 先锚定客户主体，再分析合作历史

优先确认目标客户主体，再统一使用工商全称、主体身份和内部客户记录口径做合作历史判断。主体未确认时，不输出完整合作历史结论。

### 2. 招投标能力并入合作历史，不单独输出招投标策略

招投标、采购、中标和项目参与事件是合作历史的重要证据域和合作事件类型，但本 Skill 不输出投标动作、投标策略或采购窗口推进方案。

### 3. 先区分合作对象角色，再解释合作关系

必须区分客户方、供应商、生态伙伴、项目方、集团/关联方、竞品/替代供应商和内部关系对象。只列企业名而不区分角色，视为无效输出。

### 4. 区分事实、推断、待核实

- `事实`：有明确来源、可回链。
- `推断`：基于公开资料、行业规律、合作模式或弱信号推理，必须标注。
- `待核实`：主体不清、供应商类型不明、资料过旧或来源冲突。

没有证据不进结论，只进待核实。

### 5. 供应商关系和竞品关系必须有证据

不能只凭供应商名称或合作名称臆测其是否为竞品、替代服务商或关键供应商。供应商类型不清时，必须标注待核实。

### 6. CRM 内部记录只解释业务含义，不暴露技术细节

内部历史接触、商机、合同、订单和失败记录进入输出时，只解释业务含义，不展示对象 API 名、内部记录 ID 或敏感字段原值。

### 7. 卖方画像只参与推理，不作为正文展示

发问方可能来自任意 B2B 行业。卖方画像只用于判断哪些合作事实与发问方业务相关；报告正文不能直接展示卖方公司介绍、产品清单、能力说明或销售卖点。

### 8. 不输出动作类方案

本 Skill 可以输出合作信号和业务解释，但不输出触达路径、找谁推进、销售话术、跟进节奏、作战计划、CRM 动作建议或资源投入决策。

## Workflow

1. **识别用户意图和范围**
   - 判断用户关注的是合作历史、供应商关系、公开案例、招投标、内部接触，还是其中某一类。
   - 如果无法判断，默认全覆盖。

2. **锚定客户主体**
   - 确认客户工商主体和内部客户身份。
   - 必要时结合 CRM 记录和企业基础信息统一主体口径。
   - 主体不清时，要求确认或明确降级。

3. **识别用户角色和场景**
   - 判断用户是销售、销售管理者、售前、客户成功、风控/签约，还是其他角色。
   - 如果无法判断，默认按销售视角输出。

4. **读取卖方画像**
   - 优先读取已验证的卖方画像或上下文。
   - 配置不足时，按 `business-context.md` 降级。
   - 用于判断哪些合作关系与发问方业务相关。

5. **收集公开合作事件**
   - 收集新闻、公告、官网案例、上市公告、招投标、采购、中标和项目参与等公开证据。
   - 证据不足时，明确标注缺口，不编造合作事件。

6. **收集 CRM 内部历史接触**
   - 收集联系人覆盖、历史商机、合同、订单、销售记录和失败记录摘要。
   - 只做业务含义解释，不暴露技术细节。

7. **合并合作事件并区分角色**
   - 对同一事件去重和归并。
   - 区分采购方 / 中标方 / 参与方以及其他合作对象角色。
   - 区分事实、推断和待核实。

8. **形成合作判断和业务含义**
   - 解释合作类型、供应商关系、竞品占位、内部历史接触和业务领域分布。
   - 输出与发问方业务相关的客户侧合作信号。

9. **生成结果**
   - 独立调用时按 `output-contract.md` 组织完整输出。
   - 编排调用时，只输出结构化摘要、判断和证据。
   - 根据实际获取到的信息动态裁剪内容。

10. **自检**
    - 按 `quality-checklist.md` 内部检查。
    - 自检结果不得作为正文输出。
