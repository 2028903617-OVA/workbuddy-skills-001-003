# 招投标并入合作历史规则

本文定义如何把招投标、采购、中标和项目参与事件并入合作历史主链路。

## 1. 并入原则

招投标不是独立 skill 输出，而是合作历史中的重要事件类型和证据域。

并入后主要回答：

- 客户近期在采购什么。
- 客户近期和哪些中标方、候选方或项目参与方发生公开关系。
- 这些事件说明客户偏好什么样的供应商、项目模式或合作方向。
- 公开项目实际涉及什么产品、服务、工程、设备、系统、运维或交付内容。

## 2. 角色区分

招投标相关事件必须区分：

- 采购方 / 招标方
- 中标方 / 候选人
- 项目参与方

不同角色对应不同的业务含义，但都只进入合作历史解释，不进入销售动作建议。

## 3. 事件合并

同一项目可能出现：

- 招标公告
- 中标公告
- 候选人公示
- 项目建设新闻

这些属于同一合作事件时，应归并表达，而不是重复列出。

合并后的事件必须尽量保留：

- 项目或采购名称。
- 采购方 / 招标方。
- 中标方 / 候选人 / 项目参与方。
- 采购或合作内容。
- 金额、预算、数量或建设规模，若来源披露。
- 公告时间和来源。

## 4. 预算与项目强度

可解释：

- 是否为连续采购或连续项目
- 是否为高金额或重大项目
- 是否反映客户建设方向、采购偏好或项目活跃度
- 是否反映客户近期关注的软件、设备、工程、服务、系统建设或供应商类型

但不输出：

- 投标策略
- 项目推进方案
- 直接机会等级

## 5. 供应商与竞品识别

中标方或候选方若需要解释为供应商、竞品或替代服务商，必须有证据支撑。

证据不足时：

- 标注供应商类型待核实
- 不得直接判为竞品强绑定

## 6. 主报告消费方式

招投标事件并入合作历史后，被主报告消费时只以以下形态出现：

- 合作时间线中的项目合作事件
- 供应商关系与合作偏好
- 机会信号与壁垒信号

## 7. Web 和官网补证

招投标 CLI 返回为空、字段不足、角色不清或缺少合作内容时，应像其他公开数据一样用 web search、官网案例、新闻、上市公告、政府采购网站或行业媒体补证。

补证只用于完善合作对象、角色、合作内容和业务含义；公开来源仍不足时，保留为待核实，不编造合作内容。
