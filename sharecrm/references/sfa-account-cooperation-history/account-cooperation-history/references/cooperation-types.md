# 合作类型与合作对象角色规则

本文定义 `account-cooperation-history` 如何识别合作事件类型和合作对象角色。

## 1. 合作类型

默认识别以下类型：

- 项目合作
- 战略合作
- 供应商合作
- 生态合作
- 客户案例
- 招投标 / 采购 / 中标 / 项目参与
- 内部历史接触

## 2. 合作对象角色

默认区分以下角色：

- 客户方
- 供应商
- 生态伙伴
- 项目方
- 集团 / 关联方
- 竞品 / 替代供应商
- 内部关系对象

## 3. 角色判断要求

- 能明确角色时必须明确。
- 角色无法确认时，标注待核实。
- 不把供应商、渠道、客户方、项目方混成一类。
- 合作事件必须尽量提炼“合作了什么 / 采购了什么 / 中标了什么 / 案例服务了什么”。不能只复制新闻标题、公告标题或招投标标题。
- 合作内容优先来自招投标 CLI、政府采购或招标公告、官网案例、企业新闻、上市公告、权威媒体和 web search 可追溯来源。

## 4. 关系强度

关系强度只分为业务可解释的强、中、弱，不做机会优先级定档。

可参考：

- 强：长期合作、连续合作、框架合作、集团级合作、重大项目合作
- 中：有明确项目合作或单次采购
- 弱：新闻提及、活动同台、无法确认实质合作

## 5. 不允许的输出

- 基于角色直接生成销售动作。
- 在角色未确认时强下结论。
- 只有合作对象名称、没有合作内容或证据来源时，不能写成确定合作关系。
