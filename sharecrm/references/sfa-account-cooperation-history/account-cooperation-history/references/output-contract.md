# 客户合作历史分析输出契约

本文定义 `account-cooperation-history` 的独立输出模板和编排调用时的消费契约。HTML 展示形态由 `references/html-report-template.md` 定义，本文件只约束输出结构、字段消费和裁剪边界。

独立输出前，必须先形成 `references/schemas/standalone-report-data-model.md` 中定义的结构化数据；本文件只负责把该数据模型映射成结构化章节，HTML 展示规则另见 `references/html-report-template.md`。

`output-contract.md` 不能替代 `html-report-template.md`。需要 HTML 时，必须先读取并遵守 `references/html-report-template.md`，再渲染 HTML；未读取 HTML 模板时不得生成正式 HTML，也不得宣称 HTML 自检通过。

独立调用专题 skill 时，默认交付方式为：先输出文字业务概要结论，同时交付一份 HTML 合作历史分析结果作为正式完整结果。若用户未明确要求完整 Markdown/文字长文，不强制再生成整份 Markdown 报告。

## 输出原则

- 只输出与目标客户相关的合作历史内容。
- 先解释合作结论，再展开合作事实。
- 每段都要落到“这对这个客户意味着什么”。
- 没有获取到的信息不强行输出。
- 不固定输出证据缺口或待核实事项。
- 不展示卖方画像原文。
- 不输出触达路径、销售话术、跟进节奏或作战计划。
- 事实、推断、待核实必须分开表达。

## 2. 独立输出写法要求

- `合作历史情报结论` 只放已获取到的核心信息。
- `合作时间线` 必须区分合作对象角色和合作类型。
- `合作时间线` 必须尽量提炼合作内容，优先回答“合作了什么 / 采购了什么 / 中标了什么”。招投标 CLI、官网案例、新闻、公告和 web search 来源都应围绕这个字段归并。
- `合作对象分类分析` 解释关系强度和业务含义，不只列名字。
- `供应商关系与合作偏好` 只基于证据表达，不凭名称臆测。
- `CRM 内部历史接触摘要` 只写业务摘要，不暴露技术细节。
- `机会信号与壁垒信号` 只解释客户侧信号，不输出动作建议。
- 每个一级章节都应按“开头概述结论 -> 明细内容 -> 末尾业务含义总结”组织。
- 每个真实图表下方都必须附对应详细表格，不得把详细表格仅作为 fallback 保留。
- “合作业务领域分布”在结构化信息充分时，可进一步扩展为“合作对象行业分布”和“合作对象区域 / 市场分布”；默认优先行业分布，其次区域 / 市场分布。
- 若只能确认业务领域，输出业务领域分布；若只能确认区域或市场，输出区域 / 市场分布；证据不足时不强行补行业或市场分布。
- 合作对象行业分布和区域 / 市场分布允许来自合作对象名称、合作内容、招投标项目、官网案例、公开资料和行业常识的谨慎归纳，但必须在图例、表头或结论中保留“模型归纳”或“证据口径”说明；不得伪装成已由单一原始字段直接返回的硬事实。
- 如合作时间线、合作对象分布、业务领域分布、行业分布或区域 / 市场分布只基于首批公开记录、首批招投标样本或首批内部样本，不得写成全量合作生态或整体市场覆盖；应在表格、图例、章节结论或 coverage 说明中明确写明覆盖范围。
- CRM 快速检索未命中、仅返回模糊候选、别名冲突未解决或内部对象描述未确认时，不得把 CRM 历史接触、历史成交、内部合作深度写成已确认内部事实；应明确降级或裁剪相关表达。
- 独立输出章节应优先消费 `cooperationContext`、`cooperationHistory`、`sellerRelevantSignals`、`gaps` 和 `evidence`，不要直接跳过数据模型即兴生成文本。
- 最终用户可见回复不得打印原始文件对象 JSON，例如 `{"type":"file","path":"..."}`；文件对象只能作为内部返回字段或由前端渲染为附件卡片。

## 3. 编排调用时的消费契约

编排调用模式必须按 `references/schemas/insight-data-model.md` 返回结构化结果。主报告只消费以下字段：

- `summary`
  合作历史摘要。
- `referenceReadStatus`
  专题 references 读取状态，写入主报告 `topicInsights.cooperation.referenceReadStatus`。
- `cooperationItems`
  合作对象、合作类型、合作内容和业务领域。
- `supplierAndCompetitorSignals`
  供应商、竞品、替代关系和合作偏好摘要。
- `internalHistory`
  内部历史接触摘要。
- `businessImplications`
  对客户经营、需求、风险和相关信号的影响。
- `evidence`
  关键证据列表。
- `gaps`
  待核实事项列表。

写入关系：

- 整体写入主报告 `topicInsights.cooperation`。
- `summary` 写入 `cooperationContext.summary`。
- `cooperationItems` 写入 `cooperationHistory[]`。
- `supplierAndCompetitorSignals` 写入 `cooperationContext.supplierAndCompetitorSignals`；与发问方相关的部分进入 `sellerRelevantSignals`。
- `internalHistory` 写入 `cooperationContext.internalHistory`，并按来源映射到 CRM 相关摘要。
- `businessImplications` 写入 `cooperationContext.businessImplications`，必要时同步到 `cooperationHistory[].businessImplication`。
- `evidence` 归并到主报告顶层 `evidence`，用 `evidenceRefs` 回链。

## 4. 不允许的输出

- 投标策略或采购推进方案。
- CRM 动作建议。
- 新建商机、线索、联系人或写入建议。
- 触达路径、销售话术、跟进节奏、作战计划。
- 只有标题或企业名、没有合作内容和角色依据的确定性合作结论。
