# 客户合作历史分析自检清单

本清单仅供内部验证，不得作为正文输出。

## 主体与事件

- [ ] 目标客户是否已唯一确认。
- [ ] 用户输入为简称、品牌名、产品名、股票简称或非完整工商名称时，是否先调用 `sharecrm intelligence company search` 做结构化候选召回，而不是先进入 web search。
- [ ] `company search` 返回多候选或主体冲突时，是否返回前 3-5 个候选让用户确认，没有直接套用名称相近主体。
- [ ] 是否先确认了合作事件，再解释合作关系。
- [ ] 招投标事件是否已并入合作历史主链路，而不是单独跑策略。

## 数据与证据

- [ ] 关键事件是否有证据来源。
- [ ] 企业情报 CLI 调用是否只使用 `enterprise-cli-map.md` 中允许的读命令。
- [ ] `sharecrm intelligence company conc` 是否只传入本 skill 白名单内的 `actionTypes`，没有一次性传入全部支持类型。
- [ ] CRM CLI 调用是否只使用 `crm-cli-map.md` 中允许的读命令。
- [ ] 推断是否与事实区分。
- [ ] 独立调用模式是否先形成了 `standalone-report-data-model.md` 定义的数据模型。
- [ ] 外部公开来源是否按 `external-sources.md` 的优先级、时效、去重和降级规则使用。
- [ ] CRM 查询是否经过对象识别和对象描述，而不是直接假设字段。
- [ ] 角色不清的合作对象是否已进入待核实。
- [ ] 供应商 / 竞品类型不清时是否没有强下结论。
- [ ] 招投标、官网、新闻、公告或 web 来源中的合作事件是否已提炼合作内容，而不是只复制标题。

## 内容与边界

- [ ] 是否解释了这对目标客户意味着什么。
- [ ] 是否没有写成投标策略报告。
- [ ] 是否没有输出 CRM 动作建议、线索建议或商机建议。
- [ ] 是否没有输出触达路径、话术、跟进节奏、作战计划。
- [ ] 是否没有展示卖方画像原文。
- [ ] 是否没有为了模板完整输出“暂无”“未获取到”“待核实”。

## 输出模式

- [ ] 独立调用模式是否可完整输出。
- [ ] 编排调用模式是否只返回摘要、判断和证据。
- [ ] 编排调用模式是否读取并执行 `references/00-workflow.md`、`references/output-contract.md`、`references/schemas/insight-data-model.md` 和必要合作事件/招投标/外部来源规则文件，而不是只读 `SKILL.md` 后直接推断。

## HTML / CRM 展示

- [ ] 需要 HTML 时，本轮是否已经读取 `references/html-report-template.md`；如未读取，HTML 自检必须失败，不能生成正式 HTML 或宣称自检通过。
- [ ] `output-contract.md` 是否没有被误当作 HTML 模板替代品。
- [ ] 需要 HTML 时，是否按 `references/html-report-template.md` 生成，而不是临时拼接页面。
- [ ] CRM 内嵌版本是否优先展示合作结论和关键时间线，而不是先展开整页长表。
- [ ] 独立调用交付是否默认采用“先输出文字业务概要结论 + HTML 完整报告”；如用户未明确要求完整 Markdown，是否没有重复输出整份 Markdown 长文。
- [ ] HTML 是否没有新增文字版结果没有依据的事实。
- [ ] HTML 是否没有展示卖方画像原文、CLI 路径、对象 API、SQL 或内部记录 ID。
- [ ] 长 HTML 是否包含实际渲染章节的目录、锚点和滚动高亮规则。
- [ ] 目录是否优先采用封面下方横向 sticky 样式；若使用深色侧栏，是否确有长目录或标题拥挤原因，且没有让大面积深色压过正文。
- [ ] HTML 是否没有被限制成纯白卡片和普通表格；封面、摘要区、时间线、关系卡和图表是否有正式报告的视觉完成度。
- [ ] 标签、徽章和 emoji 文案是否来自 `cooperationContext`、`cooperationHistory`、`sellerRelevantSignals`、`gaps`、结构化字段或证据；是否没有把未核实对象写成已合作供应商、竞品或既有客户关系。
- [ ] 荣誉/资质类标签是否只在主报告传入字段、企业情报 CLI 或公开证据明确支持时展示；是否没有凭行业、合作事件或客户规模生成“高新技术企业”“专精特新”“单项冠军”等标签。
- [ ] 结构化信息充足时，是否允许使用合作时间轴、客户类型分布图、招投标趋势组合图、关系网络图等更适合合作历史判断的表达。
- [ ] 每个一级章节是否都具备开头概述结论和末尾业务含义总结。
- [ ] 复杂图表容器是否按类型设置稳定尺寸；关系网络/Sankey 是否约 `500-620px`，热力图/矩阵是否约 `440-500px`，没有复用普通 360-380px 高度。
- [ ] 每个真实图表下方是否都有对应详细表格，而不是只有 fallback table。
- [ ] “合作业务领域分布”在结构化信息充分时，是否优先扩展到合作对象行业分布，其次合作对象区域 / 市场分布。
- [ ] 若未输出行业分布或区域 / 市场分布，是否因为证据不足、字段不清或样本不足，而不是遗漏。
- [ ] 若输出合作对象行业分布或区域 / 市场分布，是否明确保留了归纳口径或证据说明，没有把模型归纳伪装成单一原始字段直出事实。
- [ ] 合作历史是否优先使用时间线、趋势组合图、关系卡和分组矩阵；如使用 Sankey，是否确有清晰方向关系且没有编造交易流向、金额或合作强度。
- [ ] 如合作时间线、合作对象分布、业务领域分布、行业分布或区域 / 市场分布只消费首批公开记录、首批招投标样本或首批内部样本，是否在表格、图例、章节结论或 coverage 说明中明确写明覆盖范围，没有把首批样本写成全量合作生态或整体市场覆盖。
- [ ] CRM 快速检索未命中、仅返回模糊候选、别名冲突未解决或内部对象描述未确认时，是否没有把 CRM 历史接触、历史成交、内部合作深度写成已确认内部事实。
- [ ] 热力图/矩阵是否有清晰二维维度；维度不足、标签过长或证据不足时，是否降级为关系卡、分组表格或时间线。
- [ ] 合作对象类型、合作来源、业务领域等占比图是否只在真实构成清晰且类别少时使用环形图/饼图；样本不完整、类别多或需要排序比较时是否改用条形图、分组表格或关系卡。
- [ ] 定性归纳型可视化是否标注了模型归纳口径，没有伪装成原始统计值。
- [ ] HTML 交付前是否完成展示完整性自检，并修复空白图表、无效锚点、目录遮挡、脚本配置错误或其他明显渲染异常；如图表无法稳定渲染，是否改为表格、列表、时间线、关系卡、矩阵或文字摘要表达同一数据。
- [ ] 最终用户正文是否没有打印原始文件对象 JSON、内部路径或 `{"type":"file","path":"..."}`。
- [ ] 内部历史摘要是否只展示业务摘要和结果，没有泄露敏感字段原值。
