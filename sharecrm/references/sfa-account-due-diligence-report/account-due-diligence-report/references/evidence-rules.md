# 证据与事实表达规则

## 证据类型

| 类型 | 说明 |
|:---|:---|
| 结构化企业数据 | 工商、股权、风险、上市公司等企业数据 |
| CRM 记录 | 通过对象识别和对象描述查询到的客户、商机、合同/订单、活动、联系人、回款、服务、历史接触等 |
| 企业一手资料 | 官网、年报、公告、招股书、ESG 报告等 |
| 公开 web 来源 | web search 找到的官网、监管网站、法院、税务、交易所、新闻、招投标网站等 |
| 公开动态 | 新闻、招投标、招聘、政策、行业活动等 |
| 专题 Skill 结论 | 行业分析、产业链分析、合作历史的结构化摘要 |
| 模型推断 | 基于事实和业务规则形成的解释，不等同于事实 |

## 表达规则

- 事实必须能追溯来源。
- 推断必须标明是基于哪些事实形成。
- 不确定内容不能写成确定结论。
- 旧资料不得写成当前事实，应保留资料时间。
- 无法回链来源的重要判断不应作为核心结论。
- 内部 CLI 空、失败或字段不足时，应继续使用公开 web 来源补查；补查结果必须保留来源。
- 公开来源与内部 CLI 冲突时，优先解释时间口径、来源权威性和字段含义，不能简单合并为一个事实。
- 主体基础字段以工商/企业情报 CLI 的 `baseinfo` 为最高优先级；web、百科和新闻不能覆盖工商全称、统一社会信用代码、成立日期、法定代表人、登记状态和注册资本。
- 列表型 CLI 的 `total` 只表示接口记录总量，不等于有效数量、当前有效覆盖或全量结论；首批返回只可作为已返回样本，除非分页取全或接口明确 `isLastPage=true`。
- 空字段 item、角色不清或状态不可用的记录不能进入正式结论和图表；只能进入覆盖说明、缺口或待核实。
- 知识产权资产、知识产权出质和股权出质必须分开：`ipProfile` 写专利、软著、标准、商标、ICP备案；`risk conc:intellectualinfo` 写知识产权出质；`risk conc:pledgeinfo` 写股权出质。
- CRM 字段必须结合对象描述中的 label、类型、选项和关联对象解释；不得把字段 API 名直接当作业务含义。
- 最终报告的证据来源只展示业务可读的数据名称或公开来源名称，不展示 CLI 路径、对象 API 名、SQL、内部记录 ID 等技术追溯信息。
- 技术追溯信息只保留在中间数据或工作笔记中，用于排查和事实回溯，不进入报告正文。

## 缺失信息处理

- 模板中没有获取到的信息不强行输出。
- 不固定输出"证据缺口"或"待核实事项"。
- 用户明确要求但无法确认的点，可在对应位置简短说明。
- CLI 和公开 web 来源均未找到证据时，该项默认不输出。

## 证据来源格式

| 编号 | 来源名称 | 时间 | 支撑内容 |
|:---|:---|:---|:---|

来源名称示例：工商基础信息、股东信息、分支机构信息、司法风险信息、客户记录、商机记录、销售合同记录、企业官网、交易所公告、法院公告、监管公开信息。
