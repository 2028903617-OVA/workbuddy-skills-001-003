# 客户尽调报告模板

本文定义客户尽调报告的文字版默认结构。最终输出边界、数据消费顺序、章节裁剪和证据展示规则以 `output-contract.md` 为准；本模板只负责文字版章节组织。报告模板只消费 `schemas/report-data-model.md` 中已有内容，不补写缺失事实。

## 输出原则

- 章节按已获取信息动态裁剪。
- 没有获取到的信息不强行输出。
- 报告开头不固定输出证据缺口或待核实事项。
- 卖方画像不展示，只展示基于卖方画像推理出的客户侧情报信号。
- 不输出触达路径、话术、跟进计划或作战方案。
- 报告不是资料拼接，也不是销售行动方案。每个章节按"开头概述结论 -> 明细内容 -> 末尾业务含义总结"组织，详细写法仍保持"事实是什么 -> 说明客户什么情况 -> 对业务理解有什么影响"。
- 优先解释客户侧事实的业务含义，不堆叠工商字段、新闻标题、风险记录或 CRM 字段。
- 数据覆盖范围不作为固定章节输出；只有首批或定向查询范围会影响读者理解时，才在对应事实附近用业务语言说明。

禁止写法：

- 只罗列资料，不解释业务含义。
- 把卖方画像、产品清单、能力说明或销售卖点写进报告正文。
- 把情报信号直接写成触达动作、销售话术、跟进计划或推荐动作。
- 为了模板完整强行输出"暂无""未获取到""待核实"。

## 1. 客户概览摘要

用于报告开头，只放已获取到的核心信息。摘要采用四段式表达，缺失段落可省略，不固定补齐。

| 模块 | 内容 |
|:---|:---|
| 客户是谁 | 企业类型、所属行业、主体特征、规模、区域、集团/子公司属性 |
| 客户做什么 | 主营业务、产品/服务、目标客户、销售/交付模式 |
| 当前业务重点 | 近期业务方向、战略动作、扩张、转型、经营变化 |
| 与发问方相关的情报信号 | 机会信号、风险信号、合作关系信号、竞品/供应商信号 |

补充规则：

- 如果 CRM 没有精确命中或只返回模糊候选，不强制补“CRM 或合作状态”相关表达。
- 如果分页数据只消费首批样本，摘要中不得把样本覆盖误写成全量结论。

写法要求：

- `客户是谁`：说明主体身份、行业、企业性质、规模特征、区域和集团/上市/融资等关键背景。
- `客户做什么`：说明实际业务，不照抄经营范围；回答卖什么、卖给谁、怎么销售、怎么交付。
- `当前业务重点`：基于新闻、公告、官网、年报、招投标、CRM 记录等说明近期重点变化。
- `与发问方相关的情报信号`：只输出客户侧信号，不展示卖方画像原文，不输出具体销售动作。

示例：

```text
客户是谁：客户为一家总部位于 XX 的制造业企业，主营业务集中在 XX 领域，工商状态正常。其股权结构显示存在集团化背景，后续判断签约主体、采购决策和关联企业时，需要关注集团与子公司的关系。

客户做什么：客户主要面向 XX 行业客户提供 XX 产品和服务，业务模式具有项目制、区域交付和多渠道协同特征。这说明客户经营活动不只是单一产品销售，还涉及交付、渠道、服务和客户管理等复杂环节。

当前业务重点：近期公开信息显示客户在产能扩张、区域布局和新产品建设方面有连续动作，说明其经营重点可能从存量业务维护转向规模扩张和组织协同能力提升。

与发问方相关的情报信号：客户存在多区域扩张、渠道协同和项目交付复杂度提升的信号。若发问方画像中包含多区域服务、渠道管理、项目协同或供应链服务能力，该类变化可作为相关情报信号。该表述仅说明相关性，不输出具体销售动作。
```

## 3. 集团、股权与组织关系

可包含：

- 股东和实控人。
- 集团关系。
- 分支机构。
- 对外投资。
- 关联企业。
- 是否可能存在集团统一采购或区域独立经营。

输出重点：

- 是否影响签约主体。
- 是否影响客户归属。
- 是否存在关联客户拓展空间。
- 是否影响合作决策链。

章节写法要求：

- 开头先总结组织和股权结构最重要的判断。
- 图表或表格后补组织、控制、采购归口或区域经营的业务含义总结。

## 4. 主营业务与商业模式

| 维度 | 内容 |
|:---|:---|
| 主营业务 | 客户主要产品、服务、解决方案 |
| 目标客户 | 客户服务的行业、企业类型或终端用户 |
| 销售模式 | 直销、渠道、经销、招投标、项目制、大客户销售、平台交易 |
| 交付模式 | 产品销售、项目交付、订阅服务、运维服务、设备+服务等 |
| 经营复杂度 | 多业务线、多区域、多渠道、多项目、多角色、多系统协同 |

写法要求：

- 不复述经营范围，应解释客户主要产品或服务、下游客户类型、收入方式、销售方式和交付复杂度。
- 业务复杂度应落到客户经营理解，例如多区域、多渠道、多项目、多角色、多系统协同。

推荐表达：

```text
客户业务呈现"产品 + 项目交付 + 持续服务"的特征，说明其内部可能需要协调销售、交付、服务、渠道和财务等多个环节。该特征对判断客户组织复杂度和合作场景有参考价值。
```

章节写法要求：

- 开头先概括业务定位和商业模式判断。
- 末尾总结业务复杂度和合作含义。

## 4A. 研发与知识产权实力

当 `ipProfile` 有有效内容时输出本节；没有知识产权、研发或线上经营证据时动态裁剪，不写“暂无”。

| 维度 | 内容 | 业务含义 |
|:---|:---|:---|
| 专利 | 核心专利、近年专利、专利方向 | 判断技术积累和产品支撑 |
| 软件著作权 | 软件著作权名称、登记时间、产品相关性 | 判断软件化、数字化或平台能力 |
| 标准 | 参与起草标准、标准级别、发布时间 | 判断行业话语权或技术规范参与度 |
| 商标 | 主要商标、品牌或产品线相关商标 | 判断品牌和产品布局 |
| ICP 备案 | 官网、平台、应用或服务入口 | 判断线上经营和产品触点 |

写法要求：

- 不只罗列数量，应解释技术资产与主营业务、产品、应用场景之间的关系。
- 专利、软著、标准、商标和 ICP 与主营业务无法对应时，降低研发实力结论强度。
- 知识产权出质属于融资、担保或风险补充，不作为研发实力本身。

## 5. 行业环境与客户位置

只输出与目标客户相关的行业摘要：

- 行业基本情况摘要。
- 市场趋势摘要。
- 政策或监管变化。
- 行业主要玩家或竞争格局。
- 行业共性痛点。
- 目标客户在行业中的位置。

不输出完整行业市场报告。

章节写法要求：

- 开头给行业结论和客户行业位置判断。
- 末尾总结行业变化对客户的业务含义。

## 6. 产业链与生态关系

| 维度 | 内容 |
|:---|:---|
| 产业链位置 | 上游、中游、下游、平台、渠道、服务商、集成商等 |
| 上游关系 | 原材料、设备、技术、平台、供应商 |
| 下游关系 | 客户类型、销售对象、终端市场 |
| 渠道/生态 | 经销商、代理商、合作伙伴、协会、活动、平台 |
| 关键依赖 | 对哪些资源、客户、供应商或渠道依赖较强 |
| 业务含义 | 对客户经营和发问方判断的影响 |

章节写法要求：

- 开头给链位和关键关系结论。
- 末尾总结依赖、上下游、渠道或生态关系的业务含义。

## 7. 经营动态与业务重点

| 动态/信号 | 来源事实 | 业务解释 | 对判断的影响 |
|:---|:---|:---|:---|

可包含新闻公告、新产品/新业务、招投标/中标、融资/上市/财务变化、组织扩张、区域扩张、出海、战略合作等。

写法要求：

- 动态信息必须从"新闻/公告标题"转译成"客户变化"。
- 每条动态说明来源事实、反映的客户变化、对业务判断的影响。

推荐表达：

```text
客户近期发布新基地建设信息。该事实说明客户可能处于产能扩张或区域布局阶段，后续可能带来供应链、设备、交付、人员和管理协同需求。该动态对判断客户当前业务重点有价值。
```

章节写法要求：

- 开头概括当前业务重点。
- 末尾总结这些动态意味着客户处于什么阶段、对合作判断有什么影响。

## 8. 上市主体公开财务与经营摘要

仅在客户是上市主体、上市公司关联主体，或用户明确关注经营财务压力时输出。

可包含：

- 公开上市身份、股票代码和公告口径。
- 近年营收、利润、资产负债和现金流摘要。
- 财务变化反映的经营压力、预算弹性、履约能力或扩张阶段。

写法要求：

- 只解释公开财务事实对客户经营、预算、履约和风险判断的影响。
- 不输出证券投资建议、估值判断、股价判断或买卖建议。
- 不把上市主体财务直接套用于非同一签约主体；集团、子公司和上市主体口径必须分开表达。

推荐表达：

```text
公开财务数据显示，客户近年收入保持增长但现金流波动较大。该事实可作为判断客户扩张节奏、预算弹性和履约稳定性的背景信息；若签约主体并非上市主体本身，需要进一步区分上市公司口径和实际签约主体口径。
```

章节写法要求：

- 开头概括财务与经营的核心结论。
- 末尾总结预算、履约、扩张或风险含义。

## 9. 合作历史与供应商关系

| 时间 | 合作对象 | 合作类型 | 合作内容 | 业务领域 | 业务含义 |
|:---|:---|:---|:---|:---|:---|

重点判断：

- 是否存在长期供应商。
- 是否存在竞品占位。
- 是否存在战略合作绑定。
- 是否有历史接触、历史商机、历史成交、历史失败原因。
- 是否有可借鉴的类似客户或类似场景。

写法要求：

- 合作历史不能只列合作新闻，应说明合作对象类型、合作性质和关系含义。
- 供应商或竞品关系只能基于证据表达，不能凭名称臆测。

推荐表达：

```text
客户与 XX 供应商存在连续合作记录，说明该领域可能已有稳定服务商或供应商占位。该信息对判断进入壁垒、替换窗口和合作关系复杂度有参考价值，但不能直接推导为销售动作。
```

章节写法要求：

- 开头概括合作生态和供应商/竞品占位判断。
- 末尾总结进入壁垒、替换难度和合作窗口含义。

## 10. 风险与准入信息

| 风险类型 | 风险事实 | 业务影响 |
|:---|:---|:---|
| 经营异常 |  | 是否影响客户准入 |
| 被执行/失信 |  | 是否影响账期和回款 |
| 行政处罚 |  | 是否影响品牌和合规 |
| 司法诉讼 |  | 是否影响项目稳定性 |
| 税务/严重违法 |  | 是否需要谨慎签约 |
| 破产/清算 |  | 是否不宜投入 |

只输出已经获取到且有业务判断价值的风险信息。

写法要求：

- 风险信息不能只列记录数量，应解释风险性质、时间、状态和业务影响。
- 历史已结案风险、当前被执行、失信、破产、重大税务违法应区分表达。

推荐表达：

```text
客户存在历史诉讼记录，案件多为合同或知识产权相关，且多数已结案。该类风险更偏经营过程风险，不直接等同于持续经营异常；但如近两年出现新增高金额被执行、失信或破产信息，则会影响签约账期、回款预期和项目稳定性判断。
```

章节写法要求：

- 开头概括风险等级和准入判断。
- 末尾总结风险对签约、账期、回款或项目稳定性的影响。

| 机会信号 |  |  |  |
| 风险信号 |  |  |  |
| 合作关系信号 |  |  |  |
| 供应商/竞品信号 |  |  |  |

写法要求：

