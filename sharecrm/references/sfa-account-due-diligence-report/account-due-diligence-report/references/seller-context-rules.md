# 卖方画像与相关性判断规则

卖方画像用于内部推理，不作为报告主体展示。卖方画像来自 CRM 系统内已有配置，优先通过系统配置 CLI 获取；不得用公开资料或模型常识猜测发问方是谁、卖什么、服务哪些行业。

## 读取顺序

### 1. 系统配置 CLI

每次需要判断"与发问方业务相关的情报信号"时，先读取以下配置：

| 画像字段 | 配置 key | CLI | 用途 |
|:---|:---|:---|:---|
| 服务形态 | `service_models` | `sharecrm sales get-config-by-key --data '{"key":"service_models"}'` | 判断客户组织、交付、渠道、项目或运营特征是否匹配发问方服务方式 |

读取结果只进入 `sellerContext` 中间数据，不进入报告正文。

返回结构通常为：

```json
{
  "value": "<配置值>"
}
```

报告中不得直接展示 `value` 原值，只能用于判断客户侧事实是否与发问方服务形态相关。

### 2. 配置为空时的明确上下文

如果系统配置 CLI 返回空、不可用或字段明显不足，先使用用户输入或当前 CRM 页面上下文中明确给出的发问方信息。

补充读取只用于提高相关性判断质量；不得因此编造卖方公司介绍、产品能力或目标行业。

### 3. CRM 内部业务记录降级来源

如果 `service_models` 和明确上下文仍不足以判断发问方服务形态，可按 `crm-cli-map.md` 查询 CRM 内部产品/服务对象摘要和近 12-24 个月已成交合同/订单摘要，作为卖方画像的二级降级来源。

允许消费：

- 产品/服务对象中的产品线、产品分类、服务类型、有效状态等摘要字段。
- 已成交合同/订单中的成交产品或服务类型、服务形态、客户行业分布等聚合或摘要。
- 能帮助判断发问方过往服务形态的字段 label 和选项含义。

禁止消费或展示：

- 产品对象、订单、合同的原始明细。
- 客户名称、成交金额、折扣、成本、合同条款、审批意见等敏感信息。
- 将历史成交记录推断为当前战略、当前主推产品或确定销售方向。

CRM 降级来源只进入 `sellerContext.summaryForInternalReasoning`，用于判断客户侧事实是否相关，不进入报告正文。

### 4. 仍然缺失时的处理

卖方画像仍缺失时：

- 可输出客户事实。
- 可输出通用 B2B 语境下的谨慎解释。
- 不输出具体产品、方案、设备或服务匹配判断。
- 不在报告中固定输出"卖方上下文缺失"章节。
- 不默认卖方是 SaaS、CRM 或企业服务厂商。

## 禁止展示

报告中不得直接展示：

- 卖方公司介绍。
- 卖方产品清单。
- 卖方能力说明。
- 卖方销售卖点。
- 内部配置字段原值。
- 配置 CLI 原始返回值。
- 历史成交或合同中的敏感内部信息。

## 允许输出

只允许输出客户侧情报信号，例如：

- 客户的渠道扩张与发问方渠道管理类业务可能相关。
- 客户新建生产基地可能带来设备、供应链或项目协同相关关注点。
- 客户存在长期供应商，可能形成进入壁垒。
- 客户近期经营承压，可能影响签约账期或续费预算。

## 相关性判断方法

将客户事实与卖方画像做交叉判断：

- 客户组织复杂度、区域分布、交付模式、项目制特征是否与 `service_models` 相关。
- CRM 产品/服务和已成交摘要只能辅助推断发问方过往服务形态，不能替代配置或用户明确上下文。
- 客户风险、经营承压、供应商稳定性是否影响发问方业务判断。

表达时使用客户侧语言，避免把报告写成卖方产品介绍或销售推荐。

## 不假设卖方行业

不得默认卖方是 SaaS、CRM 或企业服务厂商。发问方可能来自制造业、设备商、咨询服务商、金融机构、物流企业、渠道商或其他 B2B 企业。

卖方画像缺失时：

- 可输出客户事实。
- 可输出与通用 B2B 判断相关的谨慎解释。
- 不输出具体产品/方案匹配判断。
