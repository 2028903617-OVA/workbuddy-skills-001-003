# account-industry-analysis

## Goal

作为客户情报 Agent 中的专题 Skill，围绕目标客户所处行业生成面向客户理解的行业分析结果，重点回答：

1. 这个客户所在行业当前处于什么状态。
2. 行业变化为什么会影响这个客户。
3. 这个客户在行业中处于什么位置。
4. 行业变化会给该客户带来哪些经营压力、需求变化、机会信号和风险信号。

本 Skill 的输出重点不是纯行业研究报告，而是把行业事实解释成对“这个客户”的业务理解和判断依据。

## Trigger

适合：

- 用户要求分析某个客户所在行业。
- 用户说“这个客户所在行业怎么样”“这个行业最近有什么变化”“行业政策会不会影响这个客户”“这个客户在行业里是什么位置”。
- 客户尽调报告需要补充行业环境、行业位置、行业外因影响。
- 销售或销售管理者需要在会前理解客户行业背景。
- 售前需要理解行业变化如何影响客户业务场景和系统相关信号。
- 客户成功需要理解行业环境是否影响客户经营、续费或扩容背景。
- 风控或签约角色需要判断行业环境是否放大客户经营压力或履约风险。

不适合：

- 只要求生成完整行业研究报告、宏观市场报告或静态/动态行业周报：应使用独立行业研究能力。
- 只要求分析客户上下游、渠道、生态和产业链位置：应使用产业链分析 Skill。
- 只要求分析公开合作、供应商、竞品占位、招投标和内部历史接触：应使用合作历史 Skill。
- 要求输出触达路径、销售话术、跟进节奏、作战计划或资源投入决策。

## Inputs

| 输入 | 作用 | 必填 |
|:---|:---|:---|
| 目标客户名称 | 确定行业分析对象 | 是 |
| 用户角色 | 判断输出重点 | 否，默认销售 |
| 用户业务场景 | 判断输出偏向会前准备、客户经营、售前准备、续费、签约风控等 | 否 |
| 区域或区域范围 | 行业判断时限定区域口径 | 否 |
| 时间范围 | 控制趋势、政策、事件时间窗 | 否 |
| 关注方向 | 增长、监管、竞争、周期、经营压力中的某几维 | 否，默认全覆盖 |
| 发问方/卖方画像 | 判断哪些行业变化与发问方业务相关 | 运行时应尽量获取 |
| CRM 客户记录 | 锚定客户行业、赛道、区域、客户分层、内部样本和历史记录 | 有权限时应获取 |
| 外部行业资料 | 行业报告、政策法规、监管通报、官网、年报、新闻、榜单等 | 有可用工具时应获取 |

## Scope

本 Skill 负责：

- 锚定目标客户所属行业、赛道和区域。
- 识别行业阶段、趋势变化、政策影响、竞争格局和共性压力。
- 判断目标客户在行业中的位置。
- 解释行业变化对该客户经营、需求、风险和相关情报信号的影响。
- 独立工作时输出完整行业分析结果。
- 被主报告 Skill 编排调用时输出行业摘要、判断和证据。

本 Skill 不负责：

- 输出完整行业研究报告、宏观市场综述、市场容量测算。
- 输出产业链拓客、上下游找新客户或生态拓展方案。
- 输出触达路径、销售话术、跟进节奏、作战计划。
- 输出最终商机推荐、资源投入决策或销售执行方案。
- 自动写 CRM、建线索、建商机或修改字段。

## Output

本 Skill 有两种输出模式。

### 1. 独立调用模式

当用户直接要求做行业分析时，默认交付方式为：先输出文字业务概要结论，同时交付一份 HTML 行业分析结果作为正式完整结果。若用户未明确要求完整 Markdown/文字长文，不强制再生成整份 Markdown 报告。

独立调用模式必须先形成 `references/schemas/standalone-report-data-model.md` 定义的数据模型，再按 `references/output-contract.md` 渲染文字结果；需要 HTML 时，再按 `references/html-report-template.md` 渲染。模板不得直接从原始 CLI 输出、网页文本或 CRM 原始记录临时拼接正文。

生成 HTML 前必须已经读取 `references/html-report-template.md`。如果本轮没有读取该文件，不得生成正式 HTML 文件，不得宣称 HTML 自检通过；应先读取模板后再继续。

独立输出通常包含：

1. 行业情报结论
2. 客户行业位置
3. 行业变化对客户的影响
4. 行业背景摘要
5. 与发问方业务相关的行业信号
6. 待核实事项
7. 证据来源

### 2. 编排调用模式

当被主报告 Skill 编排调用时，不输出完整行业分析结果，只返回：

- 行业基本情况摘要
- 行业趋势和政策
- 主要玩家或竞争格局
- 行业共性痛点
- 客户在行业中的位置
- 对客户经营、需求、风险和相关信号的影响
- 关键证据和待核实事项

编排调用模式必须按 `references/schemas/insight-data-model.md` 返回结构化字段，供主报告写入 `topicInsights.industry` 和 `industryContext`。

编排调用模式不能只读取本 `SKILL.md` 后直接返回结论。至少必须读取并执行 `references/00-workflow.md`，读取 `references/output-contract.md`、`references/enterprise-cli-map.md` 和 `references/schemas/insight-data-model.md`，并按行业判断需要读取 `references/industry-judgment-criteria.md`、`references/industry-templates/_router.md` 及命中的行业模板。无法完成时必须在返回结构中说明降级原因，不能把“主报告已有数据”当作跳过 workflow 的理由。

独立输出和编排调用输出必须消费同一组事实和证据，不能出现口径不一致。

输出要求：

- 只输出与目标客户相关的行业内容。
- 每段都要解释“这对这个客户意味着什么”。
- 没有获取到的信息不强行输出。
- 不在开头固定输出证据缺口或待核实事项。
- 不展示卖方画像原文。
- 不输出触达动作、销售话术、跟进计划或作战方案。
- 重要判断应有证据来源支撑。
- 模型推断必须与事实分开表达。
- HTML 结果不得新增文字版没有依据的事实。

## Core Rules

### 1. 先锚定客户行业，再做行业分析

优先从 CRM 客户对象锚定行业、赛道和区域。不要凭用户随口给的行业名直接展开分析。CRM 行业字段不清晰时，先读对象描述和字段 label，再解释业务含义。

### 2. 先看客户，再看行业

同一行业标签下，不同经营模式、规模、上下游位置和区域的客户，分析重点不同。行业分析必须结合客户自身业务、规模、区域和经营模式解释，不直接把行业共性当作客户事实。

### 3. 行业分析必须落到客户影响

只描述行业现状而不解释客户影响，视为无效输出。每条结论都应落到客户经营、需求、风险或相关情报信号。

### 4. 卖方画像只参与推理，不作为正文展示

发问方可能来自任意 B2B 行业。卖方画像只用于判断哪些行业变化与发问方业务相关；报告正文不能直接展示卖方公司介绍、产品清单、能力说明或销售卖点。

### 5. 区分事实、推断、待核实

- `事实`：有明确来源、可回链。
- `推断`：基于行业规律、结构化线索或弱信号推理，必须标注。
- `待核实`：行业未确认、样本不足、资料过旧、来源冲突或证据不足。

没有证据不进结论，只进待核实。

### 6. 先定行业阶段，再展开五维判断

先判断行业阶段，再按增长、监管、竞争、周期、经营压力五维展开。行业阶段只取一个主阶段，不组合输出。

### 7. 命中行业模板时必须用个性化判断点

命中已建模板的行业时，必须套用对应模板的判断点、趋势观察点、典型事件和客户位置判断要点；未命中模板时走通用口径，并标注“该行业未建个性化模板”。

### 8. 不输出动作类方案

本 Skill 可以输出行业信号和业务解释，但不输出触达路径、具体找谁、销售话术、跟进节奏、作战计划或资源投入决策。

## Workflow

1. **识别用户意图和范围**
   - 判断用户给的是客户、行业，还是客户 + 行业。
   - 判断关注维度、区域范围和时间范围。
   - 如果无法判断，默认按单客户、全维覆盖输出。

2. **锚定客户行业**
   - 优先从 CRM 客户对象锚定行业、赛道和区域。
   - 先识别对象，再读取对象描述，再查询记录。
   - 行业未锚定时，标注“行业未经 CRM 确认”。

3. **识别用户角色和场景**
   - 判断用户是销售、销售管理者、售前、客户成功、风控/签约，还是其他角色。
   - 如果无法判断，默认按销售视角输出。

4. **读取卖方画像**
   - 优先读取已验证的卖方画像或上下文。
   - 配置不足时，按 `business-context.md` 降级。
   - 用于判断哪些行业变化与发问方业务相关。

5. **route 行业模板**
   - 按客户行业、经营模式、规模、上下游位置和区域做多维识别。
   - 命中模板则读取对应行业模板。
   - 未命中模板则走通用口径并标注降级。

6. **收集外部行业资料和内部样本**
   - 收集行业报告、政策法规、监管通报、新闻、官网、年报和榜单等资料。
   - 查询 CRM 中与该客户、同类行业客户、成交样本或历史记录相关的内部证据。
   - 证据不足时，明确标注缺口，不编造内部样本。

7. **判断行业阶段和五维影响**
   - 先判断行业阶段。
   - 再按增长、监管、竞争、周期、经营压力五维分析。
   - 每维都翻译成对该客户的影响。

8. **形成客户行业位置和相关信号**
   - 判断客户在行业中的位置、类型、角色或分层。
   - 输出与发问方业务相关的客户侧行业信号。
   - 不输出具体销售动作。

9. **生成结果**
   - 独立调用时按 `output-contract.md` 组织完整输出。
   - 编排调用时，只输出结构化摘要、判断和证据。
   - 根据实际获取到的信息动态裁剪内容。

10. **自检**
    - 按 `quality-checklist.md` 内部检查。
    - 自检结果不得作为正文输出。
