# 客户行业分析执行流程

本文是 `account-industry-analysis` 的主流程 reference。主 `SKILL.md` 负责入口，本文件负责执行顺序、独立/编排调用两种输出模式和降级规则。

## 阶段顺序

```text
用户输入客户 / 行业问题
  ↓
A. 客户主体与行业锚定
  ↓
B. 识别用户角色和场景
  ↓
C. 卖方画像读取
  ↓
D. 行业模板 route
  ↓
E. 外部行业资料与内部样本采集
  ↓
F. 行业阶段与五维判断
  ↓
G. 客户行业位置与客户影响映射
  ↓
H. 独立输出 or 编排调用输出
  ↓
I. 质量自检
```

## A. 客户主体与行业锚定

执行要求：

1. 先识别客户对象，并抽取简称、品牌名、产品名、股票简称、城市、行业/业务关键词等主体辅助锚点。
2. 用户输入不是完整工商名称时，先按 `enterprise-cli-map.md` 调用 `sharecrm intelligence company search` 做一次结构化候选召回；候选可解释用户输入后，再进入企业批量取数，不先进入 web search。
3. 高置信候选可自动选中；多家候选都可能匹配、集团/子公司/分公司混杂或辅助锚点冲突时，返回前 3-5 个候选让用户确认。
4. 主体确认后统一使用工商全称，优先用 `sharecrm intelligence company conc` 的批量结果锚定行业、赛道、业务、竞品、融资和招聘信号。
5. 再读取 CRM 对象描述和客户记录，确认行业、赛道、区域和分层等相关字段。
6. 若行业字段缺失或无法确认，标注“行业未经 CRM 确认”，并允许降级继续。

## B. 识别用户角色和场景

执行要求：

1. 判断用户是销售、销售管理者、售前、客户成功、风控/签约还是其他角色。
2. 默认按销售视角输出。
3. 角色只影响表达重点，不改变事实口径。

## C. 卖方画像读取

目标是让行业分析具备发问方语境，但不把卖方画像展示在结果中。

执行要求：

1. 优先按 `business-context.md` 中的已验证配置 CLI 读取 `service_models`。
2. 配置不足时，按 `business-context.md` 使用用户明确上下文、CRM 产品/服务对象摘要、近 12-24 个月成交摘要降级。
3. 卖方画像缺失时仍可输出行业事实，但不做强相关性判断。

## D. 行业模板 route

执行要求：

1. 不能只按单一行业字段 route。
2. 要结合经营模式、主营业务、规模分层、上下游位置和区域多维识别。
3. 命中模板时读取对应模板。
4. 未命中模板时走通用判断口径，并标注“该行业未建个性化模板”。

## E. 外部行业资料与内部样本采集

执行前读取 `references/enterprise-cli-map.md`、`references/external-data-rules.md` 和 `references/crm-anchor-playbook.md`，分别约束企业情报 CLI、外部资料证据和 CRM 内部样本。

外部资料包括：

- 行业报告
- 政策法规和监管通报
- 行业新闻、官网、年报、榜单
- 与行业相关的公开研究或统计资料

内部样本包括：

- CRM 中该客户的相关记录
- 同行业成交客户或历史样本
- 与该客户相关的商机、销售记录、会议纪要、客户声音

执行要求：

1. 主报告已取得的 `company conc`、`market get-news`、上市公告等结构化结果可复用；字段不足时再按本专题 `enterprise-cli-map.md` 补查。
2. 内部 `company / market / listed` CLI 已覆盖的数据域，不先 web search；CLI 不可用、返回空、字段不足、时效不够或需要权威公开原文补证时，才使用 web search / web fetch。
3. 外部资料必须带时间口径。
4. 内部样本优先解释客户相关影响，不做无边界挖掘。
5. 资料不足时明确标注，不编造样本。

## F. 行业阶段与五维判断

执行要求：

1. 先定行业阶段。
2. 再按增长、监管、竞争、周期、经营压力五维判断。
3. 每维都要回答“这对这个客户意味着什么”。
4. 无实质影响的维度可简写，不强行展开。

## G. 客户行业位置与客户影响映射

执行要求：

1. 判断客户在行业中的位置、角色、类型或分层。
2. 把行业变化翻译成对客户经营、需求、风险和相关情报信号的影响。
3. 只输出客户侧信号，不输出动作类方案。

## H. 两种输出模式

### 独立调用模式

先形成 `references/schemas/standalone-report-data-model.md` 定义的独立报告数据模型，再输出完整行业分析结果，包括：

- 行业情报结论
- 客户行业位置
- 行业变化对客户的影响
- 行业背景摘要
- 与发问方业务相关的行业信号
- 待核实事项
- 证据来源

### 编排调用模式

编排调用模式仍必须先完成本 workflow 的关键步骤；不得只读取 `SKILL.md` 后基于上游主报告数据直接生成结论。至少读取 `enterprise-cli-map.md`、`output-contract.md`、`schemas/insight-data-model.md`、`industry-judgment-criteria.md`、`industry-templates/_router.md` 和命中的行业模板。无法完整执行时，在结构化结果中写明降级原因。

按 `references/schemas/insight-data-model.md` 返回以下结构化结果：

- 行业基本情况摘要
- 趋势和政策
- 主要玩家或竞争格局
- 行业共性痛点
- 客户行业位置
- 对客户的业务影响
- 关键证据
- 待核实事项

## I. 降级规则

| 情况 | 处理 |
|:---|:---|
| 客户主体多候选 | 中止，要求用户确认 |
| 客户未在 CRM 命中 | 允许用用户输入或公开资料降级，但标注“行业未经 CRM 确认” |
| 行业字段为空或不清晰 | 使用公开资料和多维特征推断，并标注 `inferred` |
| 行业模板未命中 | 走通用口径，并标注“该行业未建个性化模板” |
| 卖方画像缺失 | 输出客户事实，不做强相关性判断 |
| 外部资料不足 | 对应维度进入待核实，不编造 |
| 内部样本不足 | 不输出强样本判断，只说明样本不足 |
