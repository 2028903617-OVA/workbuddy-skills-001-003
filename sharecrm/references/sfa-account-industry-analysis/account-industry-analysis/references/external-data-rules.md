# 外部行业资料规则

本文定义 `account-industry-analysis` 如何使用行业报告、政策、新闻、官网、年报、榜单、监管资料等外部数据。内容参考原始 `sfa-industry-analysis-v4.0.zip` 中的 `references/data-sources.md` 和 `references/trend-and-events.md`，并按当前专题 Skill 边界收敛。

## 1. 外部资料定位

外部资料用于补充行业环境、趋势、政策、竞争格局、共性痛点和关键事件，但不能替代 CRM 行业锚定，也不能被写成 CRM 内部事实。

使用原则：

- 先锚定目标客户，再使用行业资料。
- 能用内部企业情报 CLI 获取到的企业基础、公开动态或上市披露时先取 CLI；CLI 不存在、字段不足、返回为空、时效不够或无法覆盖用户关注点时，才继续用 web search 和公开来源补查。
- 外部资料必须落到“对这个客户意味着什么”。
- 外部资料必须保留来源、时间口径和支撑内容。
- 只有旧资料时，标注“最新可得资料为 <年份/日期>”，不得写成当前事实。
- 外部资料不足时进入 `gaps`，不得编造行业结论。

## 2. 数据源类型与证据要求

| 维度 | 数据源类型 | 证据要求 | 可支撑内容 |
|:---|:---|:---|:---|
| 增长 | 行业报告、统计公报、协会数据、榜单 | 机构 + 年份/发布日期 | 行业阶段、增长趋势、客户所在赛道变化 |
| 监管 | 政策法规、监管通报、政府官网政策栏 | 政策名称/文号 + 发布日期 | 监管加强、准入变化、合规压力 |
| 竞争 | 行业新闻、上市公司年报、公开财报、榜单 | 来源 + 年份/发布日期 | 竞争格局、主要玩家、价格战、集中度变化 |
| 周期 | 行业指数、上下游价格、景气调查、采购经理指数等 | 时间点 + 发布机构 | 周期波动、订单压力、预算弹性 |
| 经营压力 | 同业财报、行业调研、公告、新闻 | 来源 + 年份/发布日期 | 毛利压力、现金流压力、库存、交付、成本压力 |
| 客户位置 | 官网、年报、公告、新闻、客户案例 | 来源 + 日期 | 客户业务类型、行业角色、分层、区域位置 |

## 3. 证据优先级

行业专题中涉及目标客户或同行业样本判断时，证据优先级为：

1. CRM 原值：商机、销售记录、会议纪要、客户声音中的客户侧原文片段。
2. CRM 结构化记录：客户、商机、合同/订单、活动、同行业成交/输单样本摘要。
3. 官方/监管来源：政策法规、监管网站、政府官网、企业官网、公告。
4. 年报/招股书/上市公司公告：需区分集团口径、上市主体口径和目标签约主体口径。
5. 权威机构报告、行业协会报告、统计公报：必须标机构和年份。
6. 行业新闻：二手转引价值最低，必须标来源和日期。
7. 行业通用规律推断：只能标 `inferred`，不得写成事实。

## 4. 趋势与事件使用规则

趋势输出要求：

- 给出方向，例如上行、持平、下行、转折或监管加强。
- 给出时间窗，例如近 6-12 个月、近 1-2 年。
- 给出依据，必须能回链证据。
- 如果属于推断，必须显式标注 `inferred`。
- 必须解释对目标客户的影响，否则不输出。

事件输出要求：

- 只保留与目标客户相关的行业事件。
- 每条事件包含时间、事件、来源和对客户的影响。
- 传闻、无来源事件不进入正文，进入 `gaps`。
- 趋势以 1-2 条为宜，关键事件以 3-5 条为宜。

## 4A. web search / web fetch 控制

- 主报告或本专题已有 `company conc`、`market get-news`、上市公告等可支撑行业客户判断时，不为补充背景泛化 web search。
- 默认最多 1-2 个精准 query，每个 query 只消费前 3-5 条高质量结果；query 应包含行业/政策/客户业务关键词，避免泛搜“行业地位/竞争格局”。
- web fetch 只抓官网、公告、监管、交易所、行业协会、权威报告或权威新闻。遇到“操作过于频繁”、访问受限、登录/验证码、403、404、加载失败、明显反爬或长时间无正文时立即降级。
- 行业通用背景不足时可以简写或进入 `gaps`，不得为了五维完整性长时间抓取低价值网页。

## 5. 能力降级规则

| 情况 | 处理 |
|:---|:---|
| 外部行业资料不可用 | 对应维度进入 `gaps`，说明需要的资料类型 |
| 政策/监管资料不可用 | 监管维度标“政策未核实”，不假设利好或利空 |
| 榜单/财报不可用 | 竞争维度只输出有证据的定性判断，不给排名或数字 |
| 只能找到旧资料 | 标注最新可得时间，并在 `gaps` 中记录时效缺口 |
| 来源冲突 | 同时保留冲突来源和时间口径，降低判断强度 |
| 只有新闻转述 | 不作为核心结论单独支撑，需寻找官网、监管或公告补证 |
| CLI 返回为空、字段不足或覆盖不全 | 少量精准 web search、官网、公告、监管网站、年报、行业报告等公开来源补查；公开来源仍无证据时再进入 `gaps` |

## 6. 禁止用法

- 不把行业新闻写成客户事实。
- 不把公开资料写成 CRM 内部记录。
- 不用市场容量、行业规模、宏观增速等通用数字替代客户影响判断。
- 不为了模板完整强行补趋势、政策、竞争、周期、经营压力五维内容。
- 不输出 PEST、波特五力、TAM/SAM/SOM、行业发展史等独立研究报告章节。

## 7. 写入独立报告数据模型

- 外部资料证据写入 `evidence`。
- 行业阶段和依据写入 `industryContext.industryStage`、`industryContext.industryStageBasis`。
- 五维判断写入 `industryContext.businessImplications`。
- 趋势和事件写入 `industryContext.trendAndEvents`。
- 通用行业背景压缩写入 `industryContext.trends`、`industryContext.policies`、`industryContext.majorPlayers`、`industryContext.commonPainPoints`。
- 证据不足、资料过旧或来源冲突优先写入 `industryContext.gaps`，必要时同步写入顶层 `gaps`。
