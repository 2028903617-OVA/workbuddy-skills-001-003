# 客户行业分析自检清单

本清单仅供内部验证，不得作为正文输出。

## 主体与锚定

- [ ] 目标客户是否已唯一确认。
- [ ] 用户输入为简称、品牌名、产品名、股票简称或非完整工商名称时，是否先调用 `sharecrm intelligence company search` 做结构化候选召回，而不是先进入 web search。
- [ ] `company search` 返回多候选或主体冲突时，是否返回前 3-5 个候选让用户确认，没有直接套用名称相近主体。
- [ ] 行业是否优先从 CRM 锚定。
- [ ] CRM 字段是否对象描述驱动解释。
- [ ] 行业未确认时是否明确标注。
- [ ] CRM 快速检索未命中时，是否没有直接断言 CRM 未覆盖。
- [ ] 内部样本不足时，是否没有输出强样本判断。

## 数据与证据

- [ ] 关键判断是否有证据来源。
- [ ] 企业情报 CLI 调用是否只使用 `enterprise-cli-map.md` 中允许的读命令。
- [ ] `sharecrm intelligence company conc` / `ip conc` 是否只传入本 skill 白名单内的 `actionTypes`，没有一次性传入全部支持类型。
- [ ] CRM CLI 调用是否只使用 `crm-cli-map.md` 中允许的读命令。
- [ ] 证据是否带时间口径。
- [ ] 推断是否与事实区分。
- [ ] 没有证据的内容是否已进入待核实。
- [ ] 外部行业资料是否保留来源、年份或发布日期。
- [ ] 只有旧资料时，是否标注最新可得时间和时效缺口。
- [ ] CRM 原值是否脱敏，且没有展示对象 API 名、内部记录 ID 或敏感字段原值。

## 内容与边界

- [ ] 是否解释了这对目标客户意味着什么。
- [ ] 如输出“是否值得做”判断，是否基于卖方画像、客户行业事实和证据强度，而不是泛行业判断。
- [ ] 是否没有写成纯行业研究报告。
- [ ] 是否没有输出 PEST、波特五力、TAM/SAM/SOM、行业发展史等独立研究章节。
- [ ] 是否没有输出触达路径、话术、跟进节奏、作战计划。
- [ ] 是否没有展示卖方画像原文。
- [ ] 是否没有为了模板完整输出“暂无”“未获取到”“待核实”。

## 输出模式

- [ ] 独立调用模式是否先形成 `references/schemas/standalone-report-data-model.md`。
- [ ] 独立输出是否只消费独立报告数据模型中的已有字段。
- [ ] 编排调用模式是否按 `references/schemas/insight-data-model.md` 返回摘要、判断和证据。
- [ ] 编排调用模式是否读取并执行 `references/00-workflow.md`、`references/output-contract.md`、`references/schemas/insight-data-model.md` 和必要行业判断/模板文件，而不是只读 `SKILL.md` 后直接推断。

## HTML / CRM 展示

- [ ] 需要 HTML 时，本轮是否已经读取 `references/html-report-template.md`；如未读取，HTML 自检必须失败，不能生成正式 HTML 或宣称自检通过。
- [ ] `output-contract.md` 是否没有被误当作 HTML 模板替代品。
- [ ] 需要 HTML 时，是否按 `references/html-report-template.md` 生成，而不是临时拼接页面。
- [ ] CRM 内嵌版本是否优先展示行业结论和客户行业位置，而不是先展开大段行业背景。
- [ ] 独立调用交付是否默认采用“先输出文字业务概要结论 + HTML 完整报告”；如用户未明确要求完整 Markdown，是否没有重复输出整份 Markdown 长文。
- [ ] HTML 是否没有新增文字版结果没有依据的事实。
- [ ] HTML 是否没有展示卖方画像原文、CLI 路径、对象 API、SQL 或内部记录 ID。
- [ ] 长 HTML 是否包含实际渲染章节的目录、锚点和滚动高亮规则。
- [ ] 目录是否优先采用封面下方横向 sticky 样式；若使用深色侧栏，是否确有长目录或标题拥挤原因，且没有让大面积深色压过正文。
- [ ] HTML 是否没有被限制成纯白卡片和普通表格；封面、摘要区、图标卡和图表是否有正式报告的视觉完成度。
- [ ] 标签、徽章和 emoji 文案是否来自 `industryContext`、`crmContext`、`sellerRelevantSignals`、`gaps`、结构化字段或证据；是否没有把泛行业描述写成已证实的客户行业地位。
- [ ] 荣誉/资质类标签是否只在主报告传入字段、企业情报 CLI 或公开证据明确支持时展示；是否没有凭行业分类、客户规模、融资或技术描述生成“高新技术企业”“专精特新”“单项冠军”等标签。
- [ ] 结构化信息充足时，是否允许使用热力图、雷达图、矩阵图、趋势组合图等更适合行业判断的表达。
- [ ] 每个一级章节是否都具备开头概述结论和末尾业务含义总结。
- [ ] 行业章节在结构化信息充足时，是否至少输出一个行业图表；若降级为纯表格，是否确有证据不足、样本过少或维度不清原因。
- [ ] 每个真实图表下方是否都有对应详细表格，而不是只有 fallback table。
- [ ] 热力图/矩阵图容器桌面端是否约 `460-500px`，没有复用普通 360-380px 高度；移动端是否仍有稳定可读高度。
- [ ] 产品/服务、应用场景、行业趋势、机会强弱或客户匹配度信息充足时，是否优先尝试热力图或矩阵图；不适合时是否使用更合适的图表或表格降级。
- [ ] 热力图/矩阵是否有清晰二维维度和可读标签；定性等级是否展示等级含义并标注归纳口径，没有伪装成真实评分、排名或市场份额。
- [ ] 环形图/饼图是否只用于真实构成类别少且样本完整的场景；行业影响、机会强弱、客户匹配度等判断类信息是否没有被做成伪占比饼图。
- [ ] 定性归纳型可视化是否标注了模型归纳口径，没有伪装成原始统计值。
- [ ] 如行业结论、客户匹配度、机会强弱、竞争格局或分布图来自模型归纳，是否在图例、表头、结论句或说明中明确保留归纳口径。
- [ ] 如新闻、事件、动态来源或内部样本只消费首批结果，是否在表格、图例、章节结论或 coverage 说明中明确写明覆盖范围，没有把首批样本写成全量分布或全量结论。
- [ ] CRM 快速检索未命中、仅返回模糊候选或行业锚定未经确认时，是否没有把内部样本、CRM 标签或客户行业位置写成已确认 CRM 事实。
- [ ] HTML 交付前是否完成展示完整性自检，并修复空白图表、无效锚点、目录遮挡、脚本配置错误或其他明显渲染异常；如图表无法稳定渲染，是否改为表格、列表、信号卡、矩阵或文字摘要表达同一数据。
- [ ] 最终用户正文是否没有打印原始文件对象 JSON、内部路径或 `{"type":"file","path":"..."}`。
- [ ] HTML 表格是否控制列数，避免在 CRM 内嵌场景出现难以阅读的横向超宽表。
