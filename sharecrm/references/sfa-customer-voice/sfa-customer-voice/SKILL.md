# sfa-customer-voice

用于把多条销售记录、会议记录和会议记录明细中的客户表达，整理成默认面向管理层阅读的客户声音报告，或按需以 Q&A 模式回答管理者关于客户声音的具体问题。

## 快速流程

1. 识别分析视角、时间范围、过滤范围和用户意图
2. 只查询 `ActiveRecordObj`、`AIMeetingObj`、`AIMeetingChunkObj`
3. 抽取客户声音并区分 `确认`、`推断`、`未知`
4. 按 $APPEALS 八维归类，映射到用户六维维度
5. 聚类主题，判断趋势、归因、风险和机会
6. 根据交互模式组装输出（报告模式或 Q&A 模式）

## 适用边界

优先用于：

- 多客户、多记录、多会议的客户反馈汇总
- CEO、经营团队、销售管理层查看客户声音
- 某时间窗口内的高频问题、上升趋势、风险机会判断
- 按部门、负责人、会议发起人、业务类型查看声音差异
- 按六维（痛点/期望/不满/认可/竞品/趋势）深钻特定方向

不要用于：

- 单客户 360 档案或标准版客户简报
- 见客前行动建议或陪访简报
- 单商机竞对策略、赢单预测、项目交付复盘
- 需要扩查客户、商机、联系人、合同、订单、回款等其他对象的任务

## 核心原则

- 只把客户明确表达或有记录依据的内容当作客户声音
- 不把销售主观判断直接写成客户事实；必要时标注为 `推断`
- 趋势、强度、归因都要绑定时间范围、样本量和证据来源
- 数据不足时保留"不足/待补充"，不要补猜
- 引用客户原话时只保留少量高价值短句，不粘贴大段原文
- $APPEALS 八维是底层分析引擎，确保分析 MECE 不遗漏；用户看到的是六维（痛点/期望/不满/认可/竞品/趋势），$APPEALS 标签不直接暴露给用户
- 结论先行，证据可追溯——管理者 30 秒内获得核心判断，按需追溯原始语录

## 执行顺序

### 前置意图判断（最高优先级）

**在用户输入处理的第一个步骤，优先判断是否属于 VOC 理论咨询场景。**

读取 `rules/R01_scope.md` 中的意图识别规则，检查用户输入是否包含以下关键词：

- "什么是 VOC" / "VOC 是什么" / "介绍一下 VOC"
- "讲讲华为 VOC" / "华为 VOC 方法论"
- "VOC 五步闭环是什么" / "五步闭环" + "方法论"
- "$APPEALS 是什么" / "八维解码" / "客户需求八维"
- "客户声音方法论" / "VOC 理论" / "VOC 介绍"

**如果匹配上述任意关键词（intent_type=voc_theory）：**

1. **立即停止**后续所有 CRM 数据查询、声音抽取、分析报告步骤
2. **直接读取** `references/voc_methodology.md`
3. **强制输出**该知识库中的完整内容，**严禁**使用通用知识或 skill description 自行生成
4. 用户要求 HTML 时，同时读取 `references/voc_methodology_intro.html` 并按其 DOM/CSS 结构输出
5. 采用"先总后分"策略：首次输出核心全景 + 金句；用户追问具体章节时展开
6. 输出末尾**必须追加**引导语：`💡 了解了 VOC 方法论后，是否需要我为您生成一份客户声音分析报告？您可以告诉我时间范围（如"最近一个月"），我将为您按 VOC 五步闭环呈现客户声音洞察。`
7. **直接结束**，不走下面的标准执行流程

> ⚠️ **强制规则**：当 intent_type=voc_theory 时，输出内容必须来源于 `references/voc_methodology.md`，**禁止**使用 skill description、通用知识或自行编造。即使 skill description 中包含 VOC 的简要定义，回答时也必须以知识库文件内容为准。如果发现知识库内容与通用知识冲突，以知识库为准。

### 0. 意图识别（标准流程）

**仅在 intent_type ≠ voc_theory 时执行以下步骤。**

先读取：

- `rules/R09_interaction_mode.md`

需要明确：

- 意图类型：报告意图 / 问答意图 / 探索意图 / 混合意图
- 交互模式：报告模式 / Q&A 模式 / 先问答后报告模式
- 用户查询的维度：痛点 / 期望 / 不满 / 认可 / 竞品 / 趋势 / 无特定维度

### 1. 识别范围

先读取：

- `rules/R01_scope.md`

需要明确：

- 分析视角：默认 `CEO/管理层`，也可按部门负责人、AE、记录视角补充查看
- 时间范围：未指定时默认最近 30 天
- 过滤条件：负责人、部门、会议发起人、内部参与人、业务类型、会议状态等
- 意图类型和交互模式（由步骤 0 传递）
- 用户查询维度（由步骤 0 传递）

### 2. 查询数据

需要调用 CRM CLI 时读取：

- `references/cli_reference.md`
- `references/crm_schema.md`

只允许查询：

- `ActiveRecordObj`
- `AIMeetingObj`
- `AIMeetingChunkObj`

`object_api_name`、`original_id`、`account_id`、`related_object` 等字段只用于溯源、去重和分组，不自动继续扩查原对象。

### 3. 抽取与分析声音

按需读取：

- `references/voice_taxonomy.md`
- `rules/R02_voice_extraction.md`
- `rules/R10_appeals_mapping.md`
- `rules/R03_topic_clustering.md`
- `rules/R04_trend.md`
- `rules/R05_attribution.md`
- `rules/R06_quotes.md`
- `rules/R07_risks_opportunities.md`

执行时始终区分：

- `确认`：有客户原文或高可信记录证据
- `推断`：有间接证据，但非客户直接确认
- `未知`：证据不足，不能写成事实

### 4. 组装结果

根据交互模式选择不同的组装路径：

**报告模式**（interaction_mode=report）：

读取：

- `rules/R08_assembly.md`

根据 R01 输出的 `report_template` 选择报告结构：

- `voc_5step`（默认）：VOC 评审版——听见→理解→持续变革
- `classic_6chapter`：经典六章升级——整体判断→关注指标→客户声音主题→客户分层→管理动作→经营层结论

两种模板均为证据驱动格式，每个结论必须附统计+客户分布+真实反馈依据。报告开头均含六维总览。

> ⚠️ **强制规则**：旧版格式（"结论摘要/声音范围与样本/高频声音主题/趋势变化/角色视角归因/代表性客户原文/风险与机会/建议动作/开放问题"）是**已废弃的 v1 格式**，**任何情况下都不得再次使用**——无论是 Markdown 还是 HTML，无论是否指定模板。

**Q&A 模式**（interaction_mode=qa）：

读取：

- `rules/R08_assembly.md`（Q&A 输出部分）

分两步输出：

- 第一步：维度概况 + 风险/机会信号 + 建议行动
- 第二步（用户按需）：客户分布 + 原始语录

**先问答后报告模式**（interaction_mode=report_with_qa）：

读取：

- `rules/R08_assembly.md`

输出报告（按 report_template 选定结构），重点展开问答中关注的维度，开头注明聚焦注释。

> **注意**：VOC 理论咨询（intent_type=voc_theory）已在「前置意图判断」中处理，不走本步骤。

## 视角适配

- `CEO/管理层`：强调跨部门共性问题、经营风险、战略机会、客户分层和组织动作
- `销售管理者`：强调团队共性问题、人员差异、趋势变化和管理动作
- `部门负责人`：强调本部门高频声音、重点人员、局部闭环
- `AE`：强调自己负责范围内的高优先级反馈、待验证问题和跟进动作

未指定视角时，默认按 `CEO/管理层视角` 组织输出。

## Memory 使用

需要沉淀长期声音快照、重大风险事件或新出现主题时，再读取：

- `memory/template.md`

Memory 只用于趋势对照和长期观察，不替代当前周期的原始记录证据。

## 输出要求

- 默认输出 Markdown
- **HTML 输出**：当用户明确要求"输出 HTML""生成 HTML""用网页格式"时，按 R08 定义的 HTML 格式规则输出完整 HTML 代码
    - HTML 必须包含完整的 `<!DOCTYPE html>` `<html>` `<head>` `<body>` 结构
    - HTML 必须严格遵循 `references/voc_report_template.html` 的 DOM 结构和 CSS 类名
    - HTML 中的 $APPEALS 维度卡片必须使用 `.appeals-dim-card` 类名，并按三段式输出
    - HTML 中的页头、六维总览、风险/机会信号、客户分层、持续变革、能力升级方向的视觉样式，必须与 `references/voc_report_template.html` 保持一致，不得退回旧版深色头图或整卡染色样式
    - HTML 中的 `六维总览` 必须按固定顺序输出：`新需求（痛点）`、`不满`、`竞品`、`趋势`、`认可`、`期望`，并在后面追加 `主要问题清单`
    - HTML 中的 `$APPEALS 八维分析` 标题必须固定使用已确认的 8 个中文专业名，并在标题后追加原 VOC 英文维度名
    - `持续变革（Transform）` 在 HTML 中必须输出带短标题的结论卡片，短标题需从结论主旨中提炼，风格参考：`竞品风险上升`、`增长底盘仍在`、`原声数据待补`
    - HTML 输出不得省略任何章节，内容必须与 Markdown 版同等完整
- **报告模式**：根据 R01 输出的 `report_template` 选择报告结构
    - 默认使用 `voc_5step`（评审版 VOC 结构：听见→理解→持续变革）
    - 用户指定时可用 `classic_6chapter`（经典六章升级：整体判断→关注指标→客户声音主题→客户分层→管理动作→经营层结论）
    - 具体章节结构和格式严格遵循 `rules/R08_assembly.md`
- **禁止行为**：
    - 禁止只输出摘要表格后跳过正文
    - 禁止输出"完整报告文件已生成""详见附件"等占位短语代替正文
    - 禁止将报告正文拆分为"摘要版"和"详细版"两次输出；一次交互必须输出完整报告
    - 禁止自行发明与 R08 模板不符的大块结构
    - **禁止使用旧结构**：旧格式（"结论摘要/声音范围与样本/高频声音主题/趋势变化/角色视角归因/代表性客户原文/风险与机会/建议动作/开放问题"）已废弃，**严禁**再次使用，任何情况下都不允许退化为旧结构
- **评审版强制规则**：
    - 顶部 `六维总览` 必须移除表格结构，改为 6 条一句话总结，按重要性和高频性排序
    - 移除 `声音接收概览`
    - `$APPEALS 八维分析` 卡片中严禁输出评分、进度条、证据等级、证据盒子
    - 每个八维卡片必须固定为三段：第一段提及统计与信号判断；第二段列举 2-3 个客户或商机的真实反馈；第三段写当前维度的行动建议
    - 移除独立章节 `采取行动（Act）`
    - 移除独立章节 `反馈闭环（Feedback）`
    - 移除 `附录`
    - 严禁编造；任何客户名、商机名、反馈、提及次数、风险原因都必须来源于输入证据，不足则明确写“当前数据不足以支持判断”
- `客户声音主题` 使用五列表格思路：`主题 / 客户典型表达 / 经营含义 / 优先动作 / $APPEALS 归属`
- 不允许把 `客户声音主题` 退化成按客户逐条展开的明细大表
- 样本量、时间范围、信息完整度和置信度作为报告头信息保留
- **报告末尾必须输出引导语**（无论哪种模板）：`💡 如需针对特定维度（如痛点、竞品、不满）展开深度分析，或调整时间范围/人员范围重新生成报告，随时告知。输入「展开【维度名】」可查看该维度完整 5 卡片分析。`
- 如果样本明显偏斜，必须显式写出样本偏差；但不再单独生成附录
- **Q&A 模式**：按 R09 定义的分层渐进式格式输出，第一步控制在 30 秒内可读完
