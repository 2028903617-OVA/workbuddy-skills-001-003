## 1. 什么是 VOC（客户声音）

### 1.1 VOC 的定义

VOC（Voice of Customer，客户声音）是一种以客户为中心的分析方法论，源自华为销售体系。其核心逻辑是：**从客户真正说了什么出发，结构化理解客户需求，驱动组织行动和变革。**

VOC 不是简单的"收集意见"，而是一个完整的闭环体系——从"听见"到"理解"再到"行动"再到"反馈"最终实现"变革"。

### 1.2 VOC 五步闭环

```
听见（Hear）→ 理解（Understand）→ 行动（Act）→ 反馈（Feedback）→ 变革（Transform）
  多渠道采集      结构化解码        跨部门响应       告知客户改变      组织能力重塑
```

| 步骤 | 核心问题 | 说明 |
|------|---------|------|
| **听见** | 我们听到了什么？ | 从销售记录、客户会议、沟通记录中全面采集客户表达 |
| **理解** | 客户在说什么？意味着什么？ | 用 $APPEALS 八维模型结构化解码，识别风险和机会 |
| **行动** | 我们应该做什么？ | 基于证据给出可执行的管理动作，绑定责任角色和时机 |
| **反馈** | 和上期比有什么变化？ | 跟踪趋势变化，验证行动效果，形成闭环 |
| **变革** | 应该在能力上做什么升级？ | 将客户声音驱动到产品/服务/组织的深层变革 |

### 1.3 $APPEALS 八维解码模型

$APPEALS 是华为 VOC 方法论的核心工具，用于将模糊的客户声音翻译成结构化、可衡量的八个维度：

| 缩写 | 维度 | 核心问题 | 一句话理解 |
|------|------|---------|----------|
| **$** | 价格（Price） | 客户觉得贵不贵？值不值？ | "花这钱值吗？" |
| **A** | 可获得性（Availability） | 客户获取产品/服务容不容易？ | "想用时能用到吗？" |
| **P** | 包装（Packaging） | 产品给人的第一印象如何？ | "看着顺眼吗？" |
| **P** | 性能（Performance） | 功能是否满足需求？ | "能干我想干的事吗？" |
| **E** | 易用性（Ease of Use） | 用起来费不费劲？ | "好不好上手？" |
| **A** | 保证（Assurances） | 可不可靠？安不安全？ | "靠得住吗？" |
| **L** | 生命周期成本（Life Cycle Cost） | 长期用的总成本高不高？ | "后续还要花多少钱？" |
| **S** | 社会接受度（Social Acceptance） | 行业口碑好不好？别人用不用？ | "别人怎么说？" |

> 💡 **提示**：您可以直接在 CRM 智能助手中输入"什么是 VOC"或"介绍一下 VOC 方法论"，系统会为您详细介绍 VOC 理论。

>
> ![六维总览表](此处粘贴截图)

#### 第二章：理解客户声音（Understand）

回答的核心问题：**客户在说什么？意味着什么？风险和机会在哪里？**

- **$APPEALS 八维分析卡片**：每个维度独立成卡，包含得分、风险/机会标签、典型客户原话、经营含义
- **风险/机会信号**：从八维分析中推导出的具体信号
- **客户分层**：按认可型/机会型/观望型/风险型分层

> 📸 **截图位置**：第二章 $APPEALS 八维分析卡片
>
> ![$APPEALS八维卡片](此处粘贴截图)

**$APPEALS 维度卡片解读指南**：

```
┌──────────────────────────────────────────┐
│ $ 价格（Price）— 得分 35/100 🔴风险信号   │
│                                          │
│ 进度：[██████░░░░] 35%                   │
│ 统计：提及 12 次 / 8 个客户               │
│       情感：负面 60% / 正面 20%           │
│       Q2环比 ↑ 上升 12%                  │
│                                          │
│ 典型声音：                                │
│ 「价格比竞品高 20%，很难接受」             │
│   — A科技，2026-05-20，销售记录，E1       │
│                                          │
│ 经营含义：价格敏感度上升，续约风险增大     │
└──────────────────────────────────────────┘
```

| 卡片元素 | 含义 | 读取方式 |
|---------|------|---------|
| **得分（0-100）** | 该维度的客户满意度综合评分 | 低分（0-40）= 问题严重；中分（41-70）= 需关注；高分（71-100）= 表现良好 |
| **进度条** | 得分的可视化 | 实心 █ 越多 = 满意度越高 |
| **🔴风险信号** | 得分≤40且负面声音≥2条 | 需要立即关注和行动 |
| **🟢机会信号** | 得分≥75且正面声音≥2条 | 可进一步放大优势 |
| **— 平稳** | 介于风险和机会之间 | 保持观察 |
| **典型声音** | 该维度最具代表性的客户原话 | E1=客户原话（最可信）；E2=会议确认；E3=间接推断；E4=待验证 |
| **经营含义** | 该维度对经营的影响 | 决定是否需要采取行动 |

## 4. 六维维度查看指南

客户声音按六个维度进行分类展示，帮助您从不同角度理解客户。

### 4.1 六维总览表

报告的"听见客户声音"章节会首先展示六维总览表：

| 维度 | 提及客户 | 提及率 | 情感分布 | 风险等级 | 趋势 |
|------|---------|-------|---------|---------|------|

| 期望 | 9/18 | 50% | 正面 70% | 🟢 低 | ↗ 上升 8% |

| 趋势 | 4/18 | 22% | 中性 | — | 🆕 新兴 |

### 4.2 六维维度定义

#### 🔶 痛点 — 客户自身业务中遇到的困难

**定义**：客户在其自身业务运营中遇到的摩擦、效率瓶颈和问题。这些痛点可能与我们产品相关，也可能与客户自身流程有关。

**典型问题**：
- "审批流程太繁琐，影响了我们的效率"
- "数据孤岛问题严重，各系统之间无法打通"
- "一线销售使用CRM的积极性不高"

**查看方式**：输入 "客户痛点有哪些" / "展开痛点"

> 📸 **截图位置**：痛点维度展开视图
>
> ![痛点维度](此处粘贴截图)

#### 🔷 期望 — 客户明确想要的功能或能力

**定义**：客户对未来产品/服务的明确期待和需求。期望是"想要的未来"，区别于痛点（"现在的痛"）。

**典型问题**：
- "希望增加自动审批功能"
- "希望能和ERP系统集成"
- "想要更灵活的权限管理"

**查看方式**：输入 "客户期望什么" / "展开期望"

> 📸 **截图位置**：期望维度展开视图
>
> ![期望维度](此处粘贴截图)

#### 🔴 不满 — 客户对我方的负面反馈

**定义**：客户明确表达对我方产品、服务或商务关系的不满意。不满是对我方的直接批评，区别于痛点（可能是客户自身问题）。

**典型问题**：
- "系统经常卡顿，影响日常工作"
- "你们的服务响应太慢了"
- "价格比竞品高太多了"

**查看方式**：输入 "客户对我们有什么不满" / "展开不满"

> 📸 **截图位置**：不满维度展开视图
>
> ![不满维度](此处粘贴截图)

#### 🟢 认可 — 客户对我方的正面评价

**定义**：客户明确表达对我方的满意和认可。认可维度帮助我们了解自身优势，以便巩固和放大。

**典型问题**：
- "你们的移动端体验比竞品好很多"
- "售后服务很及时，这点我们很满意"
- "功能全面，基本能满足我们的需求"

**查看方式**：输入 "客户认可我们什么" / "展开认可"

> 📸 **截图位置**：认可维度展开视图
>
> ![认可维度](此处粘贴截图)

#### ⚔️ 竞品 — 和竞争对手相关的客户声音

**定义**：涉及竞争对手的客户声音，包括竞品比较、替代方案考虑、竞品优劣势等。**注意：竞品名称不做脱敏处理**，会保留真实竞品名称便于管理层识别竞争格局。

**典型问题**：

> ![竞品维度](此处粘贴截图)

### 4.3 维度下钻（5 卡片详细分析）

点击某个维度后，系统会展开该维度的完整分析，呈现 **5 张卡片**：

#### 常规五维（痛点/期望/不满/认可/竞品）的下钻结构

| 卡片 | 内容 | 回答的问题 |
|------|------|----------|
| 1️⃣ 维度概况 | 提及率、情感分布、趋势方向、风险标签 | 有多严重？ |
| 2️⃣ 客户分布 | 哪些客户提及、各自的情感、可展开原话 | 谁在说？ |
| 3️⃣ 原始语录 | 按证据等级 E1→E4 排序的真实原话 | 具体说了什么？ |
| 4️⃣ 风险/机会信号 | 该维度推导出的具体信号，附证据 | 意味着什么？ |

### 4.4 证据等级说明

### 5.2 八个维度详解

#### 💰 $ 价格（Price）— "花这钱值吗？"

**关注什么**：客户对价格、性价比、费用的反馈

**典型客户表达**：
- "价格太高了"
- "性价比不够"
- "续费价格涨了 30%，很难接受"

**解读方法**：
- 得分低 + 🔴风险信号 → 价格敏感度上升，续约风险增大
- 得分高 + 🟢机会信号 → 客户认可价值，可推进增购

>
> ![$价格卡片](此处粘贴截图)

#### 📦 A 可获得性（Availability）— "想用时能用到吗？"

**关注什么**：客户获取产品/服务的便利度、部署速度、资源可用性

**典型客户表达**：
- "部署周期太长了"
- "上线等了 3 个月还没好"
- "没有足够的实施资源"

**解读方法**：
- 得分低 → 交付能力不足，影响客户体验
- 关注趋势变化，上升说明交付改善

#### 🎨 P 包装（Packaging）— "看着顺眼吗？"

**典型客户表达**：
- "界面太丑了，拿不出手"
- "模板太少"
- "给老板看觉得不够专业"

**解读方法**：
- 包装维度往往是"第一印象"问题
- 低分可能影响客户对产品的整体评价

**典型客户表达**：
- "功能不够用"

- "不支持自定义字段"

**解读方法**：
- 性能维度往往是最核心的维度

- "培训了 3 次还是不会用"
- "操作步骤太多"

**解读方法**：

- "系统经常宕机"
- "数据同步出错了"
- "对数据安全不放心"

**解读方法**：
- 保证维度得分低 = 严重风险信号

### 5.3 八维与六维的关系

用户看到的 **六维**（痛点/期望/不满/认可/竞品/趋势）是面向用户的查询入口，**$APPEALS 八维** 是底层分析引擎。两者的映射关系：

| 用户六维 | 主要映射 $APPEALS 维度 | 说明 |
|---------|----------------------|------|
| 痛点 | E 易用性 + A 保证 + P 性能 + L 生命周期成本 | 客户业务之痛 = 流程卡、效率低、系统不好用、成本高 |
| 期望 | P 性能 + P 包装 + E 易用性 | 想要更多更好更方便 |
| 不满 | A 保证 + E 易用性 + P 性能 + $ 价格 | 对我方不满意 = 不稳定、不好用、功能不够、太贵 |
| 认可 | P 性能 + A 保证 + P 包装 + L 生命周期成本 | 对我方满意 = 功能好、靠谱、体验好、长期划算 |
| 竞品 | S 社会接受 + $ 价格 + P 性能 | 竞品比较 = 口碑、价格、能力 |
| 趋势 | 全八维 | 跨客户、跨时间的聚合洞察 |

> 💡 **简单理解**：您按六维提问，系统按八维分析，最后以六维呈现给您。八维确保分析不遗漏，六维确保查看更直观。

## 9. 常见问题（FAQ）

### Q1：报告的数据来源是什么？

**A**：报告基于 CRM 系统中的三类数据：
- **销售记录**（ActiveRecordObj）：销售人员在跟进过程中记录的客户反馈
- **会议记录**（AIMeetingObj）：客户会议的总体记录
- **会议记录明细**（AIMeetingChunkObj）：会议中的具体对话片段

### Q2：报告的可信度如何？

**A**：每个结论都标注了证据等级（E1-E4），并在报告页头标注了信息完整度和置信度说明。E1 级（客户原话）的证据最可信。

### Q3：为什么有些维度显示"本周期未检测到相关声音"？

**A**：说明在当前时间范围内，没有客户在该维度表达过意见。这不代表该维度不重要，可能只是数据覆盖不足。

### Q4：如何切换报告模板？

**A**：
- 默认使用 VOC 五步闭环模板
- 输入"用经典六章结构出报告"可切换到六章模板
- 输入"用 VOC 五步结构出报告"可切回五步模板

### Q5：可以只看某个维度的详情吗？

**A**：可以。输入"展开【维度名】"（如"展开不满"），系统会输出该维度的完整 5 卡片分析。

### Q6：竞品名称会被脱敏吗？

**A**：不会。竞品名称属于市场公开信息，报告中会保留真实竞品名称（如 Salesforce、华为云、阿里云），便于管理层直接识别竞争格局。如需脱敏，可在技能配置中开启。

### Q7：报告可以导出为 HTML 吗？

**A**：可以。输入"输出 HTML"或"用网页格式"，系统会输出完整 HTML 代码，可直接在浏览器中打开。

### Q8：数据不足时报告会怎样？

**A**：系统会在报告页头标注"信息完整度"和"置信度说明"。如果数据明显不足，会在附录中提示样本偏差。结论不充分时会保留"待补充"标注，不会编造内容。

### Q9：可以按部门或人员查看客户声音吗？

**A**：可以。在输入中指定范围即可：
- "华东区的客户声音怎么样？"
- "张三负责的客户有什么反馈？"
- "技术部的客户声音分析"

### Q10：什么是"你可能还想了解"推荐？

**A**：基于 $APPEALS 维度关联，系统会推荐与当前分析最相关的维度。例如您查看了"不满"维度中关于价格的反馈，系统会推荐您查看"生命周期成本"维度，因为觉得贵的客户往往也关注长期成本。
