# 客户声音分类参考

本文件用于定义客户声音的主题、类型、情绪、强度和证据等级。分类只能辅助分析，最终判断仍以 `ActiveRecordObj.active_record_content`、`ActiveRecordObj.interactive_content`、会议记录、会议记录明细原文和摘要为准。

## 声音类型

| 类型 | 中文 | 判断标准 |
| --- | --- | --- |
| `demand` | 明确需求 | 客户提出想要的能力、场景、结果或服务 |
| `pain` | 痛点困难 | 客户表达当前业务问题、效率问题、管理问题 |
| `objection` | 异议顾虑 | 客户对价格、周期、安全、能力、风险有顾虑 |
| `complaint` | 投诉负面 | 客户表达不满、抱怨、升级、服务或产品问题 |
| `question` | 疑问追问 | 客户反复询问方案、功能、流程、价格或案例 |
| `praise` | 正向认可 | 客户认可产品、服务、交付、效果或人员 |
| `competitor` | 竞品相关 | 客户提到竞品、自研、替代方案、对比或报价 |
| `budget` | 预算价格 | 预算状态、报价压力、折扣、ROI、付款方式 |
| `approval` | 审批决策 | 老板拍板、采购流程、法务、财务、招投标 |
| `usage` | 使用效果 | 活跃率、填报、数据质量、推广、管理看板 |
| `delivery` | 交付服务 | 实施、培训、接口、上线、验收、响应时效 |
| `expansion` | 扩展诉求 | 扩部门、扩模块、更多流程或场景 |
| `record_quality` | 记录质量 | 会议 AI 失败、原文缺失、摘要不完整、记录无法判断 |

## 主题分类

| 主题 | 包含声音 | 常见业务影响 |
| --- | --- | --- |
| 产品能力 | 功能、易用性、权限、报表、移动端、PaaS | 验收、使用效果、产品路线 |
| 系统集成 | ERP/MES/财务/工单/自研系统、接口、迁移 | 技术评估、实施周期、IT 决策 |
| 交付实施 | 上线、培训、实施资源、项目管理 | 项目满意度、验收、上线风险 |
| 服务响应 | 售后、客服、问题处理、响应时效 | 满意度、口碑、后续推进 |
| 价格预算 | 报价、折扣、预算、ROI、付款 | 推进节奏、延期、降价压力 |
| 审批决策 | 老板、采购、法务、财务、招投标 | 决策周期、关键人覆盖 |
| 竞品比较 | 同类 CRM、自研、替换方案 | 差异化打法、推进风险 |
| 使用效果 | 一线使用、管理看板、数据质量 | 推广、培训、效果证明 |
| 扩展需求 | 新部门、新模块、新流程、新场景 | 增量机会、方案复用 |
| 行业场景 | 渠道、外勤、经销商、服务、合规 | 行业方案、可复制打法 |
| 记录质量 | AI 分析失败、会议记录明细（AIMeetingChunkObj）原文缺失、摘要不足 | 样本可信度、后续补录治理 |

## 情绪判断

| 情绪 | 含义 |
| --- | --- |
| positive | 正向认可、满意、愿意推进 |
| neutral | 中性询问、信息确认、无明显态度 |
| negative | 抱怨、担心、不满、拒绝、卡点 |
| mixed | 同时有认可和顾虑 |
| unknown | 无法判断 |

## 强度判断

| 强度 | 判断标准 |
| --- | --- |
| high | 影响关键推进、上线验收、经营判断，或出现强烈负面/升级信号 |
| medium | 影响局部推进、评估、满意度或后续跟进 |
| low | 一般询问、轻微信号，短期不改变判断 |
| unknown | 证据不足 |

高强度声音至少满足一项：

- 客户明确表示会影响采购、验收、上线或后续推进。
- 客户升级投诉或多次重复反馈。
- 多场会议、多个负责人或多个部门重复出现。
- 关联竞品替代、自研替换、预算冻结或决策延期。
- 会议 AI 失败或原文缺失影响关键判断。

## 证据等级

| 等级 | 来源 | 可进入结论吗 |
| --- | --- | --- |
| E1 | `AIMeetingChunkObj.original_content`、`ActiveRecordObj.active_record_content` 或 `ActiveRecordObj.interactive_content` 中的客户明确原文 | 可以，置信度通常为确认 |
| E2 | `AIMeetingChunkObj.summary`、`AIMeetingObj.remark` 或记录行为反映 | 可以，置信度通常为确认或推断 |
| E3 | 销售观察，且有具体记录内容支撑 | 可以作为推断 |
| E4 | 经验判断、无客户表达证据 | 只能作为待验证假设 |

## 样本偏差提醒

以下情况必须在报告中说明：

- 某部门会议或销售记录明显更多，可能导致声音数量偏高。
- 样本只覆盖部分负责人、会议发起人或内部参与人。
- 当前周期整体销售记录（ActiveRecordObj）或会议记录明细（AIMeetingChunkObj）少，趋势不可靠。
- 某些会议只有摘要、没有原文，客户语气和强度可能失真。
- 会议 AI 分析失败、`fail_reason` 非空或 `ai_status` 异常。
- `ActiveRecordObj.active_record_content` 偏总结，缺少客户原文。
- 只有负面记录被写入 CRM，正向声音可能缺失。

## 输出措辞

推荐写法：

- “会议记录明细（AIMeetingChunkObj）原文显示...”
- “多场会议集中追问...”
- “从会议摘要和 `ActiveRecordObj.active_record_content` 看，预算压力可能上升...”
- “该主题在当前样本中频次较高，但记录来源集中于销售一部，需注意样本偏差。”

避免写法：

- “客户都认为...”
- “一定是产品问题...”
- “销售没有跟进好...”
- “行业客户普遍都有这个痛点...”
