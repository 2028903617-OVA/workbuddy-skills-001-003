# R03 声音主题聚类

## 目标

把抽取出的客户声音归并为少量高价值主题，并直接整理成适合管理层扫读的主题矩阵输入。这个规则的输出服务于固定的模板，不服务于客户逐条明细表。

## 触发条件

完成 R02 客户声音抽取后执行。在 R10 $APPEALS 归类标注完成后，为主题标注 $APPEALS 维度归属。

## 默认主题

| 主题 | 覆盖声音 |
| --- | --- |
| 价值量化 | ROI、效率提升、收入增长、管理改善、可验证结果 |
| 场景贴合 | 功能贴合度、流程适配、行业化、配置能力 |
| 交付体验 | 上线周期、实施资源、培训、验收、项目管理 |
| 系统集成 | ERP、财务、OA、BI、MES、开放接口、生态连接 |
| 预算压力 | 报价、折扣、预算冻结、账号缩减、采购审批 |
| AI 与数据 | 智能分析、自动摘要、预测、数据沉淀、助手能力 |
| 使用效果 | 活跃率、推广难度、数据质量、管理层使用感知 |
| 竞品与替代 | 竞品比较、自研、替换、方案对比 |
| 扩展机会 | 扩部门、扩模块、平台化、更多场景覆盖 |
| 服务响应 | 售后、响应时效、问题处理、服务体验 |

## 分析规则

- 默认输出前 5 到 8 个主题；长尾主题合并到"其他/长尾声音"
- 主题名称必须是管理层可读的业务词，不用过细模型标签
- 每个主题必须直接产出四个字段：
  - `主题`
  - `客户典型表达`
  - `经营含义`
  - `优先动作`
- `客户典型表达` 是多条声音的高保真归纳，不是客户逐条摘录，也不是单个客户流水账
- `经营含义` 必须是经营语言，例如"影响续约""影响扩容""影响内部背书""交付成为规模化瓶颈"
- `优先动作` 必须是管理动作或组织动作，不写成单个销售的临时待办
- 高频不等于高优先级；高强度、跨部门重复、影响经营判断的低频主题也要单列
- 如果证据不足，不强行命名为确定痛点，可写"待验证主题"
- 主题聚类完成后，根据 R10 的 10 主题→$APPEALS 映射表，为每个主题标注 `appeals_dimensions` 字段（包含主维度和次维度）
- $APPEALS 标签作为 YAML 元数据存在，不在主题矩阵表格中新增列
- 在"经营含义"列的输出中可自然提及 $APPEALS 维度（如"交付体验问题集中在 A 保证维度"）

## 禁止输出

- 不输出客户逐条明细表
- 不输出 `客户 / 声音摘要 / 类型 / 情绪 / 强度 / 证据` 这种设计外表格
- 不在本节展开代表性客户原文、证据等级明细、客户名单明细
- 不把一堆原始声音样本直接堆成多行表格
