# R10 $APPEALS 八维映射规则

## 目标

将客户声音原始文本按 $APPEALS 八维模型（价格/可获得性/包装/性能/易用性/保证/生命周期成本/社会接受度）进行归类标注，作为分析引擎的底层分类体系。同时维护用户六维（痛点/期望/不满/认可/竞品/趋势）→ $APPEALS 的映射表，以及现有 10 主题 → $APPEALS 的映射表，作为双层架构的桥梁。

## 触发条件

完成 R02 客户声音抽取后执行。在 R03 主题聚类之前，为每条客户声音标注 $APPEALS 维度归属。

## $APPEALS 八维定义

| 缩写 | 维度 | 中文标签 | 核心问的是什么 | 一句话理解 |
|------|------|---------|-------------|----------|
| **$** | Price | 价格/性价比 | 客户觉得贵不贵？值不值？ | "花这钱值吗？" |
| **A** | Availability | 可获得性/获取便利度 | 客户获取产品/服务容不容易？ | "想用时能用到吗？" |
| **P** | Packaging | 包装/视觉印象 | 产品给人的第一印象如何？ | "看着顺眼吗？" |
| **P** | Performance | 性能/功能/能力 | 功能是否满足需求？ | "能干我想干的事吗？" |
| **E** | Ease of Use | 易用性/使用体验 | 用起来费不费劲？ | "好不好上手？" |
| **A** | Assurances | 保证/可靠性/安全性 | 可不可靠？安不安全？ | "靠得住吗？" |
| **L** | Life Cycle Cost | 生命周期总成本 | 长期用的总成本高不高？ | "后续还要花多少钱？" |
| **S** | Social Acceptance | 社会接受度/口碑 | 行业口碑好不好？别人用不用？ | "别人怎么说？" |

## 关键词归类规则

采用关键词规则引擎 + Prompt 兜底。归类流程：

```
客户声音原始文本
  → 分词/关键词匹配
  ├── 命中 1 个维度 → 标注为该维度
  ├── 命中多个维度 → 标注为所有命中的维度（一条声音可属于多维度，最多 1 主维度 + 2 次维度）
  ├── 命中 0 个维度 → 标记为"未归类"，使用 LLM Prompt 兜底归类
  └── 命中冲突维度 → 按 primary > secondary > patterns 权重排序取 Top2
```

## Prompt 兜底模板

关键词规则未命中时，使用以下 Prompt 进行 LLM 兜底归类：

```markdown
你是一个客户声音分析专家。请将以下客户声音归类到 $APPEALS 八维模型中。

$APPEALS 八维定义：
- $ Price（价格）：客户对价格、性价比、费用的反馈
- A Availability（可获得性）：客户对获取便利度、部署速度、资源可用的反馈
- P Packaging（包装）：客户对界面、视觉、品牌形象的反馈
- P Performance（性能）：客户对功能、能力、速度的反馈
- E Ease of Use（易用性）：客户对操作体验、学习成本的反馈
- A Assurances（保证）：客户对稳定性、安全性、可靠性的反馈
- L Life Cycle Cost（生命周期成本）：客户对长期使用总成本的反馈
- S Social Acceptance（社会接受度）：客户对口碑、行业标准、竞品比较的反馈

客户声音：「{原始文本}」

请输出：
1. 主要 $APPEALS 维度（1-2 个）
2. 次要 $APPEALS 维度（0-2 个）
3. 归类理由（1 句话）
4. 置信度（high/medium/low）

输出格式：
{
  "primary_dimensions": ["E"],
  "secondary_dimensions": ["A"],
  "reasoning": "归类理由",
  "confidence": "high"
}
```

## 用户六维 → $APPEALS 映射表

用户六维是面向用户的查询入口，$APPEALS 八维是底层分析引擎。用户提问时按六维解析意图，按映射表路由到对应 $APPEALS 维度检索分析，输出时映射回用户维度呈现。

| 用户维度 | 定义 | 主要映射 $APPEALS | 映射理由 | 典型问题 |
|---------|------|-----------------|---------|---------|
| **痛点** | 客户自身业务中遇到的困难、摩擦、效率瓶颈 | E 易用性 + A 保证 + P 性能 + L 生命周期成本 | 痛点=客户自身业务之痛，核心是流程卡、效率低、系统不好用、成本高 | "客户业务上最大的痛点是什么？" |
| **期望** | 客户明确想要的功能、服务或能力 | P 性能 + P 包装 + E 易用性 | 期望=想要更多更好更方便，核心是"能不能做"、"能不能更好" | "客户最想要什么功能？" |
| **不满** | 客户对我方产品/服务/关系的负面反馈 | A 保证 + E 易用性 + P 性能 + $ 价格 | 不满=对我方不满意，核心是不稳定、不好用、功能不够、太贵 | "客户对我们有什么不满？" |
| **认可** | 客户对我方的正面评价和价值认可 | P 性能 + A 保证 + P 包装 + L 生命周期成本 | 认可=对我方满意，核心是功能好、靠谱、体验好、长期划算 | "客户认可我们什么？" |
| **竞品** | 和竞争对手相关的所有客户声音 | S 社会接受 + $ 价格 + P 性能 | 竞品比较=别人怎么选，集中在口碑、价格、能力 | "客户怎么看竞品？" |
| **趋势** | 从 VOC 中识别的市场/行业方向 | 全八维 | 趋势是跨客户、跨时间的聚合洞察 | "市场/行业趋势是什么？" |

**维度边界说明**：
- 痛点 vs 期望：痛点是"现在的痛"，期望是"想要的未来"。如"审批慢"→ 痛点，"希望自动审批"→ 期望
- 痛点 vs 不满：痛点是"客户自身业务问题（可能和我方无关）"，不满是"对我方不满意"
- 不满 vs 认可：情感二分，同一个 $APPEALS 维度可能同时有不满和认可
- 流失风险/商务关系恶化：不属于六维，在风险信号模块（R07）中独立呈现

## 现有 10 主题 → $APPEALS 映射表

现有 R03 的 10 个主题在报告输出时名称和格式不变，但在每个主题内部标注 $APPEALS 维度归属。

| 现有主题 | 主要 $APPEALS 维度 | 映射逻辑 |
|---------|-----------------|---------|
| 价值量化 | $ 价格 + L 生命周期成本 | 价值=价格感知+总拥有成本 |
| 场景贴合 | P 性能 + E 易用性 | 场景匹配=功能够不够+好不好用 |
| 交付体验 | A 保证 + A 可获得性 | 交付=质量可靠+及时交付 |
| 系统集成 | P 性能 + A 保证 | 集成=接口能力+稳定性 |
| 预算压力 | $ 价格 | 预算问题=价格敏感 |
| AI 与数据 | P 性能 + S 社会接受 | AI 能力=技术先进性+行业认可 |
| 使用效果 | E 易用性 + P 性能 | 使用效果=好不好用+功能够不够 |
| 竞品与替代 | S 社会接受 + $ 价格 + P 性能 | 竞品=口碑+价格+能力 |
| 扩展机会 | P 性能 + A 可获得性 | 扩展=更多功能+更快获取 |
| 服务响应 | A 保证 + A 可获得性 | 服务=质量保证+及时响应 |

## 归类准确率标准

| 指标 | 目标 |
|------|------|
| 关键词规则覆盖率 | ≥ 70% 的高频声音 |
| 综合归类准确率（关键词 + Prompt） | ≥ 90% |
| Prompt 兜底占比 | ≤ 30% |

**准确率测量方法**：随机抽样 200 条分类结果，两名标注员独立评分，Cohen's Kappa > 0.6 且简单一致率 > 70%。

## 分析规则

- 一条声音可同时属于多个 $APPEALS 维度，但最多标注 1 个主维度 + 2 个次维度
- 关键词匹配优先级：primary > secondary > patterns
- 关键词规则未命中的声音必须走 Prompt 兜底，不可标记为"未归类"后跳过
- Prompt 兜底归类置信度为 low 时，标注为"待验证"，不进入结论输出
- $APPEALS 维度标注结果服务于 R03 主题聚类和 R08 报告组装，不直接暴露给用户
- 用户看到的是六维（痛点/期望/不满/认可/竞品/趋势），$APPEALS 是底层标签
- 归类统计结果用于报告总览表中各维度的提及率、情感比、风险等级计算
- 客户流失风险信号不在本规则中处理，由 R07 风险与机会规则独立识别

## 禁止输出

- 不向用户直接展示 $APPEALS 维度标签（除非用户主动问"这个结论是基于什么维度分析的"）
- 不把关键词规则匹配结果作为最终结论输出，规则匹配只是分类预处理
- 不在一条声音上标注超过 3 个维度（1 主 + 2 次）
- 不把 Prompt 兜底置信度为 low 的归类结果作为确定结论

## Markdown 输出

本规则不直接输出面向用户的 Markdown。$APPEALS 归类结果作为元数据注入 R03 和 R08 的输出中。在 R08 报告的总览表中，各维度行可自然提及 $APPEALS 归类依据：

```markdown
<!-- R08 报告总览表中每维度行的参考格式 -->
| 维度 | 提及率 | 情感 | 风险等级 | 趋势 |
|------|-------|------|---------|------|
| 不满 | 12/18 客户 (67%) | 负面 60% | 🔴 高风险 | ↗ 上升 12% |
```

在 Q&A 模式的输出中，可在"维度归类"段落自然提及 $APPEALS 维度：

```markdown
<!-- Q&A 输出中维度归类段落的参考格式 -->
**$APPEALS 维度归类**：不满主要集中在 A 保证（40%）和 E 易用性（27%）
```
