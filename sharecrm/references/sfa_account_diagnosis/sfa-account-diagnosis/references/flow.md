# 客户经营洞察流程

## 场景目标

对一个明确的客户对象进行客户经营洞察，围绕五个经营判断问题输出结果：客户当前状态、真实关注点、组织突破口、增长空间与经营建议。

当前场景采用“主 skill + references 框架”模式：
- 主 `SKILL.md` 负责对象边界、评分依赖与输出硬约束。
- 本 `flow.md` 负责流程编排、内部分析视角和必读 references 组织。
- `output_template.md` 负责输出结构模板。

## 输入要求

优先识别以下信息：

- 客户名称或 `客户ID`
- 对象类型是否为 `AccountObj`
- `Scoring_Result`
- `sfa-account-due-diligence-report` 结构化结果
- 当前洞察意图

说明：

- 客户对象事实与关联数据由 `data-query.md` 负责约束查询范围。
- `sfa-account-due-diligence-report` 为默认强制输入；已提供时优先消费，未提供时必须通过 `read_skill` 编排调用，不得以任何理由跳过调用。调用失败不阻断，但必须标注增强缺失。
- `Scoring_Result` 的依赖强度仍以主 `SKILL.md` 当前规则为准；本 `flow.md` 不负责放宽或加强降级策略。
- `AI_Stage` 在本 skill 内根据客户主数据、关联商机、联系人和销售记录直接生成；证据不足时输出“信息不足”，不阻断洞察。
- 本 `flow.md` 不负责覆盖 Markdown 输出、概要简洁或风险分级等主技能硬规则。

## 内部分析视角

本场景内部包含三个连续分析视角：

### 视角A：客户当前状态判断

作用：

- 形成客户当前经营状态的整体判断
- 输出完整五模块洞察骨架
- 结合评分结果与对象事实形成整体经营状态结论

### 视角B：客户真实关注点与组织突破口

作用：

- 收敛客户当前关注点、深层驱动、当前约束与突破口
- 强化客户真实经营主题的可读性

### 视角C：增长空间与下一步经营

作用：

- 将前面识别出的短板与机会转成经营策略和行动建议
- 明确“下一步怎么经营”

这三个视角不是互斥关系，不做三选一。
这三个视角仅用于内部分析和推理顺序，不替代最终输出章节。
最终输出仍固定为：页头摘要、客户当前状态、客户真实关注点、组织突破口、增长空间、经营建议，以及附加的经营风险提示。
标准执行时默认顺序为：

1. 先做客户当前状态判断
2. 再提炼客户真实关注点与组织突破口
3. 最后输出增长空间与经营建议

## 执行步骤

1. 读取 `global-diagnosis-criteria.md`。该文件已按 `output_template.md` 章节顺序内聚客户当前状态、真实关注点、组织突破口、增长空间、经营建议与经营风险提示的诊断标准；无需再分别加载拆分规则文件。
2. 检查 `sfa-account-due-diligence-report` 结构化结果是否已提供；若未提供，必须通过 `read_skill` 调用该 skill，并按客户名称获取客户尽调结构化结果，作为外部情报增强层。不得以流程较长、外部情报只是增强项或不影响主诊断为由跳过。若调用失败或无结果，标注增强缺失并继续执行。
3. 按主 `SKILL.md` 规则先查询 `get_profile_score --objectApiName AccountObj`；CLI 不可用时回退 `sfa-account-score`，校验选定的 `Scoring_Result`，再直接生成 `AI_Stage`。
4. 先执行客户当前状态判断，结合 `Scoring_Result`、内部生成的 `AI_Stage`、客户事实和销售记录形成整体经营状态结论。
5. 再提炼客户真实关注点，总结表面关注点、深层驱动、当前约束和我方当前错位；若有尽调结果，则优先用其补足业务重点、行业背景和外部压力。
6. 再结合关键角色、关系网络与在手机会状态，判断当前组织与关系突破口。
7. 再从全局短板、关键角色覆盖情况、商机活跃度和经营管理风险中识别 `P0 / P1 / P2` 风险。
8. 然后判断当前客户的增长空间，包括扩展方向、复制可能性和是否值得追加投入；若有尽调结果，则优先补充分支机构、关联主体、产业链位置和合作格局带来的扩展空间。
9. 最后基于上述判断生成经营策略与行动建议。
10. 读取 `output_template.md`，按“页头摘要 + 五个经营判断模块 + 经营风险提示”固定结构输出结果。

## 输出要求

- 必须同时覆盖当前状态判断、真实关注点、增长空间和下一步经营三个视角。
- 必须显式说明 `Scoring_Result` 的完整度，并说明内部生成的 `AI_Stage` 及其证据充分度。
- 必须给出“页头摘要 + 五个经营判断模块 + 经营风险提示”。
- 必须将风险标为 `P0 / P1 / P2`。
- 页头摘要部分保持摘要式，不拆成“事实 / 判断 / 待确认问题”。
- 客户当前状态部分继续显式区分“事实 / 判断 / 待确认问题”。
- 必须说明行动建议对应的经营问题、目的和预期解决问题。
- 最终输出必须是 Markdown。
