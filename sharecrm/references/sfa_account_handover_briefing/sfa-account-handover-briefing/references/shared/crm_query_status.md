# CRM 查询状态统一口径

本文件定义所有客户简报和周日报的数据覆盖状态。输出报告时必须区分“没有数据”和“没能读取”。

输出给用户时，数据覆盖和参考来源只使用中文业务标签，不展示对象 apiName 或字段 apiName。对象 apiName 仅用于内部查询计划、CLI 参数和技术排查。

## 状态定义

| 状态 | 含义 | 可写入报告的表达 |
| --- | --- | --- |
| 已读取 | 查询成功且返回至少 1 条可用记录 | 可作为 CRM 事实使用 |
| 无数据 | 查询成功但返回 0 条记录 | “本次查询未查到相关记录” |
| 权限不足 | 对象、字段、列表或数据权限不足 | “权限不足未读取”，不得推断没有数据 |
| 未触发查询 | 不满足触发条件，或用户未要求 | “未触发查询”，不得写成无数据 |
| 查询失败 | 网络、接口、字段不支持、命令失败等非权限错误 | 写明失败类型并降低置信度 |

## 使用规则

- 权限不足不是无数据。
- 未触发查询不是无数据。
- 查询失败不是无数据。
- 查询成功但 0 条，只能说明当前查询条件下未查到，不代表现实中不存在。
- 同一对象本轮已经权限不足或不可恢复失败，不要重复查询。
- 依赖对象未定位时，不查询下游对象；例如客户未确认前不查商机、联系人、销售记录。

## 数据覆盖摘要格式

客户简报建议格式：

```markdown
> 数据覆盖：客户 {状态}；商机 {状态}；联系人 {状态}；销售记录 {状态}；需求 {状态}；互动问题 {状态}；会议 {状态}；待办 {状态}；订单/回款 {状态}。
```

见客前简报可压缩为：

```markdown
> 数据覆盖：客户 {状态}；商机 {状态}；联系人 {状态}；跟进记录 {状态}；日程 {状态}；需求/问题 {状态}；竞品明细 {状态}。
```

高层陪访简报可压缩为：

```markdown
> 数据覆盖：客户 {状态}；商机 {状态}；联系人 {状态}；互动记录 {状态}；会议 {状态}；竞品明细 {状态}；历史财务 {状态}。
```

交接简报可压缩为：

```markdown
> 数据覆盖：客户 {状态}；商机 {状态}；联系人 {状态}；跟进记录 {状态}；待办/任务 {状态}；需求/问题 {状态}；会议 {状态}；竞品明细 {状态}；订单/回款 {状态}；外部情报 {状态}。
```

## 降级生成规则

当关键对象无法读取时：

- 保留报告结构。
- 对相关判断标注“未知”或“推断”。
- 把缺失对象写入“开放问题 / 陪访缺口 / 交接缺口 / 数据缺口”。
- 不编造金额、阶段、联系人、会议结论、承诺状态或回款情况。

## 冲突处理

CRM、Memory、用户输入或会议纪要冲突时：

- 不直接二选一。
- 优先保留 CRM 可确认事实和用户明确补充。
- Memory 和会议纪要可作为上下文证据，但要标注需核对。
- 在报告中写“需核对”，并说明建议核对来源。
