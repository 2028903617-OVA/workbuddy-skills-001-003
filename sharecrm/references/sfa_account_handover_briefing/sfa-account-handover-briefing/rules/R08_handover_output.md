# R08 交接简报输出

## 目标

把 R01-R07 的分析结果组装成接手人可直接阅读的团队交接简报。必须先给结论摘要，再展开证据和细节；Markdown 正文必须先在对话中直接输出，`.md` 文件只是归档物，不能替代对话内正文；Markdown 完成后必须同步生成同内容 HTML 展示版。

## 触发条件

完成 R01-R07 后始终执行。`--full` 模式或客户存在历史合作、合同、订单、回款、客户健康记录时，再合并 R09。

## 输出顺序

1. 接手人必读摘要。
2. 交接背景。
3. 客户画像。
4. 博弈编年。
5. 关系温度与关键人地图。
6. 待兑现承诺。
7. 风险与敏感点。
8. 竞品历史。
9. 接手建议。
10. 历史合作、财务与客户健康，仅 `--full` 输出。

## 摘要规则

- 第一屏必须让接手人知道：当前状态、最大历史包袱、最关键关系、最高风险、第一周重点。
- 摘要只写结论，不堆字段。
- 每个关键结论必须标注置信度：确认、推断、未知。
- Memory 不足时，不展示技术状态；将“关键历史与关系信息待补充”放入交接缺口或第一周核对事项，必要时同步进入最高风险。
- 有高风险、逾期承诺、竞品 C3/C4、回款/交付/投诉风险时，不能在摘要里弱化。

## 接手建议规则

接手建议必须按“第一周可执行”组织，至少包含：

- 第一优先级：先补哪类信息。
- 联系顺序：先找原 AE、CSM、售前、实施、客户 Coach、客户关键人中的谁。
- 不能做什么：哪些话不能说、哪些人不能绕、哪些历史不能假装不知道。
- 需要原 AE 当面交代的问题。
- 下一次客户沟通前必须确认的事实。

## 数据来源显示规则

- 数据覆盖、参考来源、HTML 页脚和正文弱引用必须使用中文业务标签，不展示对象 apiName、字段 apiName 或 query plan。
- 内部查询到的 `AccountObj` 显示为“客户”，`NewOpportunityObj` 显示为“商机”，`ContactObj` 显示为“联系人”，`ActiveRecordObj` 显示为“跟进记录”。
- `ActivityTodoObj`、`MethodologyTaskObj` 显示为“待办/任务”；`RequirementObj`、`ActivityQuestionObj` 显示为“需求/问题”；`ScheduleObj`、`AIMeetingObj`、`AIMeetingChunkObj` 显示为“会议”。
- `CompetitiveLinesObj` 显示为“竞品明细”；`ContractObj`、`SalesOrderObj`、`PaymentObj` 显示为“合同/订单/回款”；外部风险、新闻、招投标、工商等 CLI 显示为“外部情报”。
- 如果权限不足、查询失败或未触发查询，只写“权限不足未读取 / 查询失败 / 未触发查询”，不得写成没有数据，也不得展示原始 apiName。

## 输出契约

交付顺序固定为：先在对话中直接输出 Markdown 格式化正文，不包进代码块，也不要只提供 `.md` 文件或路径；如果运行环境允许写文件，再写出 `.md` 归档文件；随后把同一组事实整理为 `handover_facts_bundle.json`，并调用 `scripts/render_handover_briefing.py` 输出 HTML。HTML 只做展示层，不改变交接事实、置信度、风险和接手建议；视觉样式沿用 0703 团队交接简报，桌面端使用顶部信息栏、卡片分区和分页标签，移动端自适应降为单列。页签固定为“概览、历程与竞争、交接备注、数据质量”，数据质量作为最后一个独立页签，不在每个业务页签重复展示。移动端顶部必须高度自适应并允许长文本换行，分页标签独立吸顶，不依赖固定头部高度。渲染器自动内联 CSS 并调用 `scripts/validate_handover_briefing.py`；校验失败时不得交付。校验通过的 HTML 和 `.md` 归档文件通过系统附件交付，不要在回复正文中输出“文件已生成”、文件名、文件路径或 Markdown/HTML 文件清单；只有用户明确说“只要 Markdown、不要 HTML、不用网页、不生成 HTML”时，才允许只交付 Markdown 正文和可选 `.md` 归档文件。

生成 HTML 前必须读取 `references/html_render_contract.md`。正式 HTML 必须保留模板标识 `sfa-account-handover-briefing-v1`；不得手写整份 HTML、重新设计 DOM、分别生成桌面端与移动端事实，或保留示例客户、示例人员、空占位符、外部 CSS 依赖和 apiName。数据覆盖、参考来源、置信度说明和数据截止必须保留；内部记忆能力及读取状态不得进入用户可见区域。

HTML 片段全部由渲染器从结构化事实生成，agent 不传入原始 HTML。标准模式不输出历史合作、财务与客户健康卡片；`--full` 才输出该卡片。无数据时保留必要模块并写“未知/待核对/暂无记录”，不要留空。交接质量信号只能使用定性状态，不得编造交接准备度百分制；关系温度可继续使用 R04 已定义的 `-5` 到 `+5`。

## 语言规则

- 使用 CRM、销售管理领域专业术语：商机阶段、关键人、Coach、Gatekeeper、EB/TB/UX、承诺、回款、应收、客户健康、续约、增购、流失风险。
- 事实和建议分开写；推断必须标注置信度。
- 外部风险只作为接手提醒，写入风险敏感点、交接缺口或第一周核对事项；不要新增外部情报、新闻或工商风险章节。
- 外部情报与内部事实冲突时，不覆盖内部事实，写入接手后需核对事项。
- 查询失败、权限不足、未触发查询导致的关键缺口必须进入交接缺口；不要把未读取误写为无风险。
- 不写“关系良好，继续维护”这类空话。
- 不输出见客前简报语言：今日目标、P0/P1/P2、确认出发、见客就绪度、今天必须守住。
- 不使用营销式大词替代客户事实。
- Markdown 正文、Markdown 归档文件与 HTML 展开版是默认交付形态；不要额外包装成无关附件或文件卡片，也不要用文件路径替代正文。
