# 见客前客户简报

## 技能元信息

- 参数提示：`[客户名称] [--style=lite|normal|full]`
- 版本：`2.0.0`
- 更新时间：`2026-07-15`

## 目标

为 AE 在见客户前生成一份短、准、能指导行动的客户简报。简报必须帮助 AE 回答：

- 今天这场会怎么打，最先抓什么？
- 今天这场会的主要目标是什么？
- 当前见客就绪度是多少，最大信息缺口是什么？
- 今天必须守住哪些风险？
- 今天要影响谁、绕开谁、借力谁？
- 现场应该问哪句话、做哪个动作？
- 哪些历史转折影响今天，必要时如何查看完整博弈明细？
- 拜访结束后由谁在什么时间前完成哪些动作？

默认先在对话中直接输出结构化 Markdown 简报正文，再基于同一内容生成 HTML 展示版。Markdown 文件只是归档物，不能替代对话内正文；HTML 只负责排版和分享预览，不改变事实、判断、置信度或行动建议。HTML 展示版和 `.md` 归档文件通过系统附件交付；不要在回复正文中输出“文件已生成”、文件名、文件路径或 Markdown/HTML 文件清单。

## 适用场景

使用本技能处理：

- 单客户见客前准备。
- CRM 触发的“即将拜访”或“准备出发”场景。
- `/briefing [客户名]`、`/briefing [客户名] --style=lite|normal|full`。
- 用户要求见客就绪度、决策链、人力地图、会议底线、风险预警、博弈编年、今日行动建议或拜访后行动清单。

不要用于：

- 团队交接或 AE 工作移交。
- 高层陪访、领导汇报或升级汇报。
- 客户组合盘点、团队周报、销售经理 review。
- 完整首访/复访策略、调研会问题体系或访谈节奏设计；交给 `first-visit-strategy`。
- 深度需求穿透、痛点还原或预算三层穿透；交给 `needs-discovery`。
- 完整决策链诊断、EB/Sponsor识别或隐性权力中心判断；交给 `decision-chain`。
- Coach识别、分级和培养；交给 `coach-development`。
- 单商机竞品攻防；交给 `competition-intel`。
- 会后记忆更新作为主任务，除非用户明确要求在简报后更新 memory。简报中的“拜访后行动清单”只是预先规划，不代表已自动写入 CRM 或 memory。

本技能负责生成见客前行动简报，可以汇总客户事实、风险、决策链、竞品、需求和商机信息，但不做深度业务诊断。用户要完整首访策略转 `first-visit-strategy`，要需求诊断转 `needs-discovery`，要决策链诊断转 `decision-chain`，要Coach经营转 `coach-development`，要竞品攻防转 `competition-intel`。

## 需要获取的信息

必需：

- 客户名称或 CRM 客户 ID。
- 会议上下文：今天见谁、会议目的、当前商机阶段。

优先获取：

- CRM 中的客户、商机、联系人、最近跟进记录。
- 用户明确要求外部动态，且该动态会影响本次会议目标、风险或现场提问时，再补充客户近期外部情报。
- `memory/customers/[客户名称]/` 下的客户长期记忆。

如果无法识别客户，或 CRM 查询到多个候选客户，先让用户确认，不要直接生成简报。

## 数据优先级

按以下顺序使用证据：

1. 用户提供的会议上下文和 CRM 基础对象：`AccountObj`、`NewOpportunityObj`、`ContactObj`、`ActiveRecordObj`。
2. 见客前广覆盖对象：`ScheduleObj`、`RequirementObj`、`ActivityQuestionObj`、`ActivityTodoObj`、`MethodologyTaskObj`、`AIMeetingObj`、`AIMeetingChunkObj`、`CheckinsObj`。确认客户后尽量轻量读取，用于参会人、会议背景、需求、异议、承诺、待办、会议纪要和现场触达。
3. 客户 memory 文件：只提取影响本次见客的历史、关系、承诺和敏感点。
4. 竞争、历史合作与财务：`CompetitiveLinesObj`、`ContractObj`、`SalesOrderObj`、`PaymentObj`。能确认对象和字段且有权限时尽量轻量读取；无数据、权限不足或查询失败必须进入数据覆盖，不得写成“没有竞品/没有合作/没有回款”。
5. 外部情报，仅在用户明确要求，或近期新闻、舆情、招投标、突发风险会影响当前会议打法时使用。
6. 行业基准和竞品参考。
7. 明确标注的推断。

不要用外部情报或推断覆盖 CRM 事实。所有推断必须标注置信度：`确认`、`推断` 或 `猜测`。

## 数据处理流程

1. 识别客户记录。
   - 需要从 CRM 查询时，先读取 `references/shared/sharecrm_cli_min_loop.md`，再按需读取 `references/cli_reference.md`，按企业 CLI 规范查询并确认唯一客户记录。
   - 在执行查询前形成内部 `query_plan`：优先确认客户、商机、联系人、最近跟进记录；确认唯一客户后，对会前相关对象执行广覆盖轻量读取，并为每类数据记录状态。
   - 如果有多个候选客户，要求用户选择。

2. 拉取关联 CRM 数据。
   - 先读取 `references/shared/report_data_sources.md` 判断本次数据源；见客前简报采用“广覆盖、轻量读取、行动收敛”的数据策略。
   - 先完成 metadata plan：只 describe 本次需要对象；同一对象本轮只 describe 一次，并只选择已确认字段，不猜字段 apiName、对象 apiName 或枚举值。
   - 再完成 identity plan：客户、商机、联系人、员工、部门等引用过滤必须先解析为 `_id`。
   - 客户：名称、行业、规模、状态、来源、最后跟进时间。
   - 商机：阶段、金额、赢率、预计结单日期、状态、竞品、预算状态。
   - 跟进记录：最近 3-5 次互动、结论、情绪、承诺。
   - 联系人：姓名、职务、关键联系人标记、可能的 EB/TB/UX/Coach/Gatekeeper。
   - 会前广覆盖：尽量轻量查询 `ScheduleObj`、`RequirementObj`、`ActivityQuestionObj`、`ActivityTodoObj`、`MethodologyTaskObj`、`AIMeetingObj`、`AIMeetingChunkObj`、`CheckinsObj`，只提取影响今日目标、风险、人力地图、第一句话和 P0 动作的信息。
   - 竞争、历史合作与财务：尽量轻量查询 `CompetitiveLinesObj`、`ContractObj`、`SalesOrderObj`、`PaymentObj`，用于竞品压力、续约/增购、回款风险、历史合作包袱；`full` 模式可展开更多明细。
   - 查询状态必须按 `references/shared/crm_query_status.md` 区分：`已读取`、`无数据`、`权限不足`、`未触发查询`、`查询失败`。权限不足不是无数据，不得据此断言没有商机、联系人、跟进、日程、需求、待办或竞品。
   - 同一对象出现权限不足或不可恢复错误后，不要在本轮反复查询同一对象；继续基于已获得数据降级生成简报。
   - 广覆盖对象完成一次轻量读取或明确状态后停止；缺失项进入最大缺口和数据覆盖摘要，不为了填满章节反复 loop 或展开全量明细。

3. 读取客户记忆。
   - 如存在，读取 `memory/customers/[客户名称]/`。
   - 只有在会后沉淀、创建客户记忆或解释记忆结构时，才读取 `memory/template.md`。
   - 读取 memory 时只提取会影响本次见客的事实：决策链变化、痛点证据、承诺兑现、竞品阶段、预算/审批风险、必选条件。

4. 补充外部情报。
   - 只有用户明确要求外部动态，或今天会议目标依赖近期新闻、舆情、招投标、突发风险时，读取 `references/shared/external_intelligence_sources.md`。
   - 默认最多 1 次外部情报查询；如果采购窗口或重大风险已经明确触发，最多 2 次。
   - 优先在 `market get-news` 与 `market search-mentions` 中择一；采购窗口明显时用 `market bidding-pinganzhengxin`；重大外部风险才用 `risk conc`。
   - 外部情报只转化为会前预警、现场验证问题或“绝对不要做”，不要扩成长篇企业背景，不覆盖 CRM 客户、商机、联系人和承诺事实。
   - 外部情报状态记录为：`已读取 / 无数据 / 权限不足 / 未触发查询 / 查询失败`。

5. 按输出深度加载规则。
   - `lite`：`rules/R01_customer_basics.md`、`rules/R05_ready_score.md`、`rules/R06_brief_output.md`、`rules/R07_game_timeline_follow_up.md`、`rules/R08_pragmatic_style.md`。
   - `normal`：按需读取 `rules/R01_customer_basics.md`、`rules/R02_decision_chain.md`、`rules/R03_pain_points.md`、`rules/R05_ready_score.md`、`rules/R06_brief_output.md`、`rules/R07_game_timeline_follow_up.md`、`rules/R08_pragmatic_style.md`；仅在存在竞品数据或竞品信号时读取 `rules/R04_competitive.md`。
   - `full`：normal 模式规则，再加 `rules/R09_history_financial.md` 和相关 references。

6. 计算见客就绪度。
   - 若数据可结构化，优先使用 `scripts/calc_ready_score.py`。
   - 若数据不完整，可定性计算，但必须列出导致扣分的缺失字段。

7. 生成简报。
   - 默认先在对话中直接输出 Markdown 格式化正文，不包进代码块，不只提供 `.md` 文件或路径；随后生成同内容 HTML 展示版。
   - 先输出结构化“会前判断”，明确拜访目标、最大风险、推荐打法和最关键的人；不要用超大字号的一句话判断代替结构。
   - 再展开身份标签、决策锚、预警、就绪度、人力地图和行动。
   - `normal` 默认输出轻量人力地图；仅在老客户、续约/增购、多轮跟进、竞品介入、历史承诺反复或用户要求时输出“博弈编年”。HTML 在同一页签内提供“摘要 / 明细”切换，明细字段和筛选规则按 `rules/R07_game_timeline_follow_up.md`。
   - 所有模式都输出“拜访后行动清单”：`lite` 只保留 1 项会后必做，`normal/full` 输出 3-5 项。清单必须是计划，不得伪装为已经执行。
   - 使用少量 emoji 强化扫读，优先放在一级模块标题和关键状态上，不要给每行都加装饰。
   - 正文不逐条展示“来源/依据”，数据来源说明统一用弱引用格式放在简报最后。
   - 最后一个“数据质量”页签必须保留参考来源、置信度说明和数据覆盖摘要，说明客户、商机、联系人、跟进记录、日程、需求/问题、会议、待办/任务、现场拜访、竞品明细、合同、订单/回款、外部情报分别是已读取、无数据、权限不足、未触发查询或查询失败。
   - 生成 HTML 前必须读取 `references/shared/html_output_quality_gate.md`、`references/html_render_contract.md` 和 `rules/R06_brief_output.md`；Markdown 正文和 HTML 必须来自同一份 `pre_visit_facts_bundle`。
   - 必须调用 `scripts/render_pre_visit_briefing.py` 生成 HTML；不得手写完整 HTML、重新设计 DOM，或把 `assets/templates/visit.html` 仅当作视觉参考。
   - 正式 HTML 必须保留 `sfa-pre-visit-briefing-v2` 模板标识，并自动通过 `scripts/validate_pre_visit_briefing.py`；校验失败时不得交付。
   - 固定使用中文顶部栏、结构化会前判断、环形就绪度、四项关键命令条、双行动看板和横向页签；移动端自动单列，页签可横向滑动。
   - 用户可见来源只写中文业务标签，不显示对象或字段 apiName。
   - 校验通过的 HTML 和 `.md` 归档文件通过系统附件交付；不要在回复正文中输出“文件已生成”、文件名、文件路径或 Markdown/HTML 文件清单。

## 资源路由

- 需要判断本次该查哪些对象和触发补查条件时，读取 `references/shared/report_data_sources.md`。
- 需要从 CRM 拉取客户、商机、联系人、跟进记录、日程、需求、互动问题、待办/任务、会议记录、现场拜访、合同、订单、回款、CSM 预警、流失原因或竞品明细时，先读取 `references/shared/sharecrm_cli_min_loop.md`，再按需读取 `references/cli_reference.md`。
- 需要统一数据覆盖状态、权限不足和降级生成口径时，读取 `references/shared/crm_query_status.md`。
- 需要补充近期新闻、舆情、招投标、突发风险或其他影响本次会议的外部动态时，读取 `references/shared/external_intelligence_sources.md`。
- 生成 HTML 展示版前，读取 `references/shared/html_output_quality_gate.md`。
- 需要整理 HTML 输入字段和调用固定渲染器时，读取 `references/html_render_contract.md`。
- 仅在需要把原始 CRM 输出或用户粘贴的 CRM 文本映射到 R01-R05 字段时，读取 `references/crm_schema.md`。
- 仅在需要行业基准、财务阈值、采购周期或采购时机判断时，读取 `references/industry_benchmarks.md`。
- 仅在已知、疑似或用户明确讨论竞品时，读取 `references/competitive_reference.md`。
- 仅在 `full` 模式或用户要求历史订单/回款分析时，读取 `rules/R09_history_financial.md`。
- 其他简报场景的归档素材已移至 `../shared_briefing_assets/out_of_scope_briefing_templates/`，正常见客简报不要加载。

`lite` 模式：

`full` 模式：

- 在主简报之后补充完整决策链、人力地图、博弈编年明细、关键转折点、时间线缺口、痛点矩阵、竞品分析、历史财务信号和拜访后行动清单。
- 第一段主简报仍必须简短，确保 AE 一分钟内能读完。

## 务实表达规则

- 用具体会议语言，不用抽象战略话术。
- 不把“赋能”“数字化转型”“智慧化”“生态”作为主切入点。
- 每条行动建议都要有 5 分钟内能验证的标准。
- 痛点叙事必须包含具体场景，或给出可现场验证的问题。
- 竞品定位只能说“在这个场景下我们更合适”，不要说“我们更好”。

当结论没有直接证据支撑时，在正文中使用轻量推断标记，不展开逐条来源：

```markdown
推断：{claim}（置信度：推断/猜测）
验证问题：{AE今天可以问客户的一句话}
```

证据类型统一收口到简报末尾的“数据质量”页签中的参考来源弱引用，不要打断主简报阅读。

## 失败处理

- 客户定位必须按 `references/cli_reference.md` 的确定性优先级执行：已有 CRM 客户 `_id` 时直接 `get-by-id` 或 `query-by-fields --_id-eq`，不要再做名称解析；用户提供客户编号时，用 `--account_no-eq` 精确查询；只有缺少 ID 和编号时，才用 `query-by-fields --name-like` 做客户名称模糊查询。不要把 `query-by-name` 当作客户名称字段的模糊查询入口。
- 客户查询未命中时，再补充 `query-by-name` 做简称/别名/实体归一；仍未命中时，只能说明“当前查询条件下未查到该客户”，不要断言“CRM 中没有该客户记录”。如果用户截图显示网页 CRM 存在，应提示核对查询字段、客户编号、列表页筛选条件、数据权限或名称索引同步状态。
- 如果按 `_id` 能查到、但按具体名称查不到，必须以 ID 查询到的客户记录为准继续生成简报，并在数据覆盖中标注“名称查询未召回，已按 ID 读取”。
- 客户查询返回多个候选时，必须让用户选择；不要因为候选名称不完全等于用户输入，就自行判定没有目标客户。
- 查询关联商机、联系人、跟进记录时必须使用 `references/cli_reference.md` 中确认的对象和字段：关联客户字段用 `account_id`，商机对象用 `NewOpportunityObj`。不要把字段猜成 `accountId`、`_accountId`，也不要把商机对象改成 `SalesOpportunityObj`。
- 关联对象权限不足时，明确标注“权限不足未读取”，不要写成“无商机/无联系人/无跟进记录/无竞品”。
- 没有近期跟进记录时，降低信息完整度，并把 P0 行动设为“重建上下文”。
- EB 不明确时，不要假设预算拍板人；把识别 EB 作为今日目标。
- 痛点只有行业假设支撑时，标注为假设，并给出验证问题。
- 见客就绪度低于 40 时，建议缩小会议目标或延期；除非用户明确说明会议不能改期。

## 会后记忆更新

用户要求“更新记忆”“记录本次拜访”“沉淀到 memory”时，读取 `memory/template.md`，只记录会影响下次见客的信息：

- 决策链：EB、Coach、Gatekeeper、TB、UX 的新增或变化。
- 痛点：客户原话、证据等级、产品匹配度、下次验证问题。
- 承诺：我方或客户承诺、截止日期、兑现状态。
- 风险：预算、审批、竞品、必选条件、交付或回款风险。
- 下次提醒：下次见客前必须守住的 1-3 件事。

不要把完整会议纪要塞进 memory；CRM 已有事实不重复写，除非需要标注“下次见客必须提醒”。
