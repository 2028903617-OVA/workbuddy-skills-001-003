# R06 见客简报输出

## 目标

把 R01-R05 和 R07 的分析组合成最终见客前简报。本规则不引入新事实，只负责筛选、压缩和转化为结构化会前判断、会议动作与拜访后行动。

## 触发条件

R05 完成后始终执行。

## 输入依赖

- R01：客户/商机基础信息和即时风险。
- R02：决策链和角色缺口。
- R03：首选痛点、验证问题、必选条件。
- R04：竞争态势和场景化竞品话术。
- R05：见客就绪度和最大缺口。
- R07：博弈编年摘要/明细和拜访后行动清单。
- Memory：只使用已经读取过的客户事实。

## 输出长度

- `lite`：8-12 行。
- `normal`：核心主简报一屏内，目标 650 个汉字以内；末尾弱引用不计入主体。
- `full`：先输出 normal 简报，再追加展开内容。

第一段主简报必须保证 AE 一分钟内读完。

## 视觉扫读规则

- 默认使用少量 emoji，优先放在模块标题和关键状态上，帮助 AE 在移动端快速定位。
- 推荐模块 emoji：`🧭 会前判断`、`🪪 身份标签`、`🎯 决策锚`、`⚠️ 预警`、`📊 就绪度`、`👥 人力地图`、`📅 博弈编年`、`✅ 今日行动`、`☑️ 拜访后行动`、`🧪 数据质量`。
- 不要在每个字段、每个风险或每条行动前都加 emoji；正文以销售动作和风险判断为主。
- 风险等级可使用 `🔴/🟡/🟢`，但必须服务于严重度判断，不作为装饰。

## 会前判断规则

- 会前判断必须放在简报最顶部，先给现场打法，再展开证据。
- 不用超大字号的一句话判断承担全部信息；一句话概括只作普通正文摘要。
- 结构化判断恰好保留 4 项：拜访目标、最大风险、推荐打法、最关键的人。
- “第一句话/第一个问题”必须是 AE 可以直接照着问的现场语言。
- 会议底线和“绝对不要做”放在结构化判断之后，不能与推荐打法混写。
- “绝对不要做”必须是明确禁忌动作，不写成泛泛提醒。
- 会前判断不新增事实，只从 R01-R05 中抽取最关键判断。
- 正文不逐条展示 `来源：...` 或 `依据：...`；证据口径统一放到末尾弱引用区。

## HTML 结构与防重叠规则

Markdown 简报完成后，必须同步生成 HTML / 移动端展示版。Markdown 正文必须先在对话中直接输出；`.md` 文件只是归档物，不能替代对话内正文。HTML 必须由固定渲染器生成：

1. 读取 `references/html_render_contract.md`。
2. 把 Markdown 使用的同一组事实整理为 `pre_visit_facts_bundle.json`。
3. 调用 `python3 scripts/render_pre_visit_briefing.py --input <facts.json> --output <briefing.html>`。
4. 只有脚本返回 `Rendered and validated` 时才允许交付。

不得手写完整 HTML，不得把 `assets/templates/visit.html` 仅当作视觉参考，也不得复制附件后重新设计。正式 HTML 必须保留 `data-template-id="sfa-pre-visit-briefing-v2"` 和以下固定结构：

- 使用 `assets/templates/visit.html` 的内联 CSS 单文件模板，不依赖外部 CSS、脚本、字体或图片。
- 首屏顺序固定为：中文顶部简报栏 → 普通字号的局面摘要与第一句话 → 环形综合就绪度 → 4 项结构化会前判断 → 会议底线/禁忌 → 20 秒预警与今日打法双看板。
- normal/full 在首屏后展示信息完整度、痛点匹配度、竞争风险度三个分项，再用横向页签承载人力地图、条件博弈编年、痛点矩阵、拜访后行动和最后的数据质量页签；博弈编年在同一页签内提供“摘要 / 明细”分段切换；full 追加竞品分析、历史合作与财务。
- lite 不输出分项评分和横向页签，但保留一个独立的会后必做和精简来源区。
- 不要改为左侧目录、深色运维看板或自由卡片布局。
- 视觉风格以浅色 SaaS 工作台为主：白底、浅灰边线、克制阴影、少量品牌黄作为强调；不要使用脏橙/棕色大面积背景。
- 不使用固定高度承载动态内容；顶部栏、会前判断、预警横幅、博弈明细和会后清单都必须由内容自然撑开。
- 不使用绝对定位叠放正文、就绪度、主题切换或徽章；不要输出固定底部按钮，避免遮挡主体内容。
- 顶部简报栏只放客户、会议场景和关键标签；长字段允许换行，不能压缩到覆盖下一行。
- 关键命令条恰好保留 4 项：拜访目标、最大风险、推荐打法、最关键的人；会议底线和绝对不要做放在命令条下方，不占第五项。
- 桌面端主体优先使用两块行动看板：20 秒预警、今日打法；窗口不足时自动降为单列。
- 移动端首屏必须仍能看见会前判断、就绪度和第一句话，页签内容可下滑查看。
- 所有长句、客户名称、风险描述和问题话术必须允许换行，避免 `nowrap` 用在正文内容上。
- HTML 生成后检查首屏：顶部栏、会前判断、预警横幅、就绪度之间不能互相遮挡，按钮、分段切换和徽章不能覆盖正文。

## 数据来源展示规则

- 主体简报优先表达结论、风险和现场动作，不让来源字段打断阅读。
- 对没有直接证据支撑的判断，只在正文保留 `推断` 或 `猜测` 标记，并给出现场验证问题。
- 数据来源统一放在简报最后的“数据质量”页签，用低强调弱引用格式展示。
- “数据质量”页签内必须保留参考来源、置信度说明和数据覆盖摘要；状态只使用 `已读取 / 无数据 / 权限不足 / 未触发查询 / 查询失败`；覆盖客户、商机、联系人、跟进记录、日程、需求/问题、会议、待办/任务、现场拜访、竞品明细、合同、订单/回款、外部情报；不要展示完整 query plan。
- 外部情报只体现为会前预警、现场验证问题或最大缺口；不要新增客户背景、新闻、工商风险等正文模块。
- 外部情报与内部事实冲突时，必须写入最大缺口或现场验证问题，并标注“需核对”。
- Markdown 默认使用一行 blockquote；如果输出平台支持 `<details>`，可以折叠展示。

默认格式：

```markdown
> 🧪 数据质量：参考来源为 CRM 客户/商机/联系人/跟进记录、必要外部情报及行业/竞品参考。正文中的“推断/猜测”仅用于会前准备，需在现场验证。
> 数据覆盖：客户 {已读取/无数据/权限不足/查询失败}；商机 {已读取/无数据/权限不足/未触发查询/查询失败}；联系人 {已读取/无数据/权限不足/未触发查询/查询失败}；跟进记录 {已读取/无数据/权限不足/未触发查询/查询失败}；日程 {已读取/无数据/权限不足/未触发查询/查询失败}；需求/问题 {已读取/无数据/权限不足/未触发查询/查询失败}；会议 {已读取/无数据/权限不足/未触发查询/查询失败}；待办/任务 {已读取/无数据/权限不足/未触发查询/查询失败}；现场拜访 {已读取/无数据/权限不足/未触发查询/查询失败}；竞品明细 {已读取/无数据/权限不足/未触发查询/查询失败}；合同 {已读取/无数据/权限不足/未触发查询/查询失败}；订单/回款 {已读取/无数据/权限不足/未触发查询/查询失败}；外部情报 {已读取/无数据/权限不足/未触发查询/查询失败}。
```

## 人力地图规则

- `normal` 默认输出轻量人力地图，放在见客就绪度之后、今日行动之前。
- 只保留 3-5 个会影响本次会议的人：今天参会人、EB/EB 候选、Coach、Gatekeeper、TB、关键 UX。
- 每行必须包含“今天打法”，不要只写职位或关系。
- 不明确时写“未知/待确认”，并把识别问题写进今天打法。
- 如果没有任何人物信息，保留 1 行“关键决策人未知”，今天打法设为识别 EB。

## 博弈编年与拜访后行动

- 按 `rules/R07_game_timeline_follow_up.md` 判断是否输出博弈编年，不在 R06 重复截断明细。
- Markdown normal 默认显示 3 条关键摘要；用户要求明细或完整模式时展开完整关键事件表。
- HTML 始终默认显示摘要，并允许用户在同一页签切换到明细。
- 所有模式始终输出拜访后行动清单；normal/full 使用独立页签，lite 显示一个会后必做。

## 字段选择规则

### 身份标签

只选择能帮助 AE 决定今天怎么行动的标签：

- 客户类型：战略型、成长型、稳健型、收缩型、未知。
- 情绪温度：积极、中性、冷淡、负面、未知。
- 当前阶段：初次接触、需求确认、POC、方案、商务谈判、续约、重启。

不确定时写“未知”，并说明关键缺口；来源类型收口到末尾弱引用。

### 会议目标

只选择一个主目标：

- `签约`：见客就绪度 >= 80，EB 已知，预算已确认，无致命风险。
- `高层承诺`：需要 EB 参与或明确表态。
- `探测预算`：预算状态未知或审批链路不清。
- `排除障碍`：Gatekeeper、必选条件、竞品或采购风险活跃。
- `重建上下文`：近期互动过旧或 CRM 历史很薄。

不要选择比证据更激进的目标。

### 底线

底线必须是约束，不是口号：

- 不承诺无法支撑的必选功能。
- 价值和决策链未确认前，不主动让价。
- 非 EB 会议不进入最终商务谈判。
- 不直接攻击竞品。

### 预警

按严重度和与今日参会人的相关性选择前三个风险。风险证据优先级：

1. R01 中的承诺未兑现、预算未知、结单压力、商机停滞。
2. R02 中的 EB 未知、Coach 薄弱、Gatekeeper、角色错配。
3. R03 中的必选条件无法满足或痛点证据弱。
4. R04 中的 C3/C4 竞品或差异化弱。
5. 客户 memory 中的历史风险模式。

每条预警必须有现场应对动作。真实风险不足三条时，可以少于三条，不要凑数。

### 行动建议

每个行动都必须通过这个测试：

```text
AE 能否在会议中 5 分钟内完成或问出来？
```

错误示例：

```markdown
P0：深化客户关系。
```

正确示例：

```markdown
P0：问林总："这次系统上线后，您最想先看到哪个指标变化？"
```

拜访后行动不受“会议中 5 分钟完成”约束，但必须满足 R07 的负责人、时限、触发条件和完成标准要求。清单只是计划，不代表已经更新 CRM、发送消息或写入 memory。

## Full 模式

normal 简报之后，只追加用户要求的部分：

- R02 完整决策链和人力地图。
- R07 完整博弈编年、关键转折点、时间线缺口和拜访后行动清单。
- R03 痛点矩阵。
- R04 竞争态势详情。
- R09 历史财务/合作详情。
- 追加内容完成后，仍把同一事实包交给 `scripts/render_pre_visit_briefing.py`，由 full 模式固定页签同步生成并校验 HTML。

normal 输出不要包含归档的 out-of-scope 素材。
