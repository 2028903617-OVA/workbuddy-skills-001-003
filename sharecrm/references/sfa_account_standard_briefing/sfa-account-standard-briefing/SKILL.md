# 客户360档案

## 技能元信息

- 参数提示：`[客户名称] [--full]`
- 版本：`1.0.0`
- 更新时间：`2026-07-15`

## 目标

为 AE 生成一份用于桌面端深度阅读的客户360档案。这个场景没有“今天必须做什么”的压力，目标是让 AE 建立完整客户认知：

- 这个客户是谁，业务和组织处在什么状态？
- 决策圈里谁重要，谁支持，谁阻碍，关系如何变化？
- 我们和客户过去怎么打交道，关键博弈节点如何影响当前判断？
- 当前项目为什么启动，客户期望、硬门槛、预算审批和时间表是什么？
- 客户现有 IT 系统、使用规模和优先覆盖群体是什么？
- 当前和历史商机是什么状态？
- 客户真实痛点、竞品格局和未知问题分别是什么？

默认先在对话中直接输出结构化 Markdown 正文，再基于同一内容生成 HTML 标准版客户简报。Markdown 文件只是归档物，不能替代对话内正文；HTML 用于网页预览、移动端阅读和分享，不改变客户判断、置信度、数据口径或章节内容。

## 适用场景

使用本技能处理：

- `/intake [客户名称]`
- `/intake [客户名称] --full`
- “帮我了解这个客户”
- “生成客户360”
- “客户档案 / 客户全貌 / 客户画像”
- “生成 HTML 客户简报 / 网页版客户简报 / 清爽版标准简报”
- “我想先认识这个客户，不是准备马上见客户”

不要用于：

- 见客前 1 分钟行动简报。
- 团队交接或 AE 工作移交。
- 高层陪访、领导汇报或升级汇报。
- 团队周报、客户组合盘点、销售经理 review。
- 客户主体识别、行业分类或产业链位置判断；交给 `company-identifier`。
- 深度决策链诊断；交给 `decision-chain`。
- 深度需求穿透；交给 `needs-discovery`。
- 单商机竞品攻防；交给 `competition-intel`。
- 完整管线预测、目标达成判断或销售预测；交给 `pipeline-review`。

本技能负责生成客户360/客户档案产物，可以展示决策链、痛点、竞品和商机全貌，但不做深度业务诊断。用户要客户主体识别转 `company-identifier`，要决策链诊断转 `decision-chain`，要需求诊断转 `needs-discovery`，要竞品攻防转 `competition-intel`，要管线预测转 `pipeline-review`。

## 输出原则

- 结论先行：正文前必须先输出“结论摘要”，让 AE 先知道客户当前状态和最重要判断。
- 桌面端深度阅读，允许比见客前简报更完整。
- 以事实、关系和历史脉络为主，不强制输出今日行动。
- 所有推断必须标注置信度。
- 不把行业通用痛点当成客户事实。
- 不回避未知；未知项要进入“开放问题”。
- 重点呈现最重要的 10 个关键人（KP），其余人员用简表或归入“其他联系人”。
- 使用少量 emoji 强化章节扫读，只放在章节标题和关键提示，不给每行都加装饰。
- 正文不逐条堆叠“来源/依据”；证据类型和数据口径统一收口到文末“参考来源”弱引用区。
- 不删减已识别内容；数据不足时保留章节并写“未知/待补充”，不要直接省略。
- 标准版可以给出“后续建议动作”，但必须服务客户认知和机会判断，不写成见客前强行动板。

## 数据优先级

1. Memory：历史博弈、关系变化、承诺兑现、关键事件。
2. CRM 基础对象：`AccountObj`、`NewOpportunityObj`、`ContactObj`、`ActiveRecordObj`。
3. CRM 广覆盖对象：`RequirementObj`、`ActivityQuestionObj`、`ScheduleObj`、`AIMeetingObj`、`AIMeetingChunkObj`、`ActivityTodoObj`、`MethodologyTaskObj`、`CheckinsObj`。标准版客户360默认尽量覆盖这些对象，用于需求、问题、会议、承诺、过程动作和现场触达。
4. CRM 竞争与历史合作：`CompetitiveLinesObj`、`ContractObj`、`SalesOrderObj`、`PaymentObj`。能确认对象和字段且有权限时尽量轻量读取；无数据、权限不足或查询失败必须进入数据覆盖，不得写成“没有竞品/没有合作/没有回款”。
5. 企业自定义客户健康、CSM 预警、流失原因：仅在字段口径可确认、用户提供或 reference 明确时读取；不能硬编码未知 apiName。
6. References：行业基准、竞品参考、CRM 字段说明。
7. 外部情报：企业信息、市场新闻、风险、上市公司、招投标、知识产权等，只在用户要求、信息缺口明显或外部动态会改变客户画像/风险判断时使用。

## 处理流程

1. 识别客户。
   - 需要从 CRM 查询时，先读取 `references/shared/sharecrm_cli_min_loop.md`，再按需读取 `references/cli_reference.md`。
   - 按最少 loop 规则先形成内部 `query_plan`：本次要查的对象、字段、过滤条件、触发补查条件和停止条件。
   - 按 `references/cli_reference.md` 的多阶段流程识别客户主记录：先完整名称查询，再用 ID 候选召回、别名/关键词/核心词模糊召回和 `_id` 精确查询补充定位。
   - `query-by-name` 未命中只能写为“名称检索未命中”，不得直接判断“CRM 中没有客户”。
   - 用户输入不要求与 CRM 客户名完全一致；如“文易动纷享”应能通过核心词“易动纷享”定位到“易动纷享有限责任公司”这类唯一高置信候选。
   - 多个候选客户或只命中短词候选时，先让用户选择；用户提供截图、链接或客户 ID 时，优先按 `_id` 精确查询。

2. 拉取客户360数据。
   - 先读取 `references/shared/report_data_sources.md` 判断本次数据源；标准版客户360采用“广覆盖、轻量读取、状态收口”的数据策略。
   - 确认唯一客户和 `<accountId>` 后再拉取关联对象；未确认客户前，不查询商机、联系人、销售记录或扩展对象。
   - 先完成 metadata plan：只 describe 本次需要的对象；同一对象本轮只 describe 一次，并只选择已确认字段，不猜字段 apiName、对象 apiName 或枚举值。
   - 再完成 identity plan：客户、商机、联系人、员工、部门等引用过滤必须先解析为 `_id`。
   - 基础对象可在字段确认后并行查询；客户简报基础对象必须覆盖 `AccountObj`、`NewOpportunityObj`、`ContactObj`、`ActiveRecordObj`。
   - 标准版扩展对象尽量覆盖：需求查 `RequirementObj`，客户问题/异议查 `ActivityQuestionObj`，日程查 `ScheduleObj`，会议证据查 `AIMeetingObj`、`AIMeetingChunkObj`，承诺或待办查 `ActivityTodoObj`、`MethodologyTaskObj`，现场拜访查 `CheckinsObj`。
   - 竞争与历史合作尽量覆盖：能确认字段时轻量读取 `CompetitiveLinesObj`、`ContractObj`、`SalesOrderObj`、`PaymentObj`，用于竞品全貌、历史合作、客户价值、回款和续约风险；没有权限或字段不存在时只记录状态。
   - `--full` 模式可放宽历史合作、财务、客户健康和流失原因的查询深度；标准模式只做轻量读取和关键结论支撑，不做大规模明细展开。
   - 如字段含义不清，读取 `references/crm_schema.md`。
   - 按 `references/shared/crm_query_status.md` 记录每类数据状态：`已读取 / 无数据 / 权限不足 / 未触发查询 / 查询失败`。权限不足或不可恢复错误不等于无数据，不要重复查询同一对象。
   - 广覆盖对象完成一次轻量读取或明确状态后停止；缺失项进入“开放问题”和数据覆盖摘要，不为了填满版面反复 loop 或深挖全量明细。

3. 读取 Memory。
   - 读取 `memory/customers/[客户名称]/` 下已有记忆。
   - 只有创建或更新记忆结构时，读取 `memory/template.md`。

4. 补充外部情报。
   - 在 CRM 和 Memory 已形成基础判断后，如用户要求外部信息、客户画像/战略动态/风险矩阵存在明显缺口，或 `--full` 需要更完整背景，读取 `references/shared/external_intelligence_sources.md`。
   - 外部情报默认不触发；触发后优先使用聚合命令：企业背景用 `company conc`，近期动态用 `market get-news`，风险用 `risk conc`，上市客户先用 `listed listed_company`。
   - 标准模式外部情报默认最多 3 次查询；`--full` 最多 5 次。外部情报不会覆盖 CRM 客户、商机、联系人、承诺、订单或回款事实。
   - 按统一状态记录外部情报：`已读取 / 无数据 / 权限不足 / 未触发查询 / 查询失败`；缺口进入“开放问题”和数据覆盖摘要。

5. 加载规则。
   - 标准模式：执行 `rules/R01_customer_profile.md` 至 `rules/R08_open_questions.md`；其中竞品相关规则仅在竞品明细已读取、Memory/互动/商机中存在竞品信号，或用户明确要求竞品全貌时展开。
   - full 模式：额外执行 `rules/R09_history_financial.md`。

6. 生成默认 Markdown 档案。
   - 先在对话中直接输出 Markdown 格式化正文，不包进代码块，不只提供 `.md` 文件或路径。
   - 先输出结论摘要，再展开 1-8 节客户360正文。
   - 输出客户画像、决策圈图谱、博弈时间线、项目背景与商机全貌、痛点地图、竞品全貌、开放问题、后续建议动作。
   - 客户画像的基本信息字段必须使用 CRM describe 元数据返回的字段名称，不得把字段 apiName 直接作为用户可见标签；并单独整理“上系统动机”。
   - “决策圈图谱”合并关系温度、关键人、决策链、人力地图、组织政治和覆盖分析；不再拆成“关系温度”和“决策链”两个一级章节。
   - “博弈时间线”紧跟在“决策圈图谱”之后。
   - 在现有章节内补充客户价值快照、业务模式/收入来源、趋势洞察、商机汇总、阶段停留时间和数据健康预警，不新增独立大章节。
   - 如存在项目型商机，补充项目起源、客户期望、必选条件、预算审批、信息化现状、使用规模、当前商机和最近 5 条高价值历史商机。
   - 在开放问题中补充风险矩阵；再以独立一级章节输出“后续建议动作”，集中展示数据提示与健康预警和建议动作，建议动作不超过 5 条。
   - `--full` 模式追加历史合作、财务与客户健康，并在有数据时补充折扣、回款周期和应收预警。
   - 最后输出弱化的“参考来源”，不要把来源说明散落在正文每条判断后。
   - 不输出“今日目标”“行动 P0/P1/P2”“确认出发”等见客前语言；P0/P1/P2 仅可用于使用规模优先级。

7. 生成 HTML 展示版。
   - 先完成 Markdown 结构化内容，再读取 `references/shared/html_output_quality_gate.md`、`references/html_render_contract.md` 和 `rules/R10_html_output.md`。
   - 把 Markdown 使用的同一组事实整理为 `briefing_facts_bundle.json`，不得为了 HTML 重新撰写结论。
   - 必须调用 `scripts/render_standard_briefing.py` 生成 HTML；不得手写整份 HTML、重新设计 DOM，或把 `assets/templates/standard_briefing.html` 仅当作视觉参考。
   - 渲染器必须使用模板标识 `sfa-standard-briefing-v3`，并自动执行 `scripts/validate_standard_briefing.py`；校验失败时不得交付 HTML。
   - HTML 固定使用附件式中文品牌顶栏、健康度卡、KPI 条和顶部横向页签，每次展示一个一级章节；页签顺序固定为结论摘要、客户画像、决策圈图谱、博弈时间线、项目与商机、痛点地图、竞品全貌、开放问题、后续建议动作、可选的历史合作与财务、数据质量；页签内容标题不显示序号。“数据质量”固定为最后一个独立页签，承载数据覆盖、数据截止、参考来源和置信度说明，不在业务页签重复展示。移动端采用内容驱动的自适应高度，长客户名、长状态和长结论自然换行，页签可横向滑动，正文单列，表格可横向滑动。
   - 用户可见来源只写中文业务标签，不显示对象或字段 apiName。
   - 校验通过的 HTML 和 `.md` 归档文件通过系统附件交付；不要在回复正文中输出“文件已生成”、文件名、文件路径或 Markdown/HTML 文件清单。

## 资源路由

- 需要判断本次该查哪些对象和触发补查条件时，读取 `references/shared/report_data_sources.md`。
- 需要从 CRM 拉取数据时，先读取 `references/shared/sharecrm_cli_min_loop.md`，再按需读取 `references/cli_reference.md`。
- 需要统一数据覆盖状态、权限不足和降级生成口径时，读取 `references/shared/crm_query_status.md`。
- 需要补充企业工商、新闻舆情、风险、上市公司、招投标、知识产权或特殊组织信息时，读取 `references/shared/external_intelligence_sources.md`。
- 生成 HTML 展示版前，读取 `references/shared/html_output_quality_gate.md`。
- 需要整理 HTML 输入字段和调用渲染器时，读取 `references/html_render_contract.md`。
- 需要解释 CRM 对象或字段时，读取 `references/crm_schema.md`。
- 需要行业规模、采购周期、财务阈值或常见痛点假设时，读取 `references/industry_benchmarks.md`。
- 已知或疑似竞品时，读取 `references/competitive_reference.md`。
- Markdown 简报完成后，读取 `rules/R10_html_output.md`，并调用 `scripts/render_standard_briefing.py` 生成和校验 HTML 展示版。
- 只有 full 模式或用户要求历史订单/回款/增购时，读取 `rules/R09_history_financial.md`。
- 本技能的 HTML 模板只服务标准版客户简报；如需见客前、团队交接或高层陪访模板，应切换对应 skill。

## 置信度规范

- `确认`：有 CRM 记录、客户原话、合同/订单/回款记录或明确历史事件。
- `推断`：有行为证据支撑，逻辑链清楚，但客户未直接确认。
- `未知`：没有证据，不允许补成事实。

## 禁止行为

- 不输出见客前简报式的“今日目标”“行动 P0/P1/P2”“底线”“确认出发”。
- 不强制给见客前行动板；如有建议，只写服务客户认知、项目推进或风险验证的后续建议动作。
- 不把 CRM 数据简单罗列成字段清单，必须整合成客户认知。
- 不把行业假设、竞品猜测或 AE 感觉写成事实。
- 不用外部情报覆盖 CRM 或 Memory 已确认事实；外部信息冲突时写入“需核对”。
- 不输出超过 20 个关键人；重点说明最重要的 10 个关键人（KP）。
- CRM 权限不足时，不得写成“无商机/无联系人/无互动/无竞品”；必须标注“权限不足未读取”并降低相关结论置信度。
