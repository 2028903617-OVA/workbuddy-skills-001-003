# HTML 输出质量门禁

本文件定义客户简报 HTML 展示版的统一质量要求。HTML 只做展示层，不改变 Markdown 中的事实、判断、置信度和数据覆盖。

## 事实一致性

- Markdown 正文和 HTML 必须来自同一份 `briefing_facts_bundle`。
- 不允许 Markdown 和 HTML 分别重写结论。
- HTML 不得新增 Markdown 中没有的客户事实、金额、人员、承诺或风险。
- 数据覆盖、置信度、未知项和风险不能为了美观被省略。

标准版客户简报必须使用以下中间结构：

```yaml
briefing_facts_bundle:
  metadata:
  data_coverage:
  executive_summary:
  sections:
  risks:
  open_questions:
  html_assets:
```

## 模板安全

- 正式模板必须使用占位符或结构化渲染，不得残留样例客户名、样例人员、样例金额、样例日期。
- mock preview 可以保留样例数据，但文件名必须带 `mock_preview` 或 `preview`。
- 生成新客户简报时，必须检查 HTML 中是否残留旧客户名称。
- 不输出需要用户手动拼接 CSS 或脚本的半成品。

### 标准版模板强制规则

- 标准版只能通过 `scripts/render_standard_briefing.py` 渲染，不允许 agent 手写完整 HTML。
- 正式输出必须保留 `data-template-id="sfa-standard-briefing-v3"`。
- 固定一级章节 ID 必须完整：`overview / profile / decision-map / timeline / opportunity / pain / competition / open-questions / next-actions / data-quality`。
- 固定页签顺序为“结论摘要 / 客户画像 / 决策圈图谱 / 博弈时间线 / 项目与商机 / 痛点地图 / 竞品全貌 / 开放问题 / 后续建议动作 / 可选的历史合作与财务 / 数据质量”。关系温度和决策链只在“决策圈图谱”中合并展示，不保留两个独立页签。
- 每个页签的内容标题只显示标题文字，不显示数字或“来源”等序号徽标。
- 正式输出使用顶部横向页签导航，每次展示一个一级章节；“数据质量”固定为最后一个独立页签，承载数据覆盖、数据截止、参考来源和置信度说明，不在业务页签重复展示；移动端页签可横向滑动。
- 用户可见区域不得出现对象或字段 apiName，也不得保留附件中的英文模板标题。
- 客户画像“基本信息”的标签必须使用 CRM describe 元数据返回的字段名称，不得展示字段 apiName。
- 渲染完成后必须通过 `scripts/validate_standard_briefing.py`；失败时不得交付。

## 视觉要求

- 使用浅色商务风格，保留纷享销客品牌黄：`#ffb400`、`#fff8db`、`#ffe08a`。
- 页面宽度、留白、标题层级、表格和标签样式保持统一。
- 卡片圆角不超过 8px，避免大面积渐变、装饰图形和无意义背景。
- 风险用红色，中风险用黄色，低风险用绿色；颜色必须服务于证据判断。
- 一级模块标题清晰，正文以表格、列表、时间线和关键人卡片组织。

## 响应式与可读性

- 移动端自动降为单列。
- 长客户名、长风险描述、长问题话术必须允许换行。
- 移动端顶部、健康度卡和正文区必须使用内容驱动的自适应高度，不得因长文本形成遮挡或横向溢出。
- 表格必须包裹横向滚动容器。
- 不使用固定高度承载动态正文。
- 不用绝对定位叠放正文、徽章、按钮或底部操作条。
- 首屏不能出现遮挡：顶部栏、主结论、风险、就绪度之间不得重叠。

## 单文件交付

- 最终 HTML 应尽量内联 CSS，确保复制或转发后可离线打开。
- 如果模板开发阶段使用外部 CSS，最终生成时要内联到 HTML。
- 不依赖远程 CDN、远程字体或外部图片。

## 输出前检查

生成 HTML 后检查：

- 是否保留正式模板 ID 和全部固定章节。
- 是否通过固定校验脚本，而不是只做人工目测。
- 是否仍有 `{{...}}` 占位符、外部资源依赖、英文模板标题或用户可见 apiName。
- 是否残留样例客户、样例人员、样例金额。
- 是否保留数据覆盖和置信度。
- 是否有空模块被删除；数据不足时应显示“未知/待补充/暂无记录”。
- 移动端是否单列且无横向溢出。
- 表格是否可横向滚动。
- 长文本是否换行。
- 是否存在遮挡、重叠、按钮覆盖正文。
