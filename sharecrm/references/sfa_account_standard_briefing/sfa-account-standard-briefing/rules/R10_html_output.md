# R10 HTML 输出

## 目标

把 R01-R09 形成的 `briefing_facts_bundle` 确定性渲染为标准版单文件 HTML。HTML 只负责展示，不新增或改写 Markdown 中的客户事实、金额、人员、承诺、风险、置信度和数据覆盖。

## 触发条件

R08 完成 Markdown 后始终执行，除非用户明确要求只要 Markdown 或禁止生成 HTML。“输出 HTML”“做成网页”“客户360”“标准版客户简报”都必须执行本规则。

## 唯一生成方式

1. 读取 `references/html_render_contract.md`。
2. 把已完成的 Markdown 和 R01-R09 结构化结果整理为同一份 `briefing_facts_bundle.json`。
3. 调用固定渲染器：

```bash
python3 scripts/render_standard_briefing.py \
  --input <briefing_facts_bundle.json> \
  --output <客户名称>_客户360简报_<日期>.html
```

4. 只有命令返回成功且输出 `Rendered and validated` 时才允许交付 HTML。
5. 需要排除旧客户残留时，增加一个或多个 `--forbid-text "<旧内容>"`。

不得手写整份 HTML，不得复制 Markdown 后重新设计页面，不得用其他 HTML 骨架替代正式模板。`assets/templates/standard_briefing.html` 是唯一正式模板；agent 只生成事实包，HTML 标签、CSS、导航和响应式规则必须由渲染器提供。

## 固定模板结构

正式 HTML 必须保留模板标识：

```html
data-template-id="sfa-standard-briefing-v3"
```

视觉结构固定为：

- 中文品牌顶栏、报告日期、简报状态和数据覆盖摘要。
- 客户大标题、客户身份信息和健康度卡片。
- 最多 6 个客户 KPI 指标卡。
- 桌面端和移动端统一使用顶部横向页签导航，每次展示一个一级章节。
- 页签顺序固定为结论摘要、客户画像、决策圈图谱、博弈时间线、项目与商机、痛点地图、竞品全貌、开放问题、后续建议动作、可选的历史合作与财务、数据质量；页签内容标题不显示序号。
- “数据质量”固定为最后一个独立页签，展示数据覆盖、数据截止、下次更新、参考来源和置信度说明，不在业务页签重复展示。

不得合并或删减上述固定页签，不得改成营销式 hero、深色主题、双主题或自由卡片布局。关系温度和决策链必须合并为一个“决策圈图谱”页签，不得恢复为两个一级页签；“数据质量”必须始终位于最后。

## 固定内容映射

| HTML 章节 | 数据来源 |
| --- | --- |
| 结论摘要 | R08 |
| 客户画像 | R01、R06 |
| 决策圈图谱 | R03、R04 |
| 博弈时间线 | R02，固定放在决策圈图谱之后 |
| 项目背景与商机全貌 | R05 |
| 痛点地图 | R06 |
| 竞品全貌 | R07 |
| 开放问题与风险 | R08 的风险、开放问题和最大信息缺口 |
| 后续建议动作 | R08 的数据提示与健康预警、建议动作，独立一级页签 |
| 历史合作、财务与客户健康 | R09，仅 `--full` 或用户明确要求时展示 |
| 数据质量 | `metadata`、`data_coverage`、`references` |

核心章节数据不足时仍保留章节并显示“未知/待补充/暂无记录”。不得为了美观删除未知项、风险、查询失败、权限不足或外部信息冲突。

## 版式边界

以下内容允许变化：客户数据、表格行数、卡片数量、风险等级、标签状态和 full 模式历史财务章节。

以下内容禁止变化：模板 ID、顶层 DOM、一级章节 ID、导航形式、CSS 变量、品牌色、响应式断点、表格滚动容器、数据说明区和模板脚本。

- 固定浅色主题，保留 `#ffb400 / #fff8db / #ffe08a` 品牌黄。
- 不依赖 CDN、远程字体、远程脚本或外部图片。
- 不使用固定高度承载动态正文。
- 所有表格必须由渲染器放入 `.table-wrap`。
- 长客户名、长风险和长问题必须自然换行。
- 移动端所有业务网格降为单列，表格允许横向滑动。
- 移动端顶部、健康度卡和正文区使用内容驱动的自适应高度；长客户名、长状态、长结论和数据覆盖标签必须自然换行，不得挤压、遮挡或造成页面横向溢出。
- 用户可见来源只展示中文业务标签，不显示对象或字段 apiName。

## 交付要求

- 先在对话中直接输出 Markdown 正文，不包进代码块，也不只提供文件路径。
- Markdown 与 HTML 必须使用同一份事实包。
- 运行环境允许写文件时，通过系统附件交付 `.md` 归档文件和校验通过的 `.html` 文件；不要在回复正文中输出“文件已生成”、文件名、文件路径或 Markdown/HTML 文件清单。
- 如果环境不能执行渲染脚本，明确说明无法生成合规 HTML；不得回退为手写 HTML 冒充模板产物。

## 禁止行为

- 不把附件、mock preview 或历史报告中的客户名称、人员、金额、日期复制到新报告。
- 不在用户可见区域展示 `AccountObj`、`NewOpportunityObj`、`PaymentObj` 等 apiName。
- 不输出英文模板标题，例如 `Customer 360 Intelligence`、`Account Intelligence Report`、`Customer Health` 或 `Report Map`。
- 不绕过校验器交付包含未替换占位符、外部依赖或结构漂移的 HTML。
- 不把 HTML 模板塞进 Markdown 正文，也不把 `.md` 路径当成 Markdown 正文。
