# R02 - 个人日报

## 目标

个人日报用于回答：今天做了什么、哪些事情有结果、哪些客户有风险、数据是否完整、明天先做什么。

日报定位为“今日执行闭环”，不是工作流水账，也不是小周报。重点写今日有效结果、执行信号、跟进结论、待办闭环、短周期风险、数据完整性和明日第一动作。

## 输入要求

优先读取或要求用户提供：

- 当日跟进记录：客户、联系人、沟通方式、沟通结论
- 当日任务：计划完成、实际完成、延期、取消
- 当日商机变化：阶段变化、金额变化、赢率变化、预计签约时间变化
- 当日成交或回款
- 明日计划
- CRM 数据覆盖情况：日志、销售记录、日程、商机、订单、回款是否有数据
- 近 1-2 日是否连续数据缺失、是否存在未补录记录或同步异常

## 查询边界

简洁版日报默认只查询核心事实对象：日志、销售记录、商机、订单、回款。日程/外勤不是默认必查对象；只有用户明确问待办、日程、会议、拜访，或日志/销售记录不足以判断承诺闭环时才补查。

连续缺失必须有真实查询证据：只有实际查询了今日和前 1-2 日核心对象，且这些日期的日志、销售记录、商机、订单、回款均返回 0 条或明确不可用，才允许写“连续 2 日/3 日数据缺失”。如果只查了今天，只能写“今日核心对象未查询到记录”，不得推断连续缺失。

## 输出结构

普通日报必须直接渲染为正文，不要放进 `markdown`、`text` 或其他代码块。默认模块顺序：

1. `# [销售姓名] 个人日报 - [日期]`
2. `## 🧭 今日摘要`：今日最重要结果、今日最大风险、明日最重要动作。
3. `## 📊 今日执行信号`：展示有效跟进、P0 完成、待办闭环、商机变化、订单/回款、数据覆盖或数据缺失等 4-6 个信号。
4. `## ✅ 今日结果`：每条写成“成果一句话 + 证据 + 价值”，只收有结果的动作；无结果数据时写“待确认事项”，不编造客户成果。
5. `## 🤝 重点跟进`：同一客户或商机先合并，再写客户/商机、动作、客户反馈/结论、阶段/金额/赢率变化、下一步。
6. `## 📌 今日待办`：区分已完成、未完成/延期、待确认；无任务/日程数据时说明无法完整对账。
7. `## ⚠️ 今日风险`：写客户/商机或数据风险、等级、依据、已动作、下一动作和截止时间。
8. `## 🎯 明日行动`：分为 `🔴 P0 必须完成`、`🟡 P1 应该推进`、`🔵 P2 有资源再做`。
9. `## 🧾 数据说明`：人员/部门和 CRM 数据覆盖；使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；正文必须使用引用块 `>` 弱化展示。
10. `## 💾 CRM 日志保存确认`：按 `R09_journal_storage_confirmation.md` 用中文询问是否保存到 CRM 日志。

## 判定规则

- 有明确客户反馈、阶段推进、交付物、成交或回款，才算“关键结果”。
- “联系了、沟通了、发了资料”只算动作，不算结果；必须追问或标注“结论缺失”。
- 当日未完成的 P0 待办，必须进入明日 P0 或说明取消原因。
- 明日 P0 不超过 3 条，避免把所有事情都写成最高优先级。
- 今日关键成果必须写成“结果 + 证据 + 价值判断”，不要把动作堆成流水账。
- 同一个客户的多条记录要合并成一行，按“做了什么、客户反馈是什么、阶段/金额/赢率是否变化、下一步是什么”表达。
- 重点跟进必须优先展示影响明日 P0、阶段推进、成交/回款、关键承诺或风险止损的客户/商机；普通维护客户合并为一句。
- 如果客户/商机有阶段、金额、赢率、预计签约时间变化，必须写入重点跟进或今日执行信号；无变化时不要强行展开 Pipeline 结构。
- 今日待办必须对账：已完成要写证据，延期/逾期要写原因、新截止时间和补救动作，待确认要写缺什么证据。
- 风险必须包含等级、依据、已动作、下一步和截止时间；没有截止时间的风险处理建议不合格。
- 日报不默认展开 Pipeline 结构、月度目标趋势或复杂复盘；除非用户要求，否则只保留与今日动作和明日 P0 有关的指标。
- 日报的“关键指标”只放执行闭环类信号，例如今日有效跟进数、今日 P0 完成、今日新增风险、明日 P0 数；不要照搬周报的经营指标矩阵。
- 当 CRM 查询结果为空时，不要只输出“无数据”。必须判断是否为数据录入遗漏、同步延迟或确无客户活动，并输出：数据缺失诊断、待确认事项、补录/排查动作、今日风险和明日 P0。
- 如果连续 2 日或以上 CRM 销售记录、商机、订单、回款等核心对象均为空，且这些日期确实被查询过，必须把“CRM 数据连续缺失”列为中风险或待确认风险，并要求当天补录或排查同步。未查询历史日期时，不得写连续缺失。
- CRM 空数据场景下，今日结果模块写“CRM 未查询到关键成果，以下事项待确认”；重点跟进模块写“未查询到跟进记录，需确认是否有客户拜访/电话/会议未录入”；待办模块写“无法完整对账”的影响。
- 普通日报直接输出可渲染正文，不要整体包进代码块。
- 普通日报必须完整内联展示 Markdown 正文；不要折叠成“今日日报摘要”、附件卡片、`<details>` 或“点击展开”。
- 除非用户要求表格，今日关键成果、跟进记录、待办和风险默认用短段落或项目符号，不用表格。
- 数据说明放在最后，只展示人员/部门和 CRM 数据覆盖；CRM 数据使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；正文必须使用引用块 `>` 弱化展示；不默认展示数据缺口表。
- 先完成日报 Markdown 正文，再由总流程默认执行一次 `R10_html_report_output.md` 生成 HTML 页面，最后执行日志保存确认；只有用户明确说“只要 Markdown/不要 HTML”时跳过 HTML。不要为同一份日报生成多份 HTML。
- 输出日报后必须用中文询问是否保存到 CRM 日志；用户确认前不得写入。

## 输出粒度

### 简洁版（默认）

适合快速查看或发给管理者。控制在可快速阅读的长度：

- 摘要 100 字以内。
- 今日关键成果 3-5 条。
- 今日跟进记录只展开重点客户/商机，普通维护客户合并概述。
- 待办完成情况只列已完成关键事项、未完成/延期事项和待确认事项。
- 今日风险只列中高风险或影响明日 P0 的风险。
- 数据缺失场景下必须保留数据缺失诊断、待确认事项和补录 P0。
- 明日行动 P0 不超过 3 条，P1 不超过 3 条，P2 可省略或最多 2 条。
- HTML 日报应优先展示“今日结果、待办闭环、今日风险、明日行动”；桌面端保留左侧目录，移动端隐藏目录。

### 详细版

适合复盘过程或检查执行细节：

- 今日跟进记录可展开到 10 个客户/商机。
- 每个重点客户/商机写动作、客户反馈、结论、下一步。
- 待办按事项逐条对账。
- 风险写完整依据、已动作、下一动作和截止时间。
- 数据缺失场景可展开 CRM 对象查询结果、缺失影响、可能原因、补录清单和排查步骤。
- 可补充普通客户概览，但不要把无结论流水铺满正文。
- 详细版可以展开更多跟进记录，但仍必须按客户/商机合并，避免流水账。

无论简洁版还是详细版，都必须保留数据说明和 CRM 日志保存确认。

## 日报风险重点

日报优先识别短周期风险：

- 关键客户未回复
- 今日承诺没有交付物
- 会议有动作但无结论
- 客户新增竞品信号
- 关键联系人态度变冷
- 明日 P0 依赖今天未完成事项
- CRM 数据连续缺失或关键活动未补录
- 任务/日程无法对账导致承诺闭环不可追溯

## 禁止行为

- 不把所有跟进记录平铺成流水账。
- 不把无结论沟通写成有效推进。
- 不把明日计划写成泛泛的“继续跟进”。
- 不输出团队指标、团队排名或主管管理动作。
- 不因 CRM 无数据就省略今日结果、待办、风险和明日行动模块。
- 不编造客户跟进来填充空日报；必须标注“待确认”并给出补录/排查动作。
