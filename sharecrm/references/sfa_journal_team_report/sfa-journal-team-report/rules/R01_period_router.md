# R01 - 团队报告周期路由

## 目标

先判断用户要的是团队日报、团队周报还是团队月报，再决定读取哪些规则和输出什么粒度。

本规则始终先执行。

路由只负责选周期和最小规则集。周期确定后，先读取命中的周期规则，再读取 R08 团队范围与数据覆盖规则，之后按需读取 CRM 查询、HTML 和保存确认规则；不要顺着表格继续读取其他周期规则，也不要把 R08 固定在 R01 后、周期规则前。

## 周期判断

| 用户表达 | 报告类型 | 读取规则 |
|----------|----------|----------|
| 今日团队情况、昨天团队情况、昨日团队情况、某天团队情况、某一日、具体日期、团队日报、今日管理看板 | 团队日报 | R02 -> R08；CRM 按需查询，R10/R09 在产物阶段读取 |
| 团队本周、团队上周、团队某一周、团队某个日期所在周、团队周报、团队销售周报、部门周报、区域周报、销售经理周报、团队 Wxx、团队 YYYY-WXX、周会复盘 | 团队周报 | R03 -> R08；CRM 按需查询，R10/R09 在产物阶段读取 |
| 本月、上月、某一月、具体月份、团队月报、月度经营复盘、月度管理报告 | 团队月报 | R04 -> R08；CRM 按需查询，R10/R09 在产物阶段读取 |

如果用户没有说明周期，优先追问一句：

你想看团队日报、团队周报还是团队月报？如果不指定，我默认生成团队周报。

如果用户同时提到多个周期，例如“本周和本月”，按用户顺序分别输出，不混成一个报告。

## 输出格式判断

团队日报、周报、月报默认：对话内 Markdown 正文 + `.md` 归档文件 + 一个同前缀 HTML 展开版。完整输出/不折叠：Markdown 正文必须先在对话中直接展示，不包进代码块，不只给摘要，不用附件卡片、`<details>`、`summary` 或“点击展开”替代正文。

HTML、html、网页版、手机查看、自适应页面、H5、浏览器打开、做成页面只表示用户强调 HTML；HTML 不是报告周期。用户说“生成 HTML 版团队周报”时，仍按团队周报完整分析流程执行。

只有用户明确说“只要 Markdown、不要 HTML、不用网页、不生成 HTML”时，设置 `output_html = false` 并跳过 R10；其他情况默认执行一次 R10。只执行一次 HTML：不要同时生成“简洁版 HTML”和“完整版 HTML”，也不要先输出完整 HTML 后再写文件。

## 输出粒度判断

识别用户希望生成简洁版还是详细版，设置 `output_detail`：

| 用户表达 | output_detail | 处理 |
|----------|---------------|------|
| 简洁版、摘要版、快速看、给老板看、只要重点、三分钟看完、管理层版 | concise | 输出简洁版 |
| 详细版、展开、完整、明细、逐个 AE 展开、逐个客户展开、复盘过程、全部跟进记录 | detailed | 输出详细版 |
| 直接生成、快点、先给我看、先出一版 | concise | 不追问，默认简洁版 |
| 未说明粒度 | unknown | 必须触发 human-in-the-loop 二选一选择 |

### Human-in-the-loop 粒度选择

当用户未说明输出粒度，且没有表达“直接生成、快点、先给我看、先出一版”等立即生成意图时，团队日报、团队周报、团队月报都必须先触发 human-in-the-loop 选择，不要用普通文本追问替代。

选择问题：

你希望生成哪种版本？

选项必须只有两个：

- 简洁版：适合快速查看、发给老板/管理层。
- 详细版：展开 AE 表现、重点客户/商机、跨 AE 风险和管理动作。

用户选择后再继续查询和生成报表。团队日报、团队周报、团队月报的粒度确认体验必须一致。

如果用户没有回复或要求继续生成，不要卡住流程，按简洁版输出，并在报表结尾、CRM 保存确认前补一句：

如需，我可以继续展开为详细版。

输出粒度影响报表展开程度和可选扩展查询，不影响核心 CRM 查询、团队聚合、风险识别、HTML 生成和日志保存确认规则。

## 范围判断

识别用户要看的团队范围：

- 全部团队
- 指定团队或区域
- 指定行业组
- 指定销售经理下属团队
- 指定 AE 列表

如果范围不明确，优先使用当前管理者上下文；如果无法知道当前管理范围，先追问。

范围、AE 名单和数据覆盖率的详细处理见 `R08_team_scope_and_coverage.md`。R08 是团队日报、周报、月报的必要规则，但读取位置在命中周期规则之后；所有报表进入数据聚合前，必须先确认或标注团队成员范围。

## 时间范围解析

| 报告类型 | 默认时间范围 |
|----------|--------------|
| 团队日报 | 今天；用户指定昨日/昨天/某一日/具体日期时使用指定自然日 |
| 团队周报 | 本周；用户指定上周/某一周/Wxx/YYYY-WXX/某个日期所在周时使用指定 ISO 自然周 |
| 团队月报 | 本月；用户指定上月/某一月/具体月份时使用指定自然月 |

输出中必须写明实际采用的时间范围；如果无法确定，标注“时间范围待确认”。

具体周期边界和指标时间字段见 `references/report_periods.md`。

日报、周报、月报都必须先把用户表达解析为唯一的 `period_start`、`period_end`、`journal_time`。支持并必须正确处理：今日、昨日/昨天、某一日、上周、本周、某一周、上月、本月、某一月。

团队周报日期必须按 ISO 自然周计算：周一为开始，周日为结束。不要把“本周”“上周”或“某个日期所在周”解析为从今天、昨天、指定日期、周二或任意日期开始的滚动 7 天窗口。相对周必须基于当前运行环境的 `current_date/currentDateTime` 计算：

- `current_week_start = current_date 所在 ISO 周的周一`
- `本周 period_start = current_week_start`
- `本周 period_end = current_week_start + 6 天`
- `上周 period_start = current_week_start - 7 天`
- `上周 period_end = current_week_start - 1 天`
- `某个日期所在周 period_start = 指定日期所在 ISO 周的周一`
- `某个日期所在周 period_end = period_start + 6 天`
- 周报日志写入 `journal_time = period_end` 的 `yyyyMMdd`

如果当前日期是周一，用户说“上周”，`period_end` 必须是昨天（上一个周日），不能包含当前周一。回归校验：当 `current_date = 2026-05-25`（周一，Asia/Shanghai）时，`上周` 必须是 `2026-05-18 至 2026-05-24`，`journal_time = 20260524`；绝不能解析为 `2026-05-19 至 2026-05-25`。本行是回归测试样例，不得在其他日期当作当前日期使用。不要使用规则文档里的示例日期、模型训练日期或上一轮对话日期覆盖当前运行环境日期。

团队日报日期必须按 `Asia/Shanghai` 自然日计算：今天为当前运行环境日期 00:00:00 至 23:59:59，昨天为前一自然日。不要使用规则文档示例日期或模型训练日期替代当前运行环境日期。

团队月报日期必须按自然月计算：本月为当前运行环境日期所在月份的 1 日至当月最后一日，上月为前一自然月的 1 日至最后一日。不要使用规则文档示例日期或模型训练日期替代当前运行环境日期。

日报、周报、月报输出前都必须校验标题、正文开头、CRM 查询时间过滤、日志保存时间来自同一个已解析周期；不一致时先修正日期，不要继续输出。

## 边界

本技能只处理团队管理视角。遇到以下请求时应提示使用个人销售报表技能：

- 单个 AE 的个人日报、周报、月报
- 未说明团队范围或管理视角的销售日报、销售周报、周日报、本周销售周报
- 只要求“本周工作总结、下周工作建议、html格式”，但没有团队、部门、区域、多个 AE、主管或销售经理信号
- 单个 AE 的待办对账
- 单个客户的个人跟进建议
- 只关心个人下一步行动而非管理动作

## 数据与执行

进入 CRM 查询前确认：团队范围或 AE 列表、时间范围、用户已提供事实，以及是否需要历史团队日志或管理动作。不要在路由阶段提前查询或补齐所有事实；数据不足时不要编造，只在受影响模块说明缺口及影响。

范围、AE 名单和数据覆盖率见 `R08_team_scope_and_coverage.md`。R08 是必要规则，但读取位置在命中周期规则之后；缺失 AE 不得从团队结论中静默剔除。

数据获取按周期规则执行，能并行的查询分批并行执行，不要逐对象串行查询。简洁版默认核心事实：

- 团队日报：日志、销售记录、商机 + 上一日/当日团队日志；订单/回款仅在当日成交回款无法从核心事实判断时补查，会议/拜访/日程相关问题再补查。
- 团队周报：本周日志、销售记录、商机 + `JournalObj` 上周团队日志/本周已生成日志；订单/回款仅在关键经营信号需要且核心事实不足时补查；客户/线索/联系人仅在正文缺少名称、关键会议、拜访证据或关键人上下文时补查。
- 团队月报：本月日志、销售记录、商机 + 上月团队日志/月内日志；订单/回款仅在目标完成、成交或回款结构需要且核心事实不足时补查。

查询前先形成 query plan：对象清单、时间窗口、团队/AE 过滤方式、时间字段、选择字段、limit 和是否需要历史周期。字段必须来自 describe；不在 describe 返回里的字段要删掉或改为待确认。

日志查询必须精确到目标周期：团队周报上周管理动作优先查询 `journal_time = previous_period_end_yyyyMMdd`，并在字段存在时同时使用 `period_type`、`record_type` 和团队/管理者字段过滤；本周重复生成检查查询 `journal_time = current_period_end_yyyyMMdd`。如果上一周期精确查询成功但返回 0 条，状态写“上周团队日志无数据/待确认”；不要用更早“最近一条周报”、W21、月报或无关日志充当上周证据。只有用户明确要求历史参考时，才另查最近历史日志，并标注“历史参考，不是上周记录”。

简洁版按命中周期规则内置标准完成团队聚合、管理动作闭环、风险识别和 P0/P1/P2 行动；只有数据复杂、风险证据复杂、动作需逐条校验或详细版时，再读取 `R05/R06/R07`。每条 P0/P1 必须包含负责人、涉及 AE/客户、动作、截止时间和验证标准。

输出必须包含周期规则要求的业务模块、数据说明、对话内完整 Markdown 正文、可选 `.md` 归档、一个 HTML 展开版和 CRM 日志保存确认。数据说明放在报表最后，用引用块 `>` 展示团队/AE 覆盖和 CRM 数据覆盖；用户可见处使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键。
