# R03 - 团队周报

## 目标

团队周报定位为“周度经营战报”，用于回答：本周团队目标完成如何、上周管理动作是否闭环、哪些 AE 和商机异常、跨 AE 风险是什么、下周主管应该抓什么。

团队周报不是个人周报拼接，而是管理视角的汇总和判断。

## 执行顺序

生成团队周报时按以下顺序执行：

1. 汇总团队本周核心数据。简洁版先使用本文件“周报重点”和“输出粒度”内置标准；只有数据复杂、需要完整聚合口径或用户要求详细版时再读取 `R05_team_aggregation.md`。
2. 读取上周团队日志/周报/管理动作记录，检查上周 P0/P1 的完成情况、证据、延期原因和本周处理结果。
3. 识别跨 AE 风险和客户级风险。简洁版先使用本文件内置标准；只有风险证据复杂、跨 AE 模式较多或用户要求详细版时再读取 `R06_cross_ae_risk.md`。
4. 生成下周管理动作。简洁版先使用本文件内置标准；只有动作需要逐条校验、资源配置复杂或用户要求详细版时再读取 `R07_management_action.md`。
5. 周报 Markdown 正文完成后返回总流程；本规则不读取 `R10_html_report_output.md` 或 `R09_team_journal_storage_confirmation.md`，避免重复生成 HTML 或提前进入保存写入准备。Excel/xlsx 多页签附件的 HTML 转换由总流程的 R10 处理。

## 输入要求

优先读取或要求用户提供：

- 本周团队目标、成交、回款、Pipeline、任务、风险数据
- 各 AE 的 CRM 明细、日志或周报归档
- 上周团队日志、团队周报或本地历史记录
- 本周重点客户、重点商机、行业和竞品信号
- 客户/商机的金额、阶段变化、赢率变化、关键人、决策链、会议/方案/报价/回款证据
- 本周客户级风险、已采取动作和下周推进/止损计划

## 周报数据源与最少查询

团队周报必须先形成一次 query plan，再按 `references/crm_cli_reference.md` 执行批次查询。目标是数据准确、管理判断可追溯、loop 最少。

### 默认核心数据源

- `日志`：精确查询上周和本周团队日志或 AE 周期日志，用于上周 P0/P1 管理动作闭环和本周重复生成检查；不得用最近一条历史日志替代上一周期。
- `销售记录`：查询本周互动、跟进内容、客户反馈、承诺和风险证据，并用于识别沉默 AE 或无效跟进。
- `商机`：查询团队 Pipeline、阶段变化、金额、赢率、预计结单、赢单/输单/无效、重点商机和 AE 贡献。

### 指标优先聚合

只需要团队数字或 AE 分组数字时先聚合，不拉明细：

- 成交金额/赢单数：优先按商机 `sales_status=赢单` 和 `close_date` 聚合；需要订单口径时再聚合订单。
- 回款金额：优先按回款 `payment_time` 聚合。
- 新增客户/线索/商机：优先按 `create_time` 聚合。
- AE 分组、阶段分布、Pipeline 结构、逾期或预计结单期分布：优先聚合；只有需要点名 AE、客户、商机或风险证据时再查明细。

### 按需补充数据源

只有核心事实不足以支撑管理判断时才补查：

- `订单`、`回款`：成交/回款指标无法从商机或摘要判断，或用户要求明细。
- `日程`、`高级外勤`：关键会议、拜访、外勤和管理动作兑现无法从销售记录判断。
- `待办`、`任务`：上周管理动作、AE 承诺或下周 P0/P1 来源无法从日志、销售记录、日程判断。
- `会议记录`、`会议记录明细`：会议纪要、语音转写或 AI 总结是判断客户反馈/承诺/风险的必要证据。
- `互动问题`、`需求`：客户异议、需求明确度、应答状态或产品/方案卡点缺证据。
- `客户`、`线索`、`联系人`：客户名称、行业、来源、成交状态、线索阶段、关键人或职务缺失。

不得为填满数据覆盖而查询全部对象；未触发的对象在数据说明中标注“未触发查询”。查询字段、枚举值、人员/团队过滤和关联 ID 必须来自 describe 或名称解析，不使用中文字段名、自然语言枚举值或猜测的团队字段直接过滤。

## 输出结构

普通周报必须直接渲染为正文，不要放进 `markdown`、`text` 或其他代码块。默认模块顺序：

1. `# 团队周报 - [团队/范围] - [周次/日期范围]`
2. `## 🧭 本周经营摘要`：团队整体状态、本周最大风险、上周动作闭环结论、下周主管最重要动作。
3. `## 📊 关键经营信号`：目标完成、成交/回款、Pipeline 变化、深度阶段占比、待办/管理动作兑现率。
4. `## ✅ 本周关键结果`：每条写成“结果一句话 + 证据 + 管理意义”。
5. `## 📌 上周管理动作闭环`：上周 P0/P1 是否完成、证据、延期原因、本周处理和是否需要升级。
6. `## 👥 AE 表现与异常`：可用表格展示 AE、目标/结果、Pipeline、关键贡献、风险/异常和管理判断。
7. `## 🤝 重点客户与商机`：写客户/商机、金额、阶段变化、赢率变化、负责 AE、关键人/决策链、本周进展、当前判断和下周动作。
8. `## 🧠 本周打法复盘`：写可复制打法、低效动作和下周调整；只保留团队可复用经验，不写个人心得流水。
9. `## ⚠️ 跨 AE 与客户级风险`：写涉及 AE/客户/行业、风险等级、依据、已采取动作、下一步和管理动作。
10. `## 🎯 下周团队打法`：分为 `🔴 P0 主管必须亲自处理`、`🟡 P1 团队协调处理`、`🔵 P2 常规跟进`，客户/商机动作必须包含目标、负责人、截止时间和验证标准。
11. `## 🧾 数据说明`：团队/AE 覆盖和 CRM 数据覆盖；使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；正文必须使用引用块 `>` 弱化展示。
12. CRM 日志保存确认由总流程在 HTML 生成后追加，不属于周报正文主体。

## 周报重点

- 必须给出团队整体状态：良好、关注、危险或待确认。
- 必须解释 Pipeline、成交、回款、目标完成率的主要变化。
- 必须对上周 P0/P1 管理动作做闭环；上周团队日志必须按上一周期精确查询。缺少上周记录时，在“上周管理动作闭环”说明“上周动作记录待确认”，不要跳过该模块，也不要用更早周报、月报或最近一条无关日志冒充上周证据。
- 必须识别表现异常 AE，但不要在证据不足时做能力定性。
- 必须输出重点客户/商机推进台账；简洁版最多 5 个，详细版最多 10 个。每个客户/商机至少包含金额、阶段或阶段变化、负责 AE、本周进展、当前判断和下周动作。
- 如果有关键人/决策链、赢率变化、竞品、预算/采购/法务/技术节点信息，必须写入重点客户/商机；缺失时写“待确认”，不要编造。
- 必须识别客户级风险，不要只写跨 AE 风险。客户级风险要包含风险等级、风险依据、已采取动作和下一步推进/止损策略。
- 必须提炼 1-3 条本周打法复盘：可复制打法、低效动作和下周调整。打法复盘只写团队可复用经验，不写个人感受。
- 必须把跨 AE 风险和个人客户风险区分开。
- 必须给出主管下周最该处理的 2-3 件事。
- 必须说明本周团队成员覆盖情况；无法确认总人数时，不输出覆盖百分比。
- 普通周报直接输出可渲染正文，不要整体包进代码块。
- 不逐日罗列流水，不展示月度趋势、资源配置长篇判断或月度经营复盘结论。
- 数据说明放在最后，只展示团队/AE 覆盖和 CRM 数据覆盖；正文必须使用引用块 `>` 弱化展示；CRM 数据使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；不默认展示数据缺口表。
- 本规则只生成周报 Markdown 正文；HTML 生成和 CRM 日志保存确认由总流程各执行一次。用户确认前不得写入。

## 输出粒度

### 简洁版（默认）

适合周会快速浏览和向上汇报：

- 摘要 150 字以内，必须包含团队状态、关键数字、最大风险和下周主管动作。
- 团队关键指标保留 6-10 个核心指标。
- 本周关键结果 3-5 条。
- AE 表现与异常只展开关键 AE、异常 AE 和数据缺失 AE。
- 重点客户与商机最多展开 5 个。
- 重点客户与商机优先选择金额高、阶段变化明显、风险高、需主管介入或可复制打法强的客户/商机。
- 本周打法复盘最多 3 条。
- 跨 AE 风险只列中高风险或影响团队目标的系统性风险。
- 下周团队行动 P0 不超过 3 条，P1 不超过 5 条，P2 最多 3 条。

### 详细版

适合团队复盘、周会材料或管理诊断：

- 团队关键指标可补充口径解释、变化原因和环比判断。
- AE 表现可展开到全部已覆盖 AE，包含目标/结果、Pipeline、风险、管理判断。
- 重点客户与商机最多展开 10 个，写负责 AE、阶段变化、金额、风险和主管动作。
- 重点客户与商机详细版必须补充关键人/决策链、赢率变化、本周证据、当前判断、下周动作和验证标准。
- 客户级风险写清风险等级、依据、已动作、下一步推进/止损策略和是否需要主管介入。
- 跨 AE 风险写清涉及 AE/客户/行业、依据、影响和管理动作。
- 管理动作闭环逐条展开上周 P0/P1 的完成情况、证据、延期原因和新动作。

无论简洁版还是详细版，都必须保留数据说明和 CRM 日志保存确认。详细版不得把多个个人周报简单拼接成团队周报。

## 数据缺失处理

如果某个 AE 缺少数据，不单独输出“数据缺口与口径”表；只在受影响模块内说明：

[AE姓名] 缺少 [日报/周报/CRM字段]，因此团队汇总中该 AE 的 [指标] 无法判断。

缺失 AE 不应被默认为表现正常，也不应被直接判定异常。

## 禁止行为

- 不把多个个人周报简单拼接成团队周报。
- 不把周报写成月报，不输出长篇月度结构趋势和资源配置复盘。
- 不跳过上周管理动作闭环；如果查不到上周记录，必须在该模块说明“上周动作记录待确认”。
- 不只写“客户正常推进”；重点客户/商机必须有阶段、证据、判断和下一步。
- 不把客户级风险混进跨 AE 风险里一笔带过。
- 不输出没有目标、负责人、截止时间和验证标准的下周客户/商机动作。
