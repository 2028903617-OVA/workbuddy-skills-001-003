# R04 - 团队月报

## 目标

团队月报定位为“月度经营复盘”，用于回答：本月团队经营结果如何、Pipeline 和成交结构是否健康、哪些 AE/行业/客户形成趋势性问题、下月资源如何配置、管理节奏如何调整。

月报不是周报堆叠；必须输出趋势、结构和管理判断。

## 输入要求

优先读取或要求用户提供：

- 本月团队目标和实际完成
- 本月成交、回款、Pipeline 期初/期末和阶段结构
- AE 表现分层、异常和趋势
- AE 活跃度、销售记录数、有效跟进数、沉默/待激活成员和数据异常成员
- Pipeline 负责人集中度、客户/行业集中度、逾期商机、空金额商机和阶段缺失记录
- 本月重点行业、重点客户、重点商机和竞品信号
- 本月团队日志、团队周报或本地历史记录
- 数据清洗说明，例如 test 记录、空金额、测试客户/商机、统计截止日和未纳入日期范围

## 输出结构

普通月报必须直接渲染为正文，不要放进 `markdown`、`text` 或其他代码块。默认模块顺序：

1. `# 团队月报 - [团队/范围] - [月份]`
2. `## 🧭 月度经营摘要`：本月团队最终结果、本月最大管理问题、下月最重要管理策略。
3. `## 📊 目标完成与经营结构`：展示目标、成交、回款、Pipeline、深度阶段、AE 覆盖、活跃 AE、沉默/待激活 AE、有效销售记录、数据污染和完成质量。
4. `## 💰 成交与 Pipeline 结构`：写成交结构、回款结构、月初/月末 Pipeline、阶段分布、深度阶段质量、负责人集中度、逾期商机、空金额商机和阶段缺失。
5. `## 👥 AE 表现分层与趋势`：展示核心产出、高潜力、稳定执行、待激活、数据异常、零活动等分层；写 AE、依据、连续变化和管理判断。
6. `## 🤝 重点客户/行业复盘`：写客户/行业/商机、本月变化、负责 AE、关键卡点和下月管理动作。
7. `## ⚠️ 主要风险与管理问题`：写重复延期、Pipeline 偏浅、负责人/客户/行业资源集中、团队活跃度系统性缺失、数据污染、能力短板、机制问题、影响和修正动作。
8. `## 🎯 下月资源配置与管理节奏`：分为 `🔴 P0 主管必须亲自处理`、`🟡 P1 团队协调处理`、`🔵 P2 常规跟进`，同时写主管时间、售前/交付资源、关键 AE 辅导、沉默 AE 激活、数据清理、客户优先级、截止时间和验证标准。
9. `## 🧠 月度趋势判断`：用简短结论说明目标完成、Pipeline 质量、AE 分层、客户/行业风险和管理动作兑现趋势。
10. `## 🧾 数据说明`：团队/AE 覆盖和 CRM 数据覆盖；使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；正文必须使用引用块 `>` 弱化展示。
11. `## 💾 CRM 日志保存确认`：按 `R09_team_journal_storage_confirmation.md` 用中文询问是否保存到 CRM 日志。

## 月报分析规则

- 目标完成率必须结合成交、回款、Pipeline 质量和 AE 结构一起判断。
- 月报必须写团队活跃度和覆盖质量；如能获取团队总 AE 数，必须输出活跃 AE 数、沉默/零活动 AE 数和数据异常 AE 数。无法确认总人数时，只说明已覆盖 AE 范围，不计算比例。
- 缺少目标数据时不计算目标完成率，只输出成交、回款、Pipeline 等事实指标。
- Pipeline 增长但深度商机减少，要标注“增长质量存疑”。
- Pipeline 必须同时看金额、阶段、负责人集中度、逾期、空金额和阶段缺失；负责人集中度过高或大量商机无金额/无阶段时，必须进入风险或数据质量判断。
- 成交结构必须说明成交集中在哪些 AE、客户或行业，是否存在单点依赖；单笔大单必须说明可复制经验或下月跟进策略。
- AE 分层不得只写贡献型和需关注型；如果数据支持，必须识别核心产出、高潜力、待激活、数据异常、零活动等管理状态。
- 同类风险连续出现，要归纳为团队能力、管理机制或市场结构问题。
- 下月 P0 应聚焦主管必须抓的关键客户、关键 AE 或关键机制。
- 数据污染、test 记录、空金额、阶段缺失、统计截止日不完整等问题，必须同时进入数据说明；如果影响经营判断，还要进入“主要风险与管理问题”。
- 必须给出下月资源配置建议：主管时间、售前/交付资源、关键 AE 辅导、沉默 AE 激活、数据清理、客户优先级和月内检查节奏。
- 下月行动必须具备行动项、目标、负责人、截止时间和验证标准；P0/P1 不能只写“持续关注”。
- 月度趋势必须说明成员范围是否一致；如果本月和上月 AE 范围不同，在相关趋势模块内说明口径变化。
- 普通月报直接输出可渲染正文，不要整体包进代码块。
- 不逐日或逐周堆叠流水，不把单日异常直接当作月度趋势；趋势必须有连续证据或明确说明待确认。
- 数据说明放在最后，只展示团队/AE 覆盖和 CRM 数据覆盖；正文必须使用引用块 `>` 弱化展示；CRM 数据使用中文对象名，不展示对象 ApiName、记录 ID 或长串主键；不默认展示数据缺口表。
- 先完成月报 Markdown 正文，再由总流程默认执行一次 `R10_html_report_output.md` 生成 HTML 页面，最后执行日志保存确认；如果输入包含多页签 Excel，必须将 sheet 转为横向导航页签，并在每个页签补充洞察、判断和管理动作；只有用户明确说“只要 Markdown/不要 HTML”时跳过 HTML。不要为“简洁版”生成一份 HTML、再为“展开版”生成另一份 HTML。
- 输出月报后必须用中文询问是否保存到 CRM 日志；用户确认前不得写入。

## 输出粒度

### 简洁版（默认）

适合管理层快速查看月度经营结果：

- 摘要 180 字以内。
- 月度经营指标保留目标、成交、回款、Pipeline、AE 覆盖等核心指标。
- 目标完成与经营结构必须保留活跃 AE、沉默/待激活 AE、有效销售记录或数据质量信号。
- 本月关键结果 3-5 条。
- AE 表现分层只展示分层结论、关键 AE 和异常 AE。
- 重点客户/行业复盘最多展开 5 个。
- 主要风险只列影响下月 P0 或团队目标的风险。
- 下月资源配置与管理节奏 P0 不超过 3 条，P1 不超过 5 条，P2 最多 3 条；P0 优先覆盖关键客户、关键 AE 激活或数据清理。

### 详细版

适合月度经营复盘和管理诊断：

- 展开目标、成交、回款、Pipeline 结构和阶段变化原因。
- AE 表现分层可展开全部已覆盖 AE，并说明分层依据。
- 展开团队活跃度、销售记录、沉默/待激活 AE、数据异常 AE、Pipeline 集中度和数据质量问题。
- 重点客户/行业复盘最多展开 10 个。
- 主要风险写清影响、根因、涉及 AE/客户/行业、修正动作和验证标准。
- 必须归纳团队能力短板、机制问题和下月管理节奏。

无论简洁版还是详细版，都必须保留数据说明和 CRM 日志保存确认。

## 趋势判断

月报至少覆盖以下趋势：

- 团队目标完成趋势
- Pipeline 质量趋势
- Pipeline 负责人/客户/行业集中度趋势
- AE 表现分层变化
- 团队活跃度和沉默 AE 变化
- 数据质量改善或恶化趋势
- 客户/行业风险趋势
- 管理动作兑现趋势

## 禁止行为

- 不逐周复制团队周报。
- 不逐日或逐周堆叠流水。
- 不只写“本月团队拜访多少客户”。
- 不把单日异常直接上升为月度趋势。
- 不用团队平均掩盖关键 AE 或关键客户风险。
- 不用总 Pipeline 掩盖负责人集中、空金额、阶段缺失和逾期商机。
- 不把数据污染、test 记录或统计周期不完整只放在数据说明里轻描淡写；若影响结论，必须进入风险模块。
- 不输出没有负责人和验证标准的管理动作。
