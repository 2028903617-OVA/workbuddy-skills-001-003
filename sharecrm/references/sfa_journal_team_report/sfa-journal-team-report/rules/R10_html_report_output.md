# R10 - HTML 自适应报告输出

## 目标

生成团队日报、团队周报或团队月报时，默认将已生成的 Markdown 正文同步转换成可在手机端和 Web 端阅读的单页 HTML。Markdown 正文必须先在对话中完整展开输出；`.md` 文件只是归档物，不能替代对话内正文。同一份报告只执行一次 HTML 生成。

如果用户提供 Excel / xlsx / 多页签表格，或要求“把附件表格转 HTML / 多页签转页面 / 横向导航页签”，必须把工作簿中的多个 sheet 转成横向导航页签，而不是简单上下拼接表格。HTML 必须好看、有用、有价值：先给管理摘要和经营判断，再按页签展示明细、风险和动作。

HTML 是展示形态，不改变团队报表的分析逻辑、数据来源优先级和 CRM 日志保存确认规则。

团队日报、团队周报、团队月报的 HTML 必须保持统一品牌风格，但信息架构必须随周期变化：

- 团队日报：今日管理看板，突出当日关键结果、异常 AE/客户、主管当天介入和明日动作。
- 团队周报：团队销售战报，突出经营信号、AE 表现、重点商机、跨 AE 风险和下周管理动作。
- 团队月报：月度经营复盘，突出目标完成、Pipeline 结构、AE 分层、行业/客户趋势和下月资源配置。

## 执行条件

本规则默认执行；“生成 HTML、导出 HTML、网页版、手机查看、自适应页面、H5、用浏览器打开、做成页面、附件 Excel/xlsx/表格转 HTML、多页签/多 sheet/横向导航页签”只是加强 HTML 交付意图。只有用户明确说“只要 Markdown、不要 HTML、不用网页、不生成 HTML”时，才跳过本规则。

如果本轮已经基于同一份 Markdown 写出 `.html`，不要再次输出完整 HTML 或生成第二个 HTML 文件；只返回已生成路径。

## 执行顺序

本规则只负责把已完成的 Markdown 团队报表或已解析的附件数据渲染为 HTML，不重新路由、不重新读取周期规则、不重新查询 CRM、不触发 R09 保存确认。输入必须复用总流程已确定的周期、团队范围、时间范围、数据说明和同一份 Markdown 正文。

1. 确认 Markdown 正文已经完整生成并已在对话中展示；如有 Excel/xlsx/CSV 附件，复用已读取的 sheet 名、表头、有效行数、关键指标和异常值。
2. 直接使用 `assets/team_report_template.html` 作为 HTML 模板。
3. 将团队报表正文和附件 sheet 映射到模板占位符。
4. 如果运行环境允许写文件，写出同前缀 `.md` 归档和一个完整单文件 HTML；不能写文件时，在 Markdown 正文后输出一次完整 HTML 内容。
5. 在回复末尾提供可直接打开的 `.html` 路径，并附上 `.md` 归档路径。

正常生成不得读取 `references/html_responsive_design_reference.md`；只有模板缺失、用户要求修改响应式样式、或生成后出现明显布局问题需要排查时才读取。

## 多页签 Excel 映射

当存在多 sheet 工作簿时，按以下规则合并为横向导航页签。sheet 名不完全一致时，按语义归类；未识别的 sheet 进入“数据说明”或追加到最相近业务页签。

| Excel sheet / 语义 | HTML 页签 | 目标 |
| --- | --- | --- |
| 月度汇总、周度汇总、日报汇总、总览、Summary | 总览 | 提炼关键指标、管理摘要、最大风险和下期优先级 |
| 成交明细、订单、回款、收入、Win | 成交明细 | 展示成交/回款清单、负责人贡献、可复制经验 |
| Pipeline明细、商机、机会、漏斗 | Pipeline | 展示金额、阶段、负责人、逾期、集中度和下期可转化质量 |
| AE表现分层、成员表现、销售表现 | AE 表现 | 展示 AE 分层、产出、活跃度、异常和管理判断 |
| 重点客户复盘、客户复盘、行业复盘、重点商机 | 客户复盘 | 展示客户/行业/商机进展、优先级和下一步动作 |
| 风险与行动计划、风险预警、行动计划 | 风险行动 | 展示系统性风险、等级、建议措施和 P0/P1/P2 管理动作 |
| 数据说明、口径说明、来源说明 | 数据说明 | 展示数据来源、统计周期、人员范围、清洗口径和生成时间 |

典型页签包括：`月度汇总`、`成交明细`、`Pipeline明细`、`AE表现分层`、`重点客户复盘`、`风险与行动计划`、`数据说明`。

## 页签内容要求

每个横向页签都必须有“判断价值”，不能只贴原始表格。

- `总览`：输出 3-6 个核心指标卡、150 字以内管理摘要、最大风险、下期主管最重要动作。
- `成交明细`：保留成交表格；补充成交集中在哪些 AE/客户/行业、最大单、是否可复制。
- `Pipeline`：保留 Pipeline 表格；补充阶段分布、逾期、空金额、阶段缺失、单一 AE/客户/行业集中度、下期转化判断。
- `AE 表现`：保留 AE 分层表格；补充分层结论、活跃度、销售记录数、沉默/待激活成员、数据异常成员和每类 AE 的管理动作，不做无证据能力定性。
- `客户复盘`：保留客户/商机表格；补充金额、阶段变化、赢率变化、负责 AE、关键人/决策链、本期进展、当前判断、下期动作、P0/P1 优先级和主管介入建议。
- `风险行动`：保留风险表格；周报必须区分跨 AE 风险和客户级风险，客户级风险写风险等级、依据、已动作和下一步推进/止损策略；月报将活跃度系统性缺失、Pipeline 集中度、逾期商机、数据污染等风险转成 P0/P1/P2 动作。P0/P1 必须包含负责人、对象、截止时间和验证标准。
- `数据说明`：弱化展示数据来源、统计周期、人员范围、清洗口径、test 记录/空金额/阶段缺失处理和生成时间；不要展示对象 ApiName、记录 ID 或长串主键。

如果附件中的某 sheet 只有表格没有结论，必须基于表格数据提炼 1-3 条管理洞察；缺少字段时写“待确认”，不要编造。

## 内容映射

将 Markdown 模块映射到模板区域：标题/团队范围/时间 -> 顶部信息区；摘要 -> 总览页签；管理信号/关键经营信号/目标完成 -> 健康卡和总览指标卡；关键结果和上周管理动作闭环 -> 总览或风险行动；AE 异常/表现/分层 -> AE 表现；重点客户/商机/行业 -> 客户复盘；跨 AE 风险、客户级风险、管理问题和 P0/P1/P2 -> 风险行动；数据说明 -> 数据说明。CRM 日志保存确认可以留在 HTML 之后的对话确认，不必写入 HTML 主体。

优先使用 `assets/team_report_template.html` 并填满模板占位符。缺失数据时用“待确认 / 信息不足 / 数据覆盖待确认 / 管理判断待确认”，不要留裸占位符。关键占位符包括：`{{report_type}}`、`{{data_scope}}`、`{{team_health_score}}`、`{{team_health_grade}}`、`{{brand_text}}`、`{{period_brief_label}}`、`{{subtitle}}`、`{{health_label}}`、`{{overview_title}}`、`{{overview_lead}}`、`{{orders_label}}`、`{{orders_lead}}`、`{{pipeline_label}}`、`{{pipeline_lead}}`、`{{ae_label}}`、`{{ae_lead}}`、`{{accounts_label}}`、`{{accounts_lead}}`、`{{risks_label}}`、`{{risks_lead}}`、`{{executive_summary}}`、`{{management_insights}}`、`{{tab_overview}}`、`{{tab_orders}}`、`{{tab_pipeline}}`、`{{tab_ae_performance}}`、`{{tab_accounts}}`、`{{tab_risks_actions}}`、`{{tab_data_note}}`。旧生成链路至少要填满 `summary_cards`、`metrics`、`ae_performance`、`customer_opportunity`、`cross_ae_risks` 和 `p0/p1/p2_actions`。

模板固定文案必须适配中文环境：不要保留英文品牌、英文报表类型或英文健康度。日报、周报、月报的顶部、健康度标签和页面说明必须随周期变化。

## 分周期 HTML 结构

| 周期 | 顶部/健康标签 | 结构重点 |
| --- | --- | --- |
| 团队日报 | “团队日报速览 · 今日管理看板”；“今日团队健康度/今日异常闭环度” | 轻量页签：总览、AE 今日异常、重点商机异动、风险行动、数据说明；不展示成交明细长表和 Pipeline 空壳 |
| 团队周报 | “团队周报速览 · 销售战报”；“周度团队健康度” | 总览、成交与回款、Pipeline、AE 表现、客户复盘、风险行动、数据说明；必须展示上周管理动作闭环、重点客户/商机台账、跨 AE 风险和客户级风险 |
| 团队月报 | “团队月报速览 · 月度经营复盘”；“月度团队健康度/月度经营健康度” | 总览、成交结构、Pipeline 结构、AE 分层趋势、客户/行业复盘、管理问题与下月策略、数据说明；突出结构趋势、沉默/待激活 AE、数据异常、负责人集中度、逾期/空金额/阶段缺失 |

周报不逐日罗列流水，月报不展示按周流水清单。

## HTML 输出要求

- 输出必须是完整 HTML 文档，包含 `<!doctype html>`、`html`、`head`、`body`。
- 必须包含 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`。
- CSS 优先内联在 `<style>` 中；允许少量内联 JS 用于本地页签切换；不得依赖外部 CSS、字体或 CDN。
- 页面默认 mobile-first，桌面端通过 media query 增强布局。
- 必须使用横向导航页签：桌面端 sticky tabs，移动端横向滚动 tabs。
- 每个 tab panel 只显示当前页签；打印时所有 panel 展开。
- 不使用固定大宽度容器；主体容器使用 `max-width` 和响应式 padding。
- 指标区域使用 responsive grid。
- 表格必须包在横向滚动容器中；宽表不要撑破屏幕。
- 行数很多的明细表默认保留关键字段；完整明细可以分组或折叠，但不得删除风险、金额、负责人、阶段、优先级等管理字段。
- 颜色克制，适合销售主管经营看板；使用白色/浅灰工作台背景和少量 logo 黄 `#ffb400` 强调，不要做营销页或大幅 hero。
- 支持浏览器打印，至少提供 `@media print` 基础样式。

## 用户可见数据限制

- 不展示 `JournalObj`、`ActiveRecordObj` 等对象 ApiName。
- 不展示 `_id`、记录 ID、数据 ID 或长串主键。
- 不展示 `work_summary`、`journal_time` 等字段 ApiName。
- CRM 数据说明使用中文对象名，例如“日志、销售记录、日程、商机、订单、回款”。
- 如果附件原始数据说明包含对象 ApiName，HTML 对用户展示时必须转成中文对象名或概括为“CRM日志、商机、销售记录、日程、订单、回款”等。
- 系统字段、锁定状态、生命周期字段不进入 HTML。

## 文件交付

如果运行环境允许写文件，成对交付同前缀文件：`team-report-[period]-[date-or-range].md` 和 `team-report-[period]-[date-or-range].html`，例如 `team-report-weekly-<YYYY-WXX>.md/html`。对话中仍要直接完整展示 Markdown 正文；不要只交付路径、只交付 `.md` 或 `.html`，也不要同时生成“简洁版 HTML”和“完整版 HTML”。不能写文件时，先输出 Markdown 正文，再输出一次完整 HTML 内容。

## 禁止行为

- 不把 HTML 输出当成已保存 CRM。
- 不在用户未确认前写入 CRM 日志。
- 不为了美观删减关键风险、管理动作或数据说明。
- 不把多页签 Excel 直接上下拼接成一个长页面。
- 不只复制表格而不输出洞察、判断和下一步动作。
- 不输出依赖外网才能正常显示的 HTML。
- 不在 HTML 中暴露系统字段、对象 ApiName 或记录 ID。
