# 线索全局诊断标准 — Global_Diagnosis_Criteria

用于形成线索诊断正文的统一判断框架。这是**诊断标准**，不是对象事实；每条结论必须落到对象数据、评分结果、销售记录或阶段输入上，并标注「事实 / 判断 / 待确认问题」。

本文件按 `output_template.md` 的输出章节顺序组织，已内聚原拆分文件中的风险识别、阶段推进与跟进动作标准。后续生成线索诊断时优先读取本文件作为唯一标准入口。

## 0. 通用规则

### 评分完整度对诊断的影响

- **维度分 + 评分依据**：作为主依据，逐维结合得分、依据与对象事实输出「事实 / 判断 / 待确认问题」。
- **仅维度分、无依据**：可做方向性诊断，标注解释性受限；低分只提示“需重点核验”，不写成已证实事实。
- **仅总分**：只描述整体健康度，不做维度根因拆解，也不凭总分判定最短板维度。
- **无评分**：先执行 `get_profile_score --objectApiName LeadsObj`；CLI 失败或结果不可用时，再执行 `sfa-leads-score`。两者均不可用时不能形成全局诊断。

### 来源分类

| 来源 | 包含 |
|:---|:---|
| CRM | 线索字段、联系人、销售记录等对象事实 |
| Scoring_Result | 首选 `get_profile_score` 或回退 `sfa-leads-score` 生成的线索评分结果中的维度分、特征与依据；使用时记录实际来源 |
| AI_Stage | 本 skill 根据线索阶段/状态、主数据与销售记录直接生成的真实阶段判断 |
| Knowhow | 本文件中的诊断标准、风险规则、跟进策略方法论 |
| AI 推断 | 基于事实和标准形成的解释性判断；不得写成 CRM 已证实事实 |

### 禁止写法

- 禁止无证据写“客户已认可 / 预算已明确 / 可直接转商机 / 应立即报价 / 应拉高层会”等强推进结论。
- 禁止把 AI 推断或销售经验写成 CRM 已证实事实。
- 禁止脱离真实阶段边界输出建议，如潜在线索阶段直接写商务推进。
- 禁止空泛表达：`持续跟进`、`加强沟通`、`保持联系`、`适时推进`、`继续观察`。

## 概要

概要只做摘要，不拆「事实 / 判断 / 待确认问题」。必须覆盖：

- 线索名称、诊断日期、当前阶段、AI 判定阶段和阶段判断说明。
- 综合评分、综合评级，直接使用选定评分来源（CLI 或 `sfa-leads-score` 回退）的结果，并记录来源。
- 需求描述：只能从线索数据、销售记录和用户补充事实整理，不得编造需求。

## 一、核心诊断结论

本章节把全局诊断、关键缺失项和跟进策略压缩成管理层可读结论。

输出字段要求：

- **一句话结论**：回答这条线索现在值不值得投入、主要卡点是什么。
- **转化三要素**：必须是行动目标型，不是现状描述型；围绕 Timeline、Sponsor、现场拜访 / 深度互动。
- **核心跟进策略**：只输出一句主策略，不展开动作清单。建议句式：`当前应以【主策略】为主，优先处理【最高优先级短板/风险】，在【阶段边界或关键信息】满足后再推进【下一阶段动作】。`
- **关键行动项**：只列 3 项最高优先级动作，必须能回溯到全局短板或风险。

## 二、全局诊断结果

全局诊断以选定评分来源返回的 `Scoring_Result` 维度结果为主骨架。评分优先使用 `get_profile_score --objectApiName LeadsObj`，仅在 CLI 结果不可用时回退 `sfa-leads-score`，并保留所选来源的维度名称和顺序。评分是诊断线索而非事实：低分提示短板方向，高分提示相对健康，但都须落回 CRM 事实、销售记录与评分依据验证，不能把分数直接当结论。

### 评分维度

评分维度不预设固定集合。必须逐行读取选定 `Scoring_Result` 的 `dimension` 数组，保持返回的名称、顺序、分数及可用依据；不同租户或评分模型返回的维度可以不同。每个维度分别写明：

1. **事实**：对应线索字段、销售记录、特征原值或评分触发依据。
2. **判断**：该维度对当前阶段成熟度的方向性影响。
3. **待确认问题**：不能由当前事实确认的部分。

评分结果只有综合分而没有 `dimension` 时，只输出整体健康度，明确解释性受限，不自行拆分维度或补造固定问题。

### 诊断输出要求

- 每个维度必须同时说明评分、评分依据和来源。
- 每条判断尽量区分事实、判断、待确认问题。
- 低分项只能提示核验方向，不得直接写成已证实问题。
- 全局诊断的短板必须驱动第三、四、五部分；关键缺失项应引用实际返回的维度名称，而不是套用七问或三要素标签。

## 三、关键缺失项

本章节不是重复全局诊断，而是把当前最影响线索继续培育、转化或推进的缺失项显式提炼出来。

### 缺失项来源

- 全局诊断中的明显短板，如关键联系人未接触、计划时间不明确、Sponsor 不成立、现场拜访不足、客户架构未掌握、品牌认可弱。
- 当前真实阶段对应的未达标项。
- 线索对象特有风险。
- 通用销售管理风险。

### 风险优先级

- **P0**：不处理会阻断进入下一阶段，或导致线索长期无法转化 / 被判定无效。
- **P1**：会显著降低转化概率、拖慢培育节奏、造成线索继续冷却。
- **P2**：需要关注，但短期不直接阻断推进。

### 线索对象特有风险映射

| 优先级 | 常见触发 | 影响 | 优先化解方向 |
|:---:|:---|:---|:---|
| P0 | 联系方式真实性存疑，无法完成首次有效触达 | 线索真实性无法确认 | 多渠道验证联系方式并确认可达性 |
| P0 | 高意向但长期未转商机 | 存在明显流失窗口 | 锁定转化条件并推动转商机 |
| P0 | 转化窗口已出现但需求、联系人或时间表始终未确认 | 无法进入下一阶段 | 补齐需求、关键人、Timeline |
| P1 | 需求表达模糊 | 难以判断真实业务场景 | 用 SPIN 澄清业务场景与痛点 |
| P1 | 决策层级或关键对接人不清 | 无法评估转化价值 | 识别关键联系人及其角色 |
| P1 | 最近跟进中断、互动冷淡 | 线索热度下降 | 约定下一次明确跟进动作 |
| P2 | 时间窗口和采购计划不清晰 | 短期推进节奏不稳 | 补充采购 / 预算时间表 |
| P2 | 判断依据不足 | 结论可信度受限 | 补齐资料并保持低成本培育 |

### 输出要求

- “缺失项”使用具体缺口描述，如“需求仍停留在口头兴趣”“关键联系人角色未确认”。
- “当前状态”回答是否已确认、部分确认或未确认。
- “表面现象”只写可见现象。
- “深层判断”可以承接隐性诉求、组织阻力、个人风险、预算或时间窗口伪成熟信号，但必须标注待验证项。

## 四、跟进策略

本章节承接全局诊断和关键缺失项，回答“这条线索下一步应该优先怎么跟”。先做策略裁决，再说明当前打法与建议打法。

### 策略输入来源

1. **真实阶段输入**：使用本 skill 直接生成的 `AI_Stage`，判断线索处于潜在线索 / MQL / SQL / 可转商机 / 信息不足。
2. **全局短板输入**：从选定 `Scoring_Result.dimension` 返回的低分项、弱证据项与待确认问题中识别最大缺口；不得假定七问、三要素或 BANT 维度存在。
3. **风险输入**：结合 P0 / P1 / P2 风险判断哪些问题先处理。
4. **事实充分度输入**：区分已确认事实、模糊信号、待验证项；证据不足时不输出高置信推进动作。
5. **销售记录输入**：判断是否已有有效触达、是否存在互动降温、是否锁定下一次动作。

### 策略裁决三分类

| 裁决结论 | 适用含义 | 关键条件 |
|:---|:---|:---|
| 补齐关键信息 | 线索仍处于验证期，主要问题是事实不足、阶段不清或真实性未确认 | 联系方式未验证；首次有效触达未建立；需求、角色、时间窗口主要依赖模糊信号 |
| 培育推进 | 线索基本有效，但需求、决策角色、价值认知或推进节奏仍不稳定 | 已有初步触达和兴趣；但需求场景不清、关键人未识别、互动冷淡、品牌认可或 Timeline 较弱 |
| 转化推进 | 线索已具备明确需求和推进基础，重点是补齐临门一脚并推动转商机 | 需求与业务场景较明确；存在 Sponsor / 关键联系人线索；时间窗口可判断；下一步动作可以锁定 |

证据不足时，不下激进的“转化推进”结论，优先输出“补齐关键信息”或“培育推进”，并标注待验证项。

### 阶段适配规则

| 阶段 | 主目标 | 不允许越界 |
|:---|:---|:---|
| 潜在线索 | 确认线索真实性与可达性 | 未完成首次有效触达前，不给需求推进、报价推进或转商机建议 |
| 市场认可线索（MQL） | 澄清真实需求、业务场景与转化价值 | 需求未明时，不提前进入采购、预算或商务推进表述 |
| 销售认可线索（SQL） | 补齐 Sponsor / Timeline / 下一步动作并推动转商机 | Sponsor / Timeline 未闭环时，不写“可直接转化” |
| 阶段缺失 | 补齐阶段判断与关键信息 | 不给高置信阶段结论 |

### 策略类型库

主策略只选 1 个，必要时可带 1 个辅助策略。

| 主策略 | 适用核心矛盾 | 表达重点 |
|:---|:---|:---|
| 真实性验证型 | 联系方式、身份或线索有效性仍不确定 | 先确认可达性、真实性与是否值得投入 |
| 需求澄清型 | 真实业务场景、痛点与价值仍不清楚 | 用结构化提问补齐场景、痛点、影响与预期收益 |
| 关键人识别型 | 对接人角色模糊，无法判断是否有推动力 | 识别联系人角色、影响力、决策链与客户架构 |
| 节奏激活型 | 线索有基础但明显降温，互动冷淡或下一步未锁定 | 重新激活兴趣、锁定下一次动作 |
| 转商机推进型 | 线索已具备转化基础，但 Sponsor / Timeline / 下一步动作仍未闭环 | 先锁推进条件，再触发转商机动作 |
| 低频培育型 | 有初步兴趣但短期窗口不成熟 | 维持低成本、有节奏的触达与观察 |

## 五、跟进建议

跟进建议是动作层，必须从第四部分策略拆解而来。每条动作都要写清动作、目的、对应短板 / 风险、负责人 / 对象、节奏。

### 阶段 → 退出条件 → 推进动作

| 阶段 | 退出条件 | 未达标项 | 动作 | 优先级 |
|:---|:---|:---|:---|:---:|
| 潜在线索 | 完成首次有效触达，确认联系方式真实可达 | 联系方式未验证 | 多渠道尝试触达（电话 + 企微 + 邮件） | P0 |
| 潜在线索 | 完成首次有效触达 | 长时间未首触 | 48 小时内安排首次跟进 | P0 |
| MQL | 明确客户真实需求与业务场景 | 需求模糊 | 下一次沟通用 SPIN 澄清现状 / 痛点 / 影响 | P0 |
| MQL | 判断是否值得转商机 | 决策层级不清 | 确认对接人角色与决策 influence | P1 |
| MQL | 提升响应与兴趣 | 互动冷淡 | 用客户行业价值案例重新激活 | P1 |
| SQL | 满足转商机标准 | 需求已明确但未转化 | 走 `sfa-leads-convert` 转商机并约定下一步 | P0 |
| SQL | 锁定推进节奏 | 时间窗口不明 | 确认采购 / 预算时间表 | P1 |

### 动作生成规则

- 每条动作建议都应回溯到至少一项：真实阶段未达标项、全局诊断短板、P0 / P1 / P2 风险、销售记录中的节奏问题。
- 当信息不足时，优先建议补齐关键信息或验证关键假设，而不是直接推进报价、转商机或高层会。
- 第四部分“跟进策略”写策略层，第五部分“跟进建议”写动作层，避免内容重复。

### 方法论参考

- **SPIN**：Situation / Problem / Implication / Need-payoff，用于澄清需求。
- **线索分级跟进**：高潜高频触达，待培育定期激活，低优先降频或退回。
