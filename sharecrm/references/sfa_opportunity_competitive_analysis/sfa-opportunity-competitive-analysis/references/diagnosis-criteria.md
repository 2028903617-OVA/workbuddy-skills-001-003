# 竞争分析诊断标准

## 适用范围

本文件只适用于 `NewOpportunityObj` 的商机竞争分析主流程。

若用户本次明确提供额外竞争事实，可作为补充证据使用；但不得替代 CRM 中已查询到的商机事实。

## 使用原则

1. 先补三件套，再做五维判断。
2. 五维分析必须结合客户偏好和证据完整性决定权重与分值。
3. 赢单路径必须把我方优势、我方短板、竞品动作和客户关注点串起来。
4. 竞争对手明细、竞品报价、客户倾向、关系覆盖、竞品动作必须有证据；缺失证据不能视为正向证据。
5. 竞对企业风险只作为风险观察和验证建议，不作为五维评分的直接替代。
6. 推断性结论必须标记 `⚠️ 推断`。
7. 诊断标准只能作为分析框架，不能当作项目竞争事实直接输出。

## 竞争情报三件套

### 三件套定义

| 件套 | 内容 | 典型证据 | 优先级 |
|:---|:---|:---|:---:|
| 竞品产品功能对比 | 竞品产品能力、平台能力、功能适配、技术短板 | 竞争对手明细、销售记录、客户评价、竞品材料、用户补充 | P0 |
| 竞品报价策略 | 竞品价格区间、低价动作、折扣、付款方式、报价压力 | 竞争对手明细、报价单、报价明细、销售记录、用户补充 | P0 |
| 竞品客户关系 | 竞品覆盖了谁、谁倾向竞品、竞品是否切高层或影响关键人 | 联系人关系、销售记录、用户补充 | P1 |

### 收集状态口径

| 状态 | 判定标准 |
|:---|:---|
| 已完成 | 有清晰事实，且足以支撑策略判断 |
| 收集中 | 有部分线索，但仍缺关键事实 |
| 未收集 | 没有可用证据 |
| 无法判断 | 数据源不可用、字段不可见或事实冲突未澄清 |

### 使用规则

- 前两件优先级最高：产品功能和报价策略缺任何一件，五维判断都要降低可信度。
- `CompetitiveLinesObj` 是竞品名单、竞争产品、我方优势、我方劣势、竞品报价线索和备注的核心结构化来源；读取为空只能说明“暂未发现明确竞品明细”，不得据此断言无竞争。
- 客户关系不能只看“谁接触多”，要看其是否影响选型、预算、流程或高层判断。
- 查询为空不等于竞品没有动作，只能说明“当前无记录”。
- 三件套不是一次性收集完，应随着销售记录和报价变化持续更新。

## 五维竞品量化分析

### 五个维度

| 维度 | 核心问题 | 典型证据 |
|:---|:---|:---|
| 品牌力 | 客户是否明显信任大品牌、行业排名或成功案例 | 竞争对手明细、客户评价、历史选型、品牌偏好、客户层级 |
| 产品平台 | 产品功能、平台架构、扩展性、集成能力是否匹配 | 竞争对手明细、产品对比、演示反馈、技术评审记录 |
| 行业 Know-how | 是否理解客户行业流程、场景和最佳实践 | 竞争对手明细、行业案例、业务方案、客户对场景理解的评价 |
| 本地交付 | 交付响应、服务资源、实施经验、风险兜底能力 | 交付承诺、服务记录、客户本地化要求 |
| 商务成本 | 价格、折扣、付款方式、总体拥有成本和 ROI | 竞争对手明细、报价单、报价明细、竞品报价线索 |

### 评分口径

- 每个维度按 `0-10` 分评分。
- 评分对象至少包括“我方”和 1 个重点竞品；竞品超过两个时只选择当前影响最大的 1-2 个进入主分析表。
- 未进入主分析表的其他竞品不得丢弃，统一写入“情报缺口与补充计划”，用于后续核实是否仍参与本项目、报价是否有效、关系覆盖是否构成风险。
- 主要竞品优先从 `CompetitiveLinesObj` 的关联竞争对手明细识别；商机主数据 `competitor` 字段、销售记录和用户补充可作为补充或交叉验证。
- 分值必须基于证据完整性保守判断，不能因为描述合理就给高分。
- 某维度几乎无证据时，优先给 `0-3` 或写 `无法判断`；不得用空泛行业常识填满分。
- 有部分证据但不能闭环时，优先给 `4-6`，并明确仍需补充的信息。
- 证据充分且能支撑优势 / 劣势判断时，可给 `7-10`。

### 权重口径

权重可用 1-5 档表示，输出时统一写数字权重。

| 客户类型 / 偏好 | 品牌力 | 产品平台 | 行业 Know-how | 本地交付 | 商务成本 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 大型企业 / 集团客户 | 4 | 4 | 5 | 3 | 3 |
| 中型企业 | 3 | 4 | 4 | 4 | 4 |
| 小型企业 / 价格敏感 | 2 | 3 | 3 | 4 | 5 |
| 强监管 / 高合规 | 4 | 5 | 4 | 4 | 3 |
| 快速落地 / 服务敏感 | 3 | 3 | 4 | 5 | 4 |

如果客户类型或偏好无法确认，使用默认权重：品牌力 3、产品平台 3、行业 Know-how 5、本地交付 4、商务成本 4，并标注 `⚠️ 推断`。

### 加权计算

```text
单方加权得分 = Σ(维度得分 × 维度权重) / Σ(维度权重) × 10
```

结果按 `0-100` 表示。若任一 P0 三件套缺失，综合得分可以计算，但必须标注“可信度受限”。

### 竞争态势判断

| 判断 | 标准 | 输出要求 |
|:---|:---|:---|
| 领先 | 我方加权得分比主要竞品高 10 分以上，且关键 P0 证据较完整 | 说明领先来自哪些维度 |
| 相持 | 我方与主要竞品差距在 10 分以内，或优势与短板互相抵消 | 说明突破点 |
| 落后 | 我方加权得分比主要竞品低 10 分以上，或关键客户偏好维度明显弱 | 说明补短板或绕行路径 |
| 无法判断 | 竞品、报价、客户倾向或产品关键证据不足 | 先给情报补充计划 |

若 `CompetitiveLinesObj` 为空但销售记录、客户反馈或用户补充显示存在竞品、自建替代或历史供应商延续，应把竞争态势可信度降级，并把“补充竞争对手明细 / 核实隐性竞品”列为 P0 情报缺口。

多竞品场景下，竞争态势是对“我方相对于主分析竞品组合”的综合判断，而不是对所有竞品逐一给出胜负结论。若竞品 A 与竞品 B 对我方形成不同压力，应在五维证据说明和攻防策略中分别写明。

## 竞对企业风险观察

竞对企业风险用于补充判断客户选择竞品后的供应商风险，主要服务于“风险攻防”和赢单路径中的验证动作。它不是五维评分项，不得因为检索到风险记录就直接判定竞品产品、价格或交付能力不成立。

### 风险来源

| 来源 | 用途 | 使用规则 |
|:---|:---|:---|
| 结构化企业风险查询 | 识别经营异常、行政处罚、司法风险、税务风险、破产等记录 | 作为主要风险证据 |
| 互联网搜索 | 补充公开新闻、舆情、公告和行业讨论 | 只能作为线索，需交叉验证 |
| 销售记录 / 客户反馈 | 判断风险是否被客户关注或影响选型 | 可用于判断竞争影响 |
| 用户明确输入 | 补充竞对公司主体或风险线索 | 需标明来源 |

### 风险分级

| 等级 | 判定口径 | 建议处理 |
|:---|:---|:---|
| 高 | 存在失信、限制高消费、重大税收违法、破产、严重违法，或多类司法 / 行政风险集中出现 | 作为 P0 风险验证点，推动客户核实供应商稳定性与履约风险 |
| 中 | 存在行政处罚、经营异常、被执行、开庭公告、裁判文书等记录，但影响范围或时效性需要核实 | 作为 P1 验证点，结合项目交付、合规和采购要求判断影响 |
| 低 | 仅有少量低相关或历史较久记录，且未显示持续风险 | 可作为背景观察，不主动放大 |
| 无法判断 | 竞对主体不清、查询失败、结果冲突或只有未经核实的搜索线索 | 列为情报缺口，不输出确定结论 |

### 使用边界

- 企业风险结论必须写成“风险观察”或“需验证事项”，不得写成诋毁竞品的攻击话术。
- 结构化风险查询为空，只能写“当前未检索到记录”，不得写“无风险”。
- 互联网搜索结果不得单独支撑高风险结论；必须与结构化风险、销售记录或客户反馈交叉验证。
- 与本商机无关、主体不清或明显同名误匹配的风险信息不得纳入结论。
- 输出正文不逐条铺开敏感明细，只保留风险类型、等级、影响判断和建议验证动作。

### 对竞争分析的影响

| 影响位置 | 使用方式 |
|:---|:---|
| 竞争对手画像 | 增加企业风险观察，不替代核心优势 / 劣势 |
| 五维分析 | 不直接改分；如风险明显影响交付连续性，可在“本地交付 / 服务稳定性”证据说明中标注影响 |
| 风险攻防 | 转化为客户验证问题，如供应商稳定性、合规记录、项目履约保障 |
| 赢单路径 | 形成验证动作，如“补充竞对风险核查材料”“引导客户关注履约保障” |
| 情报缺口 | 竞对主体不清、风险记录需核实时列为 P0/P1 缺口 |

多竞品场景下，只对进入主分析表的竞品输出企业风险观察；其他竞品的企业风险主体待确认或未查询时，写入“情报缺口与补充计划”。

## 差异化定位

差异化定位必须同时回答三个问题：

1. 客户最在意什么。
2. 我方相对竞品真正强在哪里。
3. 这个优势如何转化为客户能感知的业务价值。

常见差异化方向：

| 我方优势 | 竞品短板 | 进攻策略 |
|:---|:---|:---|
| 行业 Know-how 强 | 竞品行业案例少 | 展示同类场景案例和业务指标 |
| 本地交付强 | 竞品响应慢 | 强调本地团队、响应机制和风险兜底 |
| 产品贴合场景 | 竞品功能泛化 | 用客户关键流程做场景化演示 |
| 商务方案灵活 | 竞品价格高或付款硬 | 设计分期、组合包、ROI 说明 |
| 关系覆盖更深 | 竞品只覆盖流程角色 | 组织高层 / 业务关键人对齐价值 |

差异化故事线应是 2-3 句话，不要写成口号。证据不足时写 `待补充`。

`CompetitiveLinesObj` 中的 `our_advantage`、`our_disadvantage`、`competitive_product` 和 `remark` 可直接作为差异化定位的结构化输入；但仍需用销售记录、客户反馈或用户补充事实校验，不得把内部填写项直接写成客户已认可结论。

## 攻防策略

### 策略类型

| 策略类型 | 目标 | 典型动作 |
|:---|:---|:---|
| 产品攻防 | 证明我方更适配关键场景，或弱化竞品功能优势 | 场景化演示、技术澄清、差异点材料 |
| 价格攻防 | 避免被低价牵着走，转向 ROI / TCO / 风险成本 | 价值测算、分期方案、交付保障说明 |
| 关系攻防 | 找到真实影响人和决策人，避免被竞品单点突破 | Coach 引荐、高层拜访、多角色覆盖 |
| 案例攻防 | 用同类客户证明可信度，削弱竞品品牌或经验优势 | 同行业案例、标杆参访、客户证言 |
| 风险攻防 | 暴露竞品交付、集成、服务、合规等潜在风险 | 风险清单、POC 验证、验收标准前置 |

### 话术使用规则

- 话术只能作为建议要点，不得包装为客户已说过的话。
- 若话术基于模型组织语言，输出时写成“话术要点”，不要声称来自 CRM。
- 价格和竞品短板没有证据时，不做直接攻击，只做验证型提问。
- 竞对企业风险只能转化为验证型问题或风险核查建议，不做诋毁性表达。

### 典型话术要点

| 场景 | 话术要点 |
|:---|:---|
| 被问到“你们和 XX 比怎么样” | 先承认竞品优势，再把差异拉回客户关键场景、交付保障和长期价值 |
| 竞品压低价格 | 不直接跟价，先拆总拥有成本、实施风险、服务响应和业务收益 |
| 竞品品牌更强 | 承认品牌差异，再强调专注领域、同类案例和项目成功率 |
| 竞品功能更多 | 区分“功能多”和“适配关键流程”，推动客户用核心场景验证 |
| 竞品关系更深 | 不正面评价关系，转向多角色价值沟通和真实决策链覆盖 |

## 赢单路径设计

赢单路径必须落到具体动作，不只写策略方向。

每个动作至少包含：

- 优先级：P0 / P1 / P2
- 动作
- 目的：解决五维或三件套中的哪个缺口
- 负责人 / 对象
- 时间
- 完成标志

设计顺序：

1. 先补 P0 情报缺口，尤其是竞品产品和报价。
2. 再围绕客户最关注维度建立差异化证据。
3. 同步处理关系覆盖或决策链风险。
4. 最后准备商务策略和攻防材料。

## 情报缺口追踪

### 缺口定义

情报缺口不是“知道得少”，而是“少了会影响策略判断的关键信息”。

常见缺口：

- 竞品报价
- 竞争对手明细缺失或未更新
- 竞品切入角度
- 竞品产品真实短板
- 客户最终倾向
- 竞品关系覆盖
- 关键人对我方 / 竞品的评价
- 客户预算和付款偏好
- 竞对企业风险证据不足或主体待确认
- 非重点竞品是否仍参与本项目、报价是否有效、关系覆盖是否构成风险

### 优先级口径

| 优先级 | 判定标准 |
|:---|:---|
| P0 | 不补齐会影响竞争态势、报价或赢单路径判断 |
| P1 | 会影响策略细节，但不阻断主判断 |
| P2 | 有助于完善材料或后续监控 |

### 获取方法

| 缺口类型 | 获取方法 |
|:---|:---|
| 竞品报价 | 竞争对手明细、报价记录、生态伙伴、客户侧验证、历史案例 |
| 竞品产品能力 | 竞争对手明细、客户演示反馈、POC、竞品材料、售前对比 |
| 竞争对手明细 | 补录或核实 `CompetitiveLinesObj`，并与销售记录、客户反馈交叉验证 |
| 竞品关系覆盖 | Coach 侧面了解、会议参与人、销售记录复盘 |
| 客户倾向 | 多角色访谈、评审反馈、关键问题追问 |
| 竞品动作 | 销售记录跟踪、客户反馈、伙伴渠道 |
| 竞对企业风险 | 结构化企业风险查询、互联网搜索、销售记录或客户反馈交叉验证 |

补齐缺口后，应反向更新三件套状态、五维分析和赢单路径。
