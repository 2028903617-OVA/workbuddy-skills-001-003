# 商机全局诊断标准 — Global_Diagnosis_Criteria（knowhow）

形成商机"全局诊断结果"的判断框架。是诊断标准，不是对象事实；每条结论须落回商机数据/评分依据，并标注「事实 / 判断 / 待确认问题」。

## 诊断维度（以所选评分来源返回结果为准）
| 维度 | 依赖 knowhow / 来源 |
|---|---|
| `<首选 CLI 或回退评分 skill 返回的维度名称>` | 按维度语义选择对应诊断 know-how；未知维度保留原名并依据 CRM 事实解释 |

全局诊断以所选 `Scoring_Result` 维度结果为唯一主骨架。首选 `get_profile_score` 返回非空且可用的评分信息；仅在 CLI 调用失败、结果为空、无评分信息或对象不一致时使用 `sfa-opportunity-score` 输出。必须保留所选来源返回的维度名称、顺序、得分和评分依据，不得套用固定维度清单或自行补分。评分是诊断线索而非事实：低分提示短板方向、高分提示相对健康，但都须落回 CRM 事实、销售记录与评分依据验证，不能把分数直接当结论。`flow.md` / `output_template.md` 只改变组织与呈现，不改变此优先级。

## 评分完整度对诊断的影响
- **维度分 + 评分依据**：作为主依据，逐维结合得分、依据与对象事实输出「事实 / 判断 / 待确认问题」。
- **仅维度分、无依据**：可做方向性诊断，标注解释性受限；低分只提示“需重点核验”，不写成已证实事实。
- **仅总分**：只描述整体健康度，不做维度根因拆解，也不凭总分判定最短板维度。
- **无评分 / 评分来源不明**：先执行 `get_profile_score`；若 CLI 无可用结果，执行 `sfa-opportunity-score`。两者都无法得到可用评分时才阻断诊断。

### 来源分类
每条评分依据判断同时标注**来源**
| 来源 | 包含 |
|:---|------|
| CRM | CRM 结构化数据和销售记录等，如 商机XXX，联系人XXX，销售记录XXX；其中XXX取对象name字段值 |
| Knowhow | 本项目沉淀的诊断标准、风险规则、赢单策略（`references/` 目录） |

## 结论分级（每条标注「事实 / 判断 / 待确认问题」）
- **可推进 / 健康**：需求匹配、决策链推进、节奏与商务条件均正向。
- **有风险**：决策链 / 竞争 / 预算等关键维度存在明显短板。
- **停滞 / 存疑**：阶段长期停留、关键人未打透或缺少实质推进信号。

## 需求分析
用于独立生成 `output_template.md` 的「## 三、需求地图分析」章节。

### 一、固定输出结构
先输出 3 个摘要字段：
- 一句话判断
- 需求成熟度
- 当前我方命中度

再输出 4 行判断表：
- 表面需求
- 真实推力
- 推进条件
- 当前错位

表格固定 4 列：`判断项 / 判断依据 / 当前结论 / 对推进的影响`。

### 二、四个判断项的执行标准
| 判断项 | 核心判断 | 主要依据 | 结论要求 |
|:---|:---|:---|:---|
| 表面需求 | 客户公开表达的业务诉求、项目目标、关键要求是否清楚 | 业务目标、场景、范围、指标、紧迫度 | 写清“已明确 / 部分明确 / 不明确”，不能把口头表达直接当真实需求 |
| 真实推力 | 客户为什么现在要推动，背后的业务压力、管理诉求、隐性顾虑是否成立 | why now、损失风险、推动者、隐性诉求、反复追问点 | 写清“推力成立 / 部分成立 / 待验证”，没有 why now 或损失压力不得写成已成立 |
| 推进条件 | 客户是否具备真实推进条件 | 组织共识、关键角色覆盖、预算、时间窗口、采购/审批路径 | 写清“条件具备 / 部分具备 / 条件不足”，预算来源、审批链路、拍板层长期不清时判断为条件不足 |
| 当前错位 | 我方当前表达是否命中客户真实需求 | 当前主打内容、客户真实关注点、current_alignment / current_misalignment | 写清“命中 / 部分命中 / 明显错位”，并说明继续这样推进会带来的偏差 |

### 三、列填写规则

#### 判断依据
- 只写核心依据，优先使用 CRM、销售记录、访谈/会议纪要、联系人分布、上游评分依据。
- 行业先验和 knowhow 仅可作为「AI 推断」来源，不得写成 CRM 已证实事实。
- 不把猜测写成事实。

#### 当前结论
- 直接回答该判断项，不复述依据。
- 用短句表达，可执行、可判断。

### 四、推断规则

- 允许基于结构化与非结构化数据交叉验证形成判断。
- 允许基于缺失证据逆向倒逼形成风险判断。
- 允许结合行业红线、客户反复追问点识别深层顾虑。
- 所有推断必须遵守「事实 / 判断 / 待确认问题」。

### 五、章节生成要求

- 本章节固定在「全局诊断结果」之后、「竞争态势分析」之前。
- 顶部 3 个摘要字段必须由下方 4 行判断表支撑，不能脱离依据单独下结论。
- 不只罗列表层需求；不把单一发言放大为稳定结论；不把“猜测”伪装成“事实”。
- 组织阻力、个人风险、预算分析统一回收到“真实推力 / 推进条件 / 当前错位”中表达。


### 六、需求地图分析固定要求

- 固定结构：一句话判断 / 需求成熟度 / 当前我方命中度 / 四行判断表（表面需求、真实推力、推进条件、当前错位）。
- 四行判断表中，每一行都必须写清：判断依据、当前结论、对推进的影响。
- 允许使用隐性诉求、组织阻力、决策安全感、伪成熟信号等判断，但必须继续遵守来源规则，不得把经验推断写成已证实事实。

## 决策链分析诊断标准（维度5 深化）

承接维度5「决策链完整度」评分，回答：是否已覆盖关键角色、已接触的人谁真正有影响力、链路是否存在缺口、推进风险高不高、下一步该补什么。数据来源见 `data-query.md` 3.2 关联联系人/决策链（商机联系人识别“有哪些人”、商机联系人关系识别“谁影响谁”）+ 销售记录/拜访纪要 + 客户组织信息。仅基于已知事实判断，不编造人物、立场、顾虑；信息不足统一写「未识别 / 未知 / 待确认」。

### 一、角色识别范围（四类角色）
| 角色 | 含义 |
|:---|:---|
| 决策层 | 最终拍板人、预算审批者、关键高层赞助者（≠ 当前对接人） |
| 技术把关 | IT 负责人、技术评审人、架构/安全/实施可行性把关人 |
| Coach候选 | 愿意提供内部信息、帮助引荐、关键节点支持我方的内部推动者（≠ 业务对接） |
| 业务对接 | 当前明确的业务接口人、需求承接人、日常沟通窗口 |

采购角色可归入业务对接，或在判断依据中单独说明其流程性作用。识别原则：角色识别优先看商机联系人；真假决策者验证优先看商机联系人关系；Coach 识别需同时满足「关系支持证据」与「内部推动能力」。

### 二、角色覆盖分析（输出字段）
针对四类角色输出：角色 / 姓名 / 当前立场 / 核心顾虑 / 突破策略。字段规则：

- 无人可识别 → 姓名写「未识别」；立场无法判断 → 写「未知」；顾虑无明确信息 → 写「—」。
- 突破策略必须写具体动作（如高层互访、技术方案汇报会、POC 验证、使用部门访谈、借助现有关系引荐、主动约访关键接口人、围绕核心顾虑定制沟通材料），**禁止**「继续跟进 / 加强沟通 / 保持联系 / 持续推动」等空泛表述，除非能说明“如何跟进、与谁沟通、要推动什么”。

### 三、真假决策者验证
不得因某人经常出面沟通就判其为决策层。若其是否具备「最终拍板权 / 预算审批权 / 关键影响力 / 跨部门协调权」不明确，则不得直接认定为决策者，应在风险提示/诊断说明中写「身份待验证 / 更可能是接口人或流程角色 / 是否能最终拍板尚不明确」。重点防止：接口人误判为决策者、采购负责人误判为业务拍板人、技术负责人误判为最终审批人、高频沟通对象误判为核心权力中心。

### 四、隐性权力中心识别
除显性联系人外，关注是否存在未识别高影响人物：老板身边人/助理/左右手、会议中发言不多但他人明显重视的人、对安全/合规/IT 红线有一票否决权的人、不在明面但影响最终选择的关键意见人物。有迹象未确认时，在风险提示中明确写「可能存在未识别的隐性权力中心 / 当前联系人未必代表完整决策面」。

### 五、覆盖度判断（内部依据，不单独成段）
- **完整**：已识别 3 类及以上角色，且包含决策层或技术把关。
- **部分覆盖**：已识别 1~2 类角色，但链路不完整。
- **严重缺失**：几乎无有效联系人，或关键角色普遍无法识别。

### 六、风险等级判断（内部依据，不单独成段）
- **高风险**：已进入方案/报价/POC/招采/立项前等关键阶段，但仍缺决策层、技术把关或 Coach，或存在明显未识别反对者/隐性影响者。
- **中风险**：已识别部分角色，但触达深度不足、立场不明、决策链不稳定，或关键人真实影响力待验证。
- **低风险**：关键角色较完整、存在明确推动路径、关键角色立场总体可控。

### 七、根因分析提示（体现在风险提示或行动建议中）
- **导演角色缺位**：销售停留在接口层，未主动推进更高层触达。
- **借力不足**：不会通过 Coach、关系引荐、活动场景突破关键人。
- **经营不深**：有联系人但关系浅，拿不到真实内部信息。
- **反对者失察**：未识别出竞品、技术阻力或隐性否决角色。

### 八、输出与生成要求（对应 output_template「决策链分析」部分）
- 必须包含：决策链全景（四类角色覆盖）、风险提示（一句话结论 + 一段诊断说明）。
- 覆盖度档位与风险等级作为内部分析依据支撑风险提示，不在最终输出中单独成段。
- 风险提示必须承担诊断功能：写清当前最核心的决策链缺口、缺失/待验证的关键角色、为何构成风险、继续按当前路径推进可能的后果。
- 语气专业、简洁、偏销售管理分析；重点是判断「决策链是否成立」，不是复述输入。
- 仅基于已知事实，信息不足统一写「未识别 / 未知 / 待确认」，不为填满模板强行下结论。

## 竞争态势分析诊断标准（维度7 深化）

承接维度7「竞争态势」评分，对竞争格局做阶段性业务判断。**不得由零散字段直接拼接结论**，遵循「事实 → 信号 → 态势 → 摘要输出」四层逻辑。数据来源见 `data-query.md` 3.5 关联竞争对手明细（`CompetitiveLinesObj`）+ 商机主数据 `competitor` + 销售记录 + Coach/客户反馈。

### 一、事实识别（第一层）

优先识别五类事实，并区分「系统事实 / 业务判断 / 合理推断」：

- **客户与项目事实**：客户类型、项目类型（新签/增购/续约/替换）、当前阶段、预算与项目真实度。
- **竞争事实**：是否有竞品记录、是否有其他厂商线索、是否有自建或历史供应商迹象、是否有客户倾向信息。
- **我方事实**：是否已有合作基础、客户是否已认知我方、我方当前优势/短板。
- **决策链事实**：是否查到关联联系人、是否识别关键人、是否覆盖业务/技术/采购/决策层等关键角色。
- **来源事实**：关键信息来自 CRM、销售记录、Coach、客户反馈还是业务推断。

规则：无竞品记录不等于无竞争；无联系人不等于无决策链；决策链信息属高权重事实必须纳入判断；关键事实缺失时保留为「待确认」，不得自动补全。

### 二、信号提炼（第二层）

基于事实提炼五类中间信号，各输出「高/中/低」或「强/中/弱」：

| 信号 | 含义 | 取值 |
|:---|:---|:---|
| 竞争透明度 | 是否清楚主要竞争方、客户倾向和风险来源 | 高 / 中 / 低 |
| 我方基础 | 是否具备存量合作、认知基础或历史服务基础 | 强 / 中 / 弱 |
| 决策链覆盖 | 是否已识别关键人并进入关键角色链路 | 强 / 中 / 弱 |
| 资源条件 | 预算、项目真实度、推进节点、可调动支持是否明确 | 强 / 中 / 弱 |
| 风险压制 | 是否存在竞品关系压制、客户倾向不利、自建/历史供应商惯性 | 高 / 中 / 低 |

### 三、态势判定（第三层）

竞争态势仅允许输出：`进攻` / `相持` / `防守` / `待确认`。

| 态势 | 判定条件 | 输出重点 |
|:---|:---|:---|
| **待确认** | 竞争透明度低，或竞品/客户倾向/决策链等关键信息明显不足，无法可靠判断 | 信息缺口、潜在风险、优先核实动作 |
| **进攻** | 我方基础强、资源条件强、决策链覆盖中等以上，且未发现强势竞品压制 | 可主动放大的优势 |
| **相持** | 已知存在竞争、双方各有优劣、客户尚未明显倾向任一方 | 当前胜负手与最关键突破点 |
| **防守** | 竞品或替代路径已形成明显压制、客户已有倾向，或我方在关键维度/决策链上被动 | 被动点、主要风险、补位动作 |

判定约束：无竞品记录不得直接判定「进攻」；有预算不等于天然占优；存量合作基础若未进入关键决策链，不足以单独支撑「进攻」；多数真实 B2B 项目中段更接近「相持」。

### 四、摘要输出（第四层，对应 output_template「竞争态势分析」摘要卡）

完成态势判定后输出摘要卡（结构与渲染见 output_template）。生成约束：

- 输出目标是「摘要卡片」，不是完整竞争分析报告，不展示完整五维评分表。
- 顶部三项（当前竞争态势 / 核心判断 / 下一步重点）优先给结论、判断、动作；核心判断必须写依据，不只重复态势结论；下一步重点只写最优先一项。
- 左栏「竞争情况」：当前状态只描述已知竞争事实，无竞品信息写「当前暂未发现明确竞品信息」而非「没有竞品」；风险提示聚焦隐性竞品/自建/历史供应商/竞品关系覆盖/客户倾向不明等 1~2 项；建议动作只写 1~2 条可执行动作，优先「找谁确认什么信息」，禁止「持续跟进」「加强沟通」等空泛动作。
- 右栏「我方优势」：存量基础/资源条件只写项目中真实存在的现实优势与有利条件，不写公司通用宣传语、不编造预算金额或客户态度；待转化点必须指出「现有优势为什么还没自动变成成交优势」，围绕决策链未突破、关键人未触达、优势未转化为客户偏好、商务条件未锁定等。
- 信息不足时明确写「待确认 / 暂无法判断」，不为填满模板强行下结论；无证据不得使用绝对化措辞（如「没有竞争对手」「客户一定会选择我方」）。
- 每项尽量 1 句话，核心判断最多 2 句话；优先「事实 + 判断 + 动作」表达。

## 核心打法策略换轨诊断标准（驱动输出「核心打法策略换轨」部分）

承接全局诊断与风险识别，回答一个问题：**当前打法是否还成立，若不成立应切到什么打法**。本节只做打法裁决，不展开行动计划（行动落到第五部分）。结论须落回前文事实/风险，并标注「事实 / 判断 / 待确认问题」。

### 一、换轨裁决三分类

| 裁决结论 | 适用含义 | 关键条件（命中多数即倾向该结论） |
|:---|:---|:---|
| **当前打法继续强化** | 主线判断正确，问题主要是执行深度/速度不足 | 客户关注点与当前打法一致；决策链方向正确；竞争可控；关键控制点大多已锁；风险来自动作深度而非方向 |
| **当前打法局部补强** | 主线大体成立，但有明显短板，不补会掉速 | 打法能对上主要关注点但覆盖不全；决策链只打到一部分；控制点存在 1~2 个关键缺口；竞争压力上升但未被动；风险集中在证据不足/关系不稳/口径未锁 |
| **当前打法必须换轨** | 现打法已无法支撑推进，继续沿用会放大风险 | 客户关注点已变、打法仍停在旧主线；关键决策人关心点与当前表达错位；竞品已占住当前赛道我方无优势；关键控制点长期未锁；P0 风险指向方向问题而非动作问题 |

> 证据不足时不下激进换轨结论，优先输出「局部补强」并标注待确认项。

### 二、五个判断输入（裁决依据）

1. **风险输入**：看 P0/P1 风险落在“执行问题”还是“主线问题”；多数 P0 指向方向错位 → 倾向换轨。
2. **客户关注点输入**：看客户真正关心业务结果/组织共识/风险兜底/价格/时间；长期未回应核心关注点 → 倾向换轨。
3. **决策链输入**：看打法服务接口人还是关键拍板人；只打执行层而拍板在高层 → 至少补强，严重时换轨。
4. **竞争态势输入**：看竞品是否已在当前赛道建立优势；继续跟随只能被动 → 换轨到差异化赛道。
5. **控制点输入**：看预算/验收/采购/责任人/时间表是否锁住；关键控制点长期未锁 → 至少补强。

### 三、快速裁决矩阵
| 判断项 | 信号表现 | 结论倾向 |
|:---|:---|:---|
| 客户关注点与当前打法一致 | 一致 | 继续强化 |
| 客户关注点部分一致但有关键遗漏 | 部分一致 | 局部补强 |
| 客户关注点明显变化或错位 | 不一致 | 必须换轨 |
| 决策链触达正确层级 | 已触达 | 继续强化 |
| 决策链只到接口层 | 未打透 | 局部补强 |
| 竞争在当前赛道我方被动 | 已被压制 | 必须换轨 |
| 控制点大多已锁住 | 可推进 | 继续强化 |
| 控制点存在关键缺口 | 不稳定 | 局部补强 |
| P0 风险指向主线错误 | 明显 | 必须换轨 |

### 四、主打法类型库（第一层：靠什么主线赢）
主打法只选 1 个，必要时带 1 个辅助打法。

| 主打法 | 适用核心矛盾 | 主打点 | 不适用条件 |
|:---|:---|:---|:---|
| **业务价值牵引型** | “为什么要做”——价值认知不集中，仍停在功能讨论 | 把“能做什么”切到“做成后带来什么业务结果” | 已进入强采购博弈，矛盾在条款/价格 |
| **高层共识突破型** | “谁来拍板”——接口层积极但关键决策人未触达 | 把“局部认可”推到“高层共识” | 高层已明确支持，卡点不在组织共识 |
| **风险兜底护航型** | “敢不敢上”——客户担心上线/连续性/安全/交付失控 | 降低客户做决定的风险感，而非堆功能 | 客户不担心交付风险，矛盾在价值/竞争替换 |
| **差异化对攻型** | “凭什么选你”——竞品深度介入，客户多方案比较 | 围绕客户最在意的 1~2 个点建立不可替代优势 | 尚未形成实质竞争格局 |
| **控制点锁定型** | “下一步能否锁住”——方向认可但控制点未锁 | 先锁验收/预算/采购/责任/时间，再谈推进 | 控制点已清晰，矛盾在需求/关系 |
| **防守保位型** | “已有位置会不会丢”——已有基础位置但节奏放缓 | 先稳住在局位置，再争取扩大优势 | 我方尚未建立基础位置 |

### 五、打法抓手标签（第二层：用什么方式打）

每单选 1~2 个，作为主打法支撑，不抢主线，不并列堆叠。

| 抓手 | 客户先问什么 | 表达重点 |
|:---|:---|:---|
| `专业型` | “你们懂不懂” | 专业深度、行业认知、架构合理性、顾问能力 |
| `价格型` | “贵不贵” | 总拥有成本、组合报价、付款设计、商务弹性 |
| `关系型` | “谁来推动” | 关键支持人、高层关系、组织协同、内部引荐 |
| `服务型` | “出问题怎么办” | 服务承诺、响应机制、驻场能力、持续陪跑 |
| `样板型` | “有没有别人做成” | 相似案例、量化结果、现场参观、客户证言 |
| `资源型` | “能调动什么资源” | 专家资源、总部资源、伙伴协同、专项投入 |

### 六、行业修正卡（第三层：在该行业偏向什么）
行业修正卡只用于调权与表达重点，不替代主打法。按 `SELLER_INDUSTRY` / `BUYER_INDUSTRY` 匹配：
- **金融**：偏“风险兜底护航型 + 高层共识突破型”，抓手偏“专业型 + 服务型”。
- **制造**：偏“业务价值牵引型 + 控制点锁定型”，抓手偏“专业型 + 样板型”。
- **政企**：偏“高层共识突破型 + 控制点锁定型”，抓手偏“关系型 + 资源型”。
- **ICT**：偏“差异化对攻型 + 风险兜底护航型”，抓手偏“专业型 + 资源型”；单纯靠已有关系/位置防守通常不够，竞争实质介入时优先切回差异化/风险兜底/高层共识，表达优先体现“风险可控 / 平滑切换 / 关键能力差异 / 资源投入 / 高层共识 / 验收与责任边界”。

### 七、输出与禁止写法
- 先给一句裁决：`继续强化 / 局部补强 / 必须换轨`；再给 1~2 句最核心原因；再给一句调整方向（只写新主线，不展开动作）。
- 若为“局部补强”，必须说明“主线不变，补强点是什么”。
- 禁止：把行动计划提前写进本部分；逐条重复所有风险；空泛表达（如“持续提升客户关系”“加强项目管理”）；无证据下激进换轨结论。

### 八、生成要求（对应 output_template「核心打法策略换轨」部分）
- “裁决结论”必须三选一（继续强化 / 局部补强 / 必须换轨），且与「当前打法 vs 换轨打法」「主打法与抓手标签」保持一致。
- “当前打法”必须来自前文全局诊断、关键卡点与风险暴露中的事实或判断，不得凭空编造。
- “换轨打法 / 主打法类型”必须回应 P0 / P1 风险和真实阶段卡点，不能写成泛泛的“加强沟通、持续跟进”。
- 主打法只选 1 个（必要时带 1 个辅助打法），抓手不超过 2 个，不并列堆叠。
- 行动细节落到第五部分行动建议，本部分不展开动作清单。
- 如证据不足，裁决倾向“局部补强”，明确写出“基于当前信息的保守换轨方向”，并列出需要补齐的证据。
