# 03 对外文件规范、脱敏与报价口径

> 适用于要发给外部供应商/客户的文件。**内部拆表（含议价点、核减、自做判定、人天）绝不可外发。**

## 3.1 脱敏自检（C04 / C05）

✅ 每个对外文件交付前跑（**文件或目录都行**）：
```
python scripts/scan_secrets.py <文件或目录> "你的平台名,供应商名,内部对象前缀"
```

**默认扫描词**（通用内部口径）：人天、核减、自做、议价、压价、砍价、报价单、替换、换平台等。
**你自己的平台名、供应商名、内部对象 API 前缀**，通过第二个参数追加，不要写死在默认表里。

**返回码**：`0` 零命中 / `1` 有命中 / `2` 路径或用法错 / `3` 有文件未取到文本。

⚠️ **两条必须记住**（否则扫了等于没扫）：
1. **Office 是压缩包**（B15），脚本会自动取真文本；**凡是报告"未取到文本"的文件，必须人工确认，不能当成已检查**。
2. 中文还可能被写成 XML 数字实体，解压直搜也搜不到——所以别自己手写 grep 代替这个脚本。

### ★ 误报必须人工看上下文（C05）

命中词**经常出现在"本件不含费用、人天与供应商信息"这类免责句里**。只数词频会误判为泄漏。

✅ 脚本会**打印命中行的上下文**，逐条人工判：
- 在免责/说明句里 → 误报，保留
- 在正文描述里 → 真泄漏，改掉

**实例**：一次扫描命中 5 处"人天/费用/供应商"，全部在免责句内，正文零泄漏。

## 3.2 对外文件的固定条款

1. **不构成采购承诺**："本函仅作需求沟通与费用了解之用，不构成任何采购承诺，亦不代表我司已作出系统更换决定。"
2. **保密**："涉及我司业务规则与内部管理信息，请贵司予以保密，不向第三方披露。"
3. **不接受打包总价**：要求按构成分块列明。

## 3.3 三档实现方式口径（★ 关键）

让对方按三档标注，才能与自研/现有系统投入做**同坐标系对比**：

| 类别 | 含义 | 可比性 |
|---|---|---|
| **A 类** | 标准产品已含，无需额外投入 | ✗ 无可比成本 |
| **B 类** | 需配置实现 | △ 部分可比 |
| **C 类** | 需定制开发 | ✓ **只有这档能直接比** |

⚠️ **口径陷阱**：一方报"在现有系统上二开"，另一方回"我们标准产品本来就有" —— **两个数字不在一个坐标系**，直接比会得出错误结论。

## 3.4 费用构成三段式

要求对方分三块报价，不接受打包总价：

| # | 构成 | 内容 |
|---|---|---|
| **一** | **基础标准化费用** | ①前期数据迁移费 ②标准系统费（许可/订阅/标准模块）——两部分分列 |
| **二** | **扩展功能费用** | B/C 类部分，**按功能点逐项列明** + 注明配置/定制 |
| **三** | **售后及维护费用** | 年度维护、版本升级、问题响应、技术支持，注明计费方式与周期 |

**双向验证原则**：若对方报得比现有方案更贵 → 结论是"现有方案不贵、别硬砍"，**不要拿报价硬套砍价结论**。

## 3.5 对外文件的信息披露取舍（★ 判断要点）

把内部能力写进给对方的函件，等于**亮家底**：

| 写法 | 好处 | 风险 |
|---|---|---|
| **详细写** | 对方必须逐项回应，无法含糊报价 | 暴露我方实现深度与业务规则 |
| **笼统写** | 可先摸底不露底 | 对方可能含糊报价、答非所问 |

✅ 交付时**主动向用户提示这个取舍**，由用户决定收还是放。

## 3.6 口径变更必须显式收回（C07 / F10）

**现象**：上一版说"这一项可以直接剔除"，后来发现只做了一层。

✅ 在文档里**明确写"上一版 X 说法已收回"**，并给出新结论。
❌ 不要静默改——用户会拿旧说法对新文档，判断依据失效。

## 3.7 术语统一（C03）

- 同一概念全文档**只用一个叫法**
- 用户指定改名后**全量替换**，并用 grep 扫旧词**零残留**
- 用户口语与系统术语不一致时（如口语「品相」= 系统「品项」）→ **按系统术语写，并在回复中说明**，不要摇摆

## 3.8 占位符约定

- `⟦字段名⟧` = 需用户填写的变量（公司名、日期、对接人等）
- `〖提示语〗` = 需用户确认/改写的提示

交付时提醒用户：**发出前确认全部 ⟦⟧ 已填**。
